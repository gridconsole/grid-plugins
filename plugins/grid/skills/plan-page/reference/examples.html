Grid · plan and task components · v0.3

Containers the planner picks from, so every plan reads the same way

A plan is an HTML page the agent writes. The skill that writes it must include the required parts below, in that order, and may use any of these components for the rest. Each example is filled with T-01's real data. Codes are stable: the skill refers to them by code.

0 · The contract

Required in every task page, in this order

R1
Headerid, project, title, one status sentence, phase track, token use against its limit. C-18.
R2
Answer firstone headline that states the conclusion, one paragraph, at most four stat tiles. C-17 optional.
R3
Where it standsprogress in one of C-02, C-03, C-04; never a raw count alone.
R4
Needs youopen decisions as C-09 or C-10; empty = leave it out, never "nothing yet".
R5
Stepsany of C-05, C-06, C-07, C-08; a table only above 40 steps, and then paged by chapter.
R6
RisksC-16, each with the step that retires it.
O1
Architecture, effort, research, filesoptional: C-15, C-08, C-13, C-14, C-12 as the content needs.
O2
Resultappears at Deliver: C-12 checks, C-14 files, one paragraph.
