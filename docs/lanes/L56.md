## Built

`internal/workflow/files.go` supplies the source-file half of the reader.
It uses `gridhome.Real` and `projects.Store.List`, selects a project by name
or ID, and rejects missing or ambiguous selections. The workspace file is
first, followed by project files in registry order. Missing files retain an
entry with null revision and empty text. Present empty files have the SHA-256
of zero bytes. Revisions are lowercase hexadecimal SHA-256 of the exact bytes;
line endings are not normalized.

The reader uses `localdata.Safe` to refuse symlinks below the resolved home.
`os.Root` confines opening to the home, and file identity and regular-file
checks precede reading. A symlink spelling of the home itself is accepted.
Read failures are recorded per file and do not discard other files. Invalid
UTF-8 is a read failure. It creates no directories, records or lock files.

The file collection function and its diagnostic type remain private until
the Rust parser's answer types can be verified. There is no `Parse` or public
`Read` yet. No front matter or YAML parser was added. The eventual parser must
use the existing frontmatter helpers and YAML dependency where applicable.

documents the target outer contract; detailed template/error field definitions
must accompany it after verifying the Rust types.

```markdown
### `grid workflow show [--project <name-or-id>] --json`

Returns `{files, templates, errors}`. Each file contains `scope` (`workspace`
or `project`), `project` (null for workspace), `rev` (lowercase SHA-256, or null
when absent), and `text`. The shared file is first. Without `--project`, all
registered project files follow; with it, only the selected project's file
follows. Missing files have empty text. A bad section is omitted from
`templates` and reported in `errors`; other sections still load. Plain output
lists each file's template names and error count. This command does not write.
```
