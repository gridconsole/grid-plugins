# L119 — Move signals between projects and the workspace inbox

## Problem and goal

The app's `inbox_move` operation has no plugin verb, so a note filed in the
wrong project cannot be relocated. This lane adds
`grid signal move <id> [--project <from>] --to <project|-> [--json]` and
`Store.Move(id, from, to)` without replacing an existing data source or changing
an app endpoint.

## Behavior and policy

- `--project` uses the existing resolver, including its folder default. `--to -`
  maps to Personal. Workflow key `inbox_workspace` defaults to `personal`, the
  only value accepted by this lane; no workflow configuration is read here.
- Both projects pass the existing `notes()` registration and PersonalOK checks
  under Add's `.signals.lock`. Unknown projects return exit 3, `no such project`.
  Guests, external callers and unknown roles receive the existing
  `guests cannot act on signals` refusal, even when invited to the source.
- The source must exist and be open (`new`, `placed`, `snoozed`). Same-project,
  decided-note, id-clash and 4000-entry target-cap refusals leave both trees
  unchanged. Add's cap and lock implementation are unchanged.
- A named destination changes `new` to `placed`; Personal changes `placed` to
  `new`. Snoozed status and `until` survive. Status is patched in the original
  front matter, preserving other bytes, extra fields, comments, timestamps,
  stored `became`, and the body. JSON returns optional `from`, destination
  `project`, and resulting status in both `status` and `became`.
- Both note paths pass `localdata.Safe`. Move atomically rewrites the source
  with mode 0600, then calls `os.Rename`. Atomicfile preserves existing modes,
  so imported notes are explicitly tightened to 0600. A failed write or rename
  restores the original content and permission bits; rollback errors are
  returned alongside the original error.
- Both folders are under one Grid home on one filesystem. There is no
  copy-and-delete fallback. This is runtime rollback, not a crash transaction:
  a crash between the source update and rename can leave the relocated status
  in the original folder.
- `TestSignalMoveSignedOutNoPersonAndDefaultProject` verifies the current local
  no-person policy against both move and act, and verifies the Personal source
  default. `signal move` is not added to the person-gate floor in this lane.

## Validation

The focused move suite passes **14 top-level tests / 60 tests and subtests**:
8 / 25 in signal, 6 / 35 in CLI. It covers content preservation, both relocation
rules, snooze metadata, exact JSON errors, tree hashes for refusals, the actual
4000-file cap (there was no existing cap seam), access, unsafe ids before storage
creation, symlinks, concurrent moves with exactly one winner, Add-lock sharing,
read-only-target rollback, and quoted/tagged/block YAML status spellings.

The rollback test ran and passed on this platform. It explicitly skips Windows,
where chmod does not prevent directory writes, and skips callers that bypass
permissions; neither skip was needed here.

Post-rebase `make test` passes: **56 tested packages**, **7 packages without
tests**, and no new matching temporary entries. The first run, concurrent with race and cross
builds, failed existing `TestFailuresAreSaved/timeout` and
`TestTransientEntryOfAnotherProcessIsIgnored` timing assumptions. An isolated
`make test` rerun passed without changing either package.

Post-rebase `make lint`, `make generate` with no regenerated contract diff,
`GOOS=windows go build ./...`, and `GOOS=darwin go build ./...` all pass.
The focused move suite also passes again after rebase.

**334 top-level tests / 2837 tests and subtests** across both packages.
