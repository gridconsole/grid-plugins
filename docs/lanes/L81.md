## Behavior and scope

An unreadable task `workflow.md` now gives projections an empty person withdrawal
policy. Each read operation emits exactly one warning:

```text
warning: cannot read task withdrawal policy (workflow.md); using withdraw: []
```

This applies to `question list`, `question sync`, `question tick`, `feed state`,
MCP `feed_state`, `job tree`, orchestrator tick (`feed tick`), and valid
non-withdrawal `job post` operations. Question defaults still apply and Jobs
still advance. Missing policy retains owner/member defaults without warning;
malformed policy retains those defaults. The contract now correctly says that
malformed policy warns for `question withdraw`, while raw `feed post` and MCP
withdrawals do not emit a fallback warning.

The strict policy reader and append checks remain in place. Person and leased
question withdrawals, Feed/Job/MCP withdrawal posts, and direct host withdrawal
posts still fail with operational code 1 before changing task files. MCP reports
`isError: true` with numeric code 1 while keeping the server alive. The read
fallback cannot bypass these checks.

No explicit file touch list was supplied beyond the contract and lane note.
The smallest supporting changes are in the shared Feed policy reader, Feed
state, question projections, and orchestrator loading/tick. A projection-only
callback on the Feed store lets a tick share one policy across its repeated
folds and saved state. The callback is local to that tick, so later ticks read
policy again and warn again as appropriate; writes still check the actual file.

The permission-denied regression exposed a second reader in the orchestrator's
progress hasher. Task-root `workflow.md` is now excluded from that scan,
including when it is a directory: policy configuration is not a work product.
This prevents an independent policy read error after the fallback, and means
policy edits alone no longer count as work progress. Other artifact read errors
retain their existing behavior.

The full suite also exposed an unrelated timing assumption in
`internal/land/process_unix_test.go`: the 100 ms deadline expired before the
child wrote its readiness marker, both in the full run and an isolated retry.
The smallest extra change gives that existing cancellation test a one-second
timeout, a two-second descendant write delay, and a 2.1-second observation
window. It still asserts that the child started and was killed before its
survival marker. No landing implementation behavior changed.

The existing module and Makefile were retained. No root DONE file was created.
Only intended source, test, contract and lane-note changes were staged; the
pre-existing untracked briefing and execution log remain outside the commits.

## Regression evidence

The read table covers nine command forms under permission denial, directory
reads, and a real Linux I/O error, for 27 cases. Each operation runs twice to
check one warning per invocation, path-free diagnostics, successful output,
question defaults, and Job assignment. The I/O fixture uses a process-memory
pseudo-file whose unmapped initial address returns EIO; it skips on systems
without that facility. Permission cases skip on Windows or as root. All three
failure modes were exercised here.

The withdrawal table covers six paths under all three failures, for 18 cases,
checking code 1 and unchanged file bytes and directory entries. The existing
agent-shell refusal and malformed-policy warning tests also pass. The Feed
projection test verifies that an existing person withdrawal is ignored when
policy becomes unreadable, leaving the question open and in needs-you.
