## What changed
- `internal/task/gates.go`: `Store.Approve` branches on `task.md` `gate`. At `gate: preview` it writes `approval-preview.json` (same event shape, token, CAS and lock order as `approval-ship.json`, `gate: preview`) and appends the prose line `- <time> · preview approved · <plan_hash> · by <who>[ · via <via>]` after the JSON event, in the same journal write. `approval.json` is never opened for write at that gate. `ApprovalForGate` accepts `preview`. The text at `internal/guard/plan.go:58` ("Grid writes the line") is now true.
- `internal/task/write.go`: `previewApprovalFile`; the journal allowlist and the reopen invalidation cover it; `commitWriteLines` lets a writer add prose lines to the same history image (`commitWrite` is unchanged for every other caller).
- `internal/guard/host.go`: `gateName` and `gateFile` match `approval-preview.json`, and the gate reason names it, so an agent cannot forge the receipt.
- `internal/plan/migrate.go`: a matching preview receipt needs `--yes` like the plan and ship receipts.
- `contract/README.md`, `docs/delivery.md`: the preview receipt next to the ship one.

How a task reaches gate preview: nothing in the plugin sets it. Only `deliver` writes a gate (`ship`, `internal/task/deliver.go:233`). `Approve` reads whatever `task.md` carries, so the writer that raises `gate: preview` (the preview step) still has to be built; it is out of this lane.
