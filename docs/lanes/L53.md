# L53: Stable Feed identity at task creation

Base: `3b40ebe`, branch `lane-L53`.

`task.Store.New` now calls `feed.NewID` while holding the existing
`.task-alloc.lock` and writes `ulid: <ULID>` into the staged `task.md` before
publishing the folder. `id: T-NN`, folder names, and task command output retain
the human identifier. Generation errors abort creation before publication.

The existing `feedHarness` uses a stable ULID in `id`; migration writes a
deterministic ULID in `id` and keeps the human number in `display`. Feed already
supports both that stable `id` form and `id: T-NN` plus `ulid: <ULID>` (covered by
`TestMachineAndTaskIDs`). Creation uses the latter to preserve the existing task
reader and reuses `feed.NewID` for generation; no new identity format or generator
was introduced. Stable identity remains available through `feed.TaskID` and
`task.FeedIdentity`.

Existing tasks without a stable ID are unchanged. `feed.TaskID` only reads; it
does **not** lazily assign an ID. Such tasks still fail Feed and Job commands
with `task.md needs a stable ULID in id or ulid`. This lane does not backfill them
or change migration behavior.

## Regression evidence

Before changing production code, both tests below failed against base `3b40ebe`:

```text
go test ./internal/cli -run '^TestTaskNewFeedCommands$' -count=1
    state: 1 grid feed: task.md needs a stable ULID in id or ulid

go test ./internal/task -run '^TestTwoProcessIDRace$' -count=1
    missing or duplicate stable id for T-01: "", task.md needs a stable ULID in id or ulid
```

The CLI test creates a task and machine identity from scratch, runs `feed state`,
posts a message, confirms it appears in state with the generated task identity,
grants the task lease required by `job next`, and runs `job next` successfully.
It also verifies that the task retains its human ID and stable ID. The existing
two-process allocation test now checks distinct stable IDs as well as consecutive
human IDs across 24 tasks created by competing processes.

The task-record golden includes a normalized ULID. A hook test that previously
injected a second stable ID now associates its result fixture with the generated
task identity, avoiding conflicting IDs.
