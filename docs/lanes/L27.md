# L27 brain decide, project-md and land

Reworked after review onto main. The first branch trusted an agent-writable
`approvals/land.json`, added a second atomic writer (`safefile.AtomicWrite`), a
second `project.md` lock (`.project-md.lock`) and a second history writer
(`internal/taskhistory` under `.history.lock`); all four are gone:

- `grid land` lands only on the plan approval that `grid approve` records in
  `approval.json`, read through `task.Store.Approval` (state, `approve` event,
  hash of plan.md re-checked under `.task.lock` and `.plan.lock`). The guard
  already keeps agents from both paths: `grid approve` is a person's verb
  (`internal/guard/host_brief_test.go:36`) and a shell or Write-tool write of
  `approval.json` is refused (`internal/guard/host_gates_test.go:88`,
  `internal/guard/task_gates_test.go:12`). A forged `approvals/land.json` with
  the current hash is refused (`TestApprovalBoundary/forged-land-json`).
- `land` and `brain decide` append history through `task.Store.Note`, the task
  writer's lock and journal. `brain decide` calls it after the brain level lock
  is released, keeping main's order (`.task.lock` before brain locks), and marks
  the receipt `noted` so a retry adds no second line.
- `project-md set` takes `localdata.Lock(home, ".projects.lock")`, the lock of
  `internal/projects`, and writes with `atomicfile.Write`, which keeps the file's
  mode (`TestSetKeepsModeAndTakesTheProjectsLock`).
- `internal/safefile` keeps only the moved symlink-free reader; the brain keeps
  its existing os.Root writer. `brain.DecideTask` takes a `TaskRef`, since
  `internal/task` imports `internal/brain` for delivery.

Built and committed:

- `grid brain decide <task> <proposal-id> accept|reject|merge-into [<note-id>] [--note <reason>] [--json]`. Accept and reject default the destination id to the proposal name; merge requires an existing destination. Fully qualified ids use `brain:home/<name>` or `brain:project/<name>`. Decisions retain the task proposal with terminal status, publish or merge a linked knowledge note, update the brain log and indexes, and record one history line. A durable receipt recovers interrupted publication, refuses conflicting decisions, and prevents duplicate notes, merged text, history lines, and index generations.
- `grid project-md get|set <project> <key> [value] [--json]`. Project names and ids resolve through `internal/project`; the same package validates identity fields. Values are YAML scalars, lists, or mappings; omit the set value for an empty string. Only a top-level front-matter key changes. Other keys, YAML comments, and Markdown body content remain; front-matter line endings normalize to LF, while body line endings remain unchanged. Missing get keys fail. Invalid YAML, non-string mapping keys, non-finite JSON values, and invalid identity field types fail before writing.
- `grid land <task> [--dry-run] [--json]`. Reads and validates exactly one `lands` mapping across the project's `knowledge/deploy/*.md` entries, excluding `TOPIC.md`. Dry-run reads only. Execution requires the plan approval for plan.md's current hash, uses the project's folder on the current machine, invokes only the configured command, bounds execution to ten minutes, and records start and outcome in `history.md`. Failure and timeout return a nonzero exit code. It performs no implicit git operations.

Shared code was reused: task resolution and reads use `internal/task` (and its `gridhome.TasksDirs` lookup); locks use `internal/fslock`, `localdata.Lock` and the task writer; the brain YAML loader and symlink-free reader moved into `internal/mdfile` and `internal/safefile`; project.md is written with `atomicfile.Write`; process execution reuses the existing eval runner, including bounded output and process-group termination. No protected package API changed. The shared CLI file changed only in its command table. No Feed records or replacement task record shapes were introduced; trust values use `contract.TrustTier`.

## Deploy and approval formats

A project deploy entry, for example `knowledge/deploy/lands.md`:

```yaml
---
lands:
  target: staging
  branch: main
  command: make deploy
  needs-approve: true
---
Deployment notes belong here.
```

All four fields are required. `target`, `branch`, and `command` must be nonempty strings on one line; `needs-approve` is a boolean. Unknown lands fields, malformed entries, or multiple lands mappings fail. The command is interpreted by `sh -c` on macOS/Linux. The command receives `GRID_LAND_TASK`, `GRID_LAND_TARGET`, `GRID_LAND_BRANCH`, and `GRID_PLAN_HASH`; it decides how to use the branch and target. The CLI does not interpolate them into command text or check out a branch.

The approval is main's plan gate: `grid approve` on a waiting task writes
`approval.json` with the plan.md hash (`internal/plan.Hash`), and `land` reads
it with `task.Store.Approval`. `land` never writes an approval.
`needs-approve: false` does not bypass it. Symlinks in deploy paths and a
symlinked `approval.json` are refused.

## Validation

Run from the repository root, leaving TMPDIR at its default:

```sh
make test
make lint
GOOS=windows go build ./...
GOOS=darwin go build ./...
```

Focused tests:

```sh
go test ./internal/braincmd ./internal/land ./internal/projectmd ./internal/cli
```

Tests cover table-driven accept/reject/merge, repeated decisions, interrupted-history recovery, unchanged index generations on retries, conflicting decisions, keeper gates, project key edits and preservation, JSON goldens, read-only land dry-run, opaque hashes, approval refusals, symlink refusal, command failure, timeout, environment values, and invalid deploy configurations. All required checks pass on the Linux runner; macOS and Windows were cross-compiled, not executed here.

## Limitations and unavailable work

- No Rust `writes_brain.rs` or `write/decide.rs` was present in the reference tree, so no Rust recording parity could be run. The available JS, curator instructions, and new design supplied the references.
- After delivery the task is at the ship gate, where `grid approve` writes `approval-ship.json`, which nothing reads yet and the guard's shell patterns do not name. `land` uses the plan approval, as the review asked; whether it should require the ship approval instead is open.
- `internal/project.Write` serializes only identity fields and discards unknown fields and the body. With its API frozen, project-md uses `project.Load` and `project.Parse`, then `atomicfile.Write` under `.projects.lock` to preserve the full document. Keys it sets are still dropped by the next `grid project relink`, which writes through `project.Write`. It does not introduce another front-matter parser or change the project API.
- Windows compiles, but mutating commands retain `internal/fslock`'s explicit unsupported-platform error. macOS/Linux locking and process-group behavior use the existing build-tagged implementations. Runtime macOS validation still needs a macOS runner.
- Automatic curator batching, proposal production changes, provenance promotion, Feed notifications, deployment rollback, and land-note generation remain with their owning commands. A killed land process may leave a start line without a result; land cannot guarantee exactly-once execution of an arbitrary external command, and execution retries are deliberate user actions.
