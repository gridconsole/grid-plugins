# L140R: L140 review must-fix, guest `job lint <file> --task` and the contract text

Base: `lane-L140` at `6e19038f`, rebased on the ref main (`dbdded39`). Branch: `lane-L140R`.

## What changed

1. `internal/job/jobcmd/command.go`, `lint`: for a guest the file gate `guestFile(path, e)` now runs
   before `os.ReadFile` whether or not `--task` is given (it was skipped when `--task` was set).
   With `--task`, the task is resolved right after, and anything but the file's own task folder
   answers `task not found` (exit 1, plain and `--json`, no host path). A `--task` that does not
   resolve keeps the resolver's own answer, as `job render` gives it. Owners and members run the
   same code as before: every changed line sits inside the `IsGuest()` branch.
2. Tests (no existing case edited):
   - `internal/job/jobcmd/context_test.go` `TestGuestFilePathMembership`: a second project `beta`
     the guest is not invited to, and eight `lint <file> --task <t>` forms, plain and `--json`, for
     uninvited, no-roles, unknown, invited, member and owner: own file in own task, outside file,
     outside missing file, file in the uninvited project (with the own task and with its own task),
     missing file in the uninvited project, outside file with the uninvited task, own file with the
     uninvited task. Guest refusals assert exit 1, the exact `task not found` text, empty stdout in
     plain mode, and no Grid home, temp folder or file content in the output. The invited guest
     reads its own file with its own task; owners and members keep every form with no task refusal
     and their old exit code.
   - `internal/cli/guest_parity_test.go`: the row `job lint {file} --task` (and its `-task-path`
     variant), whose file lies outside the Grid home, now expects `task not found` for every guest
     state (authorized by the review): `guestParityEarlyAnswer` knows the exact plain and JSON answer
     of `job lint`, and the invited subtest fails if the invited guest's output differs from the
     unknown one for that row.
3. `contract/README.md`: the `grid where --json` error paragraph gains the guest answer for a task
   path it cannot use (a path outside the Grid home or a link that leaves it included), and a new
   short section `grid job show <file>` and `grid job lint <file> [--task <task>]` states the by-path
   gate. The README had no job show/lint section, so the second sentence got a heading of its own.
