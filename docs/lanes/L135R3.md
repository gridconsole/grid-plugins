# L135R3 — a case group never closes early

## Base

`lane-L135RR` (8e12df4a), code head de378eef, rebased onto plugin main
`e7908960`; the rebase was clean.

## What changed

Only `internal/guard/host_targets.go` and a new test file,
`internal/guard/host_write_targets_case_monotonic_test.go`. No existing test is
edited.

1. No `esac` decrement (must-fix 1). `hostShellGroup` only counts: once a word
   `case` is seen inside a `( )` group (`$( )`, `<( )`, `>( )`, a nested `( )`), no
   `)` closes that group. The group takes the rest of the text, and
   `hostSegments` scans that text as commands. `esac` in an argument, a comment,
   a heredoc line, the case subject or after a `;&` terminator can no longer end
   the group before the pattern `)`. The comment on `hostShellGroup` now says so.
2. Line continuations (must-fix 2). `hostShellTokens` runs `hostJoinLines` on its
   input first, so every caller (`protectedWriteReason`, `writesProjectWorkflow`
   and the `${..}` recursion) sees text with each backslash-newline pair removed
   before any word is matched. It pairs a backslash with the byte after it, so
   `\\` followed by a newline keeps the newline: a plain `ReplaceAll` of
   backslash-newline would turn `echo x\\<NL>tee alias` into `echo x\tee alias`
   (one read-only command) and allow it. Run on the substitution bodies again,
   it changes nothing.
3. `case` counts whatever follows it unless it is a word character
   (`hostKeywordAt`, replacing `hostWordAt`): a blank, `;`, `(`, a quote or the
   end of the text. Counting too many cases is safe now that nothing lowers the
   count.

## Known cost (pinned)

Words after a substitution that holds `case` are scanned as commands, because the
group stays open to the end of the text. From a project folder
`echo $(case x in x) echo a;; esac) foo workflows.md` is refused (`foo` is not
read-only and `workflows.md` is the policy file); before this lane `foo
workflows.md` were `echo` arguments and ran. `foo notes.md` still runs.
