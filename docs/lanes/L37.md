# Lane L37

Implemented `grid job verify J-N [--task T-NN] [--dir path] [--json]` and `grid doctor --bundle [--out path]` on the existing CLI, Job, task, Grid home, version, lock and atomic-file packages. No module or dependency was added.

Verification loads `jobs/J-N/job.yaml` when present, otherwise the existing `job.LoadPlan`. `job.RunVerify(ctx, job, dir, job.VerifyOptions{GridHome: gridHome, TaskPath: taskPath, Cwd: cwd})` is the reusable entry point for the later L0 code check; `Verify` was already the name of the configuration type. The result includes pass, command exit code, nullable test count, the starting HEAD commit, a one-line failure reason, and bounded captured output. A minimum-count failure leaves the command's actual exit code intact while the CLI exits 1. Reviewer checks exit 3 and require a reviewer rather than claiming a pass.

The directory override wins over a recorded worktree, which wins over the current directory. Named worktrees resolve below the task project's Grid home worktrees directory; multiple recorded worktrees require `--dir`. Both the existing `path` field and a `paths` list work for file checks. Relative paths use the selected directory; `task:` pointers select proof files in the task folder. Files must be regular files. No Job, task, Feed or verdict is modified.

Commands run through `/bin/sh` on Unix and `cmd.exe` on Windows. Cancellation kills the Unix process group; Windows uses `taskkill /T /F`. Unix cleanup also kills descendants left holding output pipes after their shell exits. Counts recognize Go verbose or JSON events, Node TAP/spec summaries, Cargo summaries and pytest summaries, including multiple package/suite summaries. Go subtests and JSON output events are not double-counted. Plain Go package summaries cannot establish a test count. Unrecognized output or oversized lines produce unknown totals and fail a positive minimum. Captured output is limited to 64 KiB while counting continues. Counts reflect reported tests, including skipped/ignored tests, excluding pytest deselections, warnings and reruns.

Bundles run the existing doctor even for an unhealthy installation. A successful collection exits 0; doctor findings are stored in `doctor.txt` and also available with `--json`. The default destination is `$GRID_HOME/support/grid-support-<UTC timestamp>.zip`. The zip and its members have mode 0600. Existing output files and symlinks are refused. Publishing uses the existing fslock and atomicfile packages.

Each zip contains `doctor.txt`, `versions.txt` (grid, contract and app_min), the newest 20 non-crash regular files recursively under `$GRID_HOME/logs`, and the newest `crash-*.txt` there. Selection uses modification time with a filename tie-break. Logs retain at most the final 5 MiB each. Symlinks, hard links and special files are excluded. Truncation discards a partial first line, including an entire oversized single-line log, so a cut token cannot leak. PEM state is tracked through the discarded prefix. Bearer tokens, long sk- keys, JWS tokens with JSON headers, emails, PEM blocks and the user's home path are redacted from content and entry names before zip creation. Hostnames, dotted filenames, ordinary slugs and numeric version strings are retained. Windows home matching includes JSON escaping, case variants and shell-style drive paths. There is no upload or network client in bundle collection.

Run the required checks from the repository root, without changing TMPDIR:

```sh
make test
make lint
go test -race ./internal/job/... ./internal/doctor/... ./internal/cli
GOOS=windows go build ./...
GOOS=darwin go build ./...
```

Tests cover successful and failed verification, minimum counts, unknown totals, each supported runner format, file checks, reviewer handoff, saved metadata and plan fallback, directory overrides, named worktrees, HEAD reporting, cancellation of descendants, redaction, truncation across PEM/token boundaries, archive contents and permissions, existing-output refusal, and collection without network requests. The full suite also runs the repository's temporary-file leak check.

Intentional differences from the old plugin and reference prototypes:

- The old brief lint checked the presence of a `verify` field and headings (`old-plugin/hooks/lib.mjs:34`, `old-plugin/hooks/brief-lint.mjs:34`); its stop check inspected Outcome and Verdict text (`old-plugin/hooks/stop-check.mjs:84`). This command executes structured verification and enforces reported counts, as required by `docs/job-contract.md:41`, `docs/job-contract.md:68` and `docs/job-contract.md:124`.
- Non-code checks are explicit file checks or a reviewer handoff with exit 3, following `docs/job-contract.md:71`. Verification reports evidence without marking old brief status or writing a Verdict; integrating the reusable function into L0 and stop hooks is separate work (`docs/job-contract.md:124`, `docs/plugin-design.md:90`). The prototype's `grid job verify` action is implemented as a CLI, with no prototype UI changes (`prototype/task.html:5144`, `prototype/task.html:5200`).
- Support collection is a new verb with no old counterpart (`old-plugin-map.md:118`), implementing F-8 (`docs/plugin-design.md:119`). It is local only, matching `docs/go-architecture.md:386` and `prototype/settings.html:4853`.
- This lane's requested bundle scope is deliberately narrower than `docs/go-architecture.md:386` and `prototype/settings.html:4843`: diagnostics, CLI/contract/app_min versions, capped local logs and the newest crash. It does not collect task folders, Feed, `.live`, installed app/agent versions, or provide a file-list/send UI. It uses the requested support subdirectory and timestamped filename instead of the prototype's root-level filename (`prototype/settings.html:4858`).
- The lane's newest-20 and per-file 5 MiB limits replace the prototype's last-seven-days selection (`prototype/settings.html:4843`). Partial first lines, oversized single-line logs, symlinks, hard links and special files are omitted to keep collection bounded and prevent secret leakage. Redaction uses the specified patterns rather than adding an unrelated scanner or service (`docs/go-architecture.md:386`).

Limits and unavailable validation: Linux tests and both cross-builds were run here. Native macOS and Windows runtime tests were not available. Windows compiles, but bundle writing inherits the existing fslock package's unsupported-platform result; Windows locking is outside this lane and the fslock package was not changed. Plain `go test` without verbose/JSON output cannot prove `min_tests`, so use `go test -v` or `go test -json`. L0 and hook integration, UI rendering, upload, and broader support collection were not implemented because this lane explicitly requests the reusable function and narrower local bundle only.


## Rework

The rejected review's four must-fixes and six should-fixes are implemented with regression tests:

- Go package summaries require Go's tab-separated format and a duration, cached marker or recognized status. TAP `ok` lines and test diagnostics no longer invalidate totals. The recorded Node TAP fixture includes passing, failing and nested subtests, with counts taken from its `# tests` summary; it is also tested after Go output. A real Go test prints `ok ...` before its first PASS. Pytest summaries accept singular/plural warnings and reruns without counting them as tests, alongside skips, xfails and errors.
- `job.WorktreePath` is the shared resolver for named worktrees. It removes `@sha` and joins the flat `$GRID_HOME/projects/<project>/worktrees/<name>` directory for both scalar and repository-keyed records. `RunVerify` resolves worktrees, directory overrides and `task:` proofs; the CLI supplies context and formats results. Tests exercise the shared API and CLI, ambiguity, traversal refusal, cwd fallback and caller-data preservation.
- Bundle collection rejects files with multiple hard links when listing logs and checks the opened descriptor again before reading. A fixture links an outside credentials file into logs and proves it is excluded. The existing fslock now lives under `$GRID_HOME/support`, leaving only the archive in a custom output folder.
- Redaction covers Windows home paths in JSON, lowercase drive/path and `/c/Users/...` forms, and emails. Key matching requires a word boundary; JWS matching requires a JSON-header prefix. Table tests preserve hostnames, dotted filenames, slugs and neighbouring home prefixes while removing secrets.
- Windows verification sets `SysProcAttr.CmdLine` using cmd.exe's outer-quote rules. Portable command-line tests cover embedded quotes and an executable path containing spaces.
- `grid plan check` emits advisory warnings in text and the JSON `warnings` array for code Jobs using plain `go test` or `make test`. Tests cover flags, chained commands, assignments and non-code Jobs. Warnings do not change the exit code. This is a check for common commands, not a shell interpreter or Makefile inspection.

The rework retains the intended old-plugin differences listed above. Its additional decisions are:

- The flat worktree path follows the review and `docs/job-contract.md:53` (reference spec). The same reference's multi-repo paragraph at `docs/job-contract.md:70` describes an extra repository directory; this rework deliberately follows the review's explicit flat-path requirement so CLI and L34 can share one resolver.
- Reported test counts remain mandatory for positive minima (`docs/job-contract.md:68`, `docs/job-contract.md:136`). The new plan warning helps authors choose verbose/JSON output without claiming that plain package success proves a count.
- Hard-link exclusion and targeted redaction protect the local support collection while retaining useful diagnostics (`docs/go-architecture.md:386`). Files on platforms lacking a link-count implementation are conservatively omitted; this checkout's Windows fslock remains unsupported.

L34's orchestrator is absent from this checkout, so no caller there could be edited. It can adopt `job.WorktreePath` and pass task/Grid context to `job.RunVerify`; all resolution is implemented and tested here. Native macOS and Windows execution is unavailable in this Linux environment. Cross-build results and the tested implementation commit are recorded below.
