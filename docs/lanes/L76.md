# L76: Stable task ULIDs

Base: `1c70a9c4f57d21b7b129aa33246b10ba506a5f58` (plugin main).
Branch: `lane-L76`.

`grid task new` now publishes `task.md` with a generated `ulid` alongside its
existing `id: T-NN`. This is the format already accepted by `feed.TaskID`;
display IDs and CLI JSON output stay compatible. The identity is written into
the staging directory before the complete task is published.

Legacy tasks receive an identity through `feed.EnsureTaskID`, which reads again
under `.task.lock`, generates an ID only when missing, and atomically writes and
syncs the metadata before a Feed record can use it. Existing identities remain
unchanged. The insertion preserves other metadata, comments, body bytes, line
endings, and file permissions. Malformed or conflicting identities are refused.

Question writers, direct Feed posts, CLI/MCP posts and handovers, task lease
acquisition, Job/orchestrator writes, and usage notices use this initialization
path. Readers do not initialize identities or acquire the allocation lock.
CLI/MCP session resolution stays read-only; posting initializes the identity
after session validation. Task journal recovery retains an identity allocated
after the journal was left by a crash.

Migration already generated stable IDs in `id` with a separate `display` field.
It now also preserves an existing `ulid` from display-ID input and rejects
conflicting identities. MCP exposes Feed tools, and setup creates settings;
neither has a separate task creation path.

## Regression evidence

Before the implementation, the new tests failed against the base code:

- `TestTaskNewThenQuestionAdd`: creation had no stable identity, and question
  addition failed with `task.md needs a stable ULID in id or ulid`.
- `TestConcurrentFirstWritesKeepOneTaskULID`: the question writer failed with
  the missing-ULID error and the direct Feed writer failed task validation.

Both pass after the fix. The concurrent test releases a question writer and a
direct Feed writer together, checks that exactly one ULID field is persisted,
checks every post uses that identity, and checks a later write keeps it.
Additional tests cover existing IDs, CRLF, malformed headers, read-only CLI/MCP
operations, legacy CLI/MCP writes, migration, usage notices, and journal replay.

## Scope notes

No explicit touch list accompanied the lane brief. The shared Feed helper and
writer adapters are necessary to cover every existing entry point. The small
task recovery change prevents an older journal image from erasing a published
identity. Migration needs the preservation change for tasks that already have
the supported display-ID-plus-ULID format.

The task-record golden now normalizes the random ULID. Attachment tests use the
task's real identity, keep their open question deadline in the future, and
explicitly remove the ULID when testing legacy tasks. One hook test previously
injected another `id` into newly created metadata; it now replaces the generated
ULID with its contract fixture's ID. That fixture correction was required by the
full suite; hook production behavior did not change.
