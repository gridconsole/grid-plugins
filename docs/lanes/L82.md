## Migration changes

- Run the three recovery layouts concurrently. Each layout retains its own root, one clean expected view, and all ten crash points (including the existing inapplicable-step skip). Within a layout, keep the root fixed: record IDs derive from paths, so comparing different roots would invalidate the exact clean-run assertion.
- Run plugin crash and rollback cases concurrently with independent temporary directories. Pass plugin data explicitly through `WithPluginData` and the crash child environment instead of mutating the parent environment.
- Keep every crash, backup, pointer, refusal, dry-run, and byte-for-byte assertion. No corpus was shrunk; the 96 MiB streaming test and its 24 MiB allocation ceiling remain unchanged. Crash tests already reuse the test executable. Production migration code and durability operations are unchanged.

Validation of this step: `go test -race -count=1 ./internal/migrate/...` passed (21.707 s while env stress was running).

## Scope

The one change outside migration/env tests and this note is `internal/ports/process_unix.go` plus its tests. Extracting the existing stop loop behind private function parameters lets signal-order and grace assertions run deterministically, without relying on a child signal handler getting CPU within 100 ms. The production wrapper supplies the original identity lookup, signal syscall, and polling loop; behavior and timeouts are unchanged. No module or Makefile changes.

## Environment load failures and fixes

Ran twelve concurrent `go test -race -count=50 ./internal/env/...` copies and an uncached verbose probe. The probe reproduced `TestDevServerLifecycle/tree: down left process group`. A second run against an archived baseline used `-v -race -count=50 -failfast` in twelve copies; four copies failed within 76 s, reproducing a missing signal log, still-visible term/stubborn process groups, and a port already having a listener. The remaining baseline copies were interrupted after these failures. Archive runs disable VCS stamping because the archive has no repository metadata.

- `kill(pid, 0)` sees unreaped zombies, while `ports.StopRecord` explicitly permits them after SIGKILL. Each helper process now holds a FIFO writer until exit. Tests require EOF and the expected number of startup witnesses, including both tree processes. This still fails if a descendant survives shutdown, but does not wait for OS zombie reaping.
- The old exact signal-log assertion assumed a Go handler ran before the 100 ms grace expired. Under load, SIGKILL can arrive first. Exact INT → TERM → KILL order, group targeting, identity checks before escalation, and each grace interval now have deterministic tests in ports with a controlled wait function. Real env tests still exercise healthy, legacy, tree, TERM-only, stubborn, unhealthy, and redirect subprocesses and require their exit. No grace or health timeout was increased.
- The old port probe closed its listener before startup, allowing overlapping blocks and ephemeral client sockets to race the server. A listening sentinel outside each aligned ten-port block reserves that selection across test processes until cleanup. Blocks are below the usual ephemeral client range; occupied candidates are still probed and skipped. Tests remain concurrent.
- The GC test used a recorded PID as readiness even though recording precedes health checking. A pipe now acknowledges successful `Up` before the parent is killed; the 20 s watchdog stays unchanged. The child blocks for termination instead of sleeping, and lease expiry still uses the existing injected clock.
- Build the immutable dev-server helper once per test process with `sync.Once`, reuse it across lifecycle/GC tests and `-count` iterations, and remove its directory in `TestMain`.

Validation: race checks for migrate, env, and ports passed together (29.771 s, 16.959 s, and 10.039 s respectively under load). Migration statement coverage is 85.1% both before and after; all 913 coverage blocks match, with zero previously covered blocks lost. A mutation that puts the tree child in a separate process group fails the new lifecycle assertion with “server processes survived shutdown”, demonstrating that the EOF assertion still catches an orphaned descendant.

The full-suite check also exercises the dev-server helper through CLI tests, so the lifetime FIFO is optional for those callers; env tests always create it and assert all witnesses. `TestEnvironmentCLI` passes with this compatibility adjustment.

`make test` initially exposed that compatibility issue plus `TestPersonalChokePoint`, which reports `internal/job/jobcmd/trace.go` calling `gridhome.TasksDirs` outside its permitted caller-policy choke point. Running only that guard against the unchanged base SHA reproduces the same failure. The guard and trace implementation are unchanged because the failure predates this lane. The final `make test` rerun passes every other package and its temporary-file leak check; this guard is its only failure.
