## Baseline profile

Measured on a 12-vCPU Linux amd64 VM with Go 1.27.3. The uncached JSON run of both packages took 20.28 s wall time; migrate reported 15.393 s and env 12.435 s. The reported 680–760 s migrate runtime did not reproduce on this VM. No deliberate load ran during this measurement. Build caches were not cleared.

## Migration changes

- Run the three recovery layouts concurrently. Each layout retains its own root, one clean expected view, and all ten crash points (including the existing inapplicable-step skip). Within a layout, keep the root fixed: record IDs derive from paths, so comparing different roots would invalidate the exact clean-run assertion.
- Run plugin crash and rollback cases concurrently with independent temporary directories. Pass plugin data explicitly through `WithPluginData` and the crash child environment instead of mutating the parent environment.
- Keep every crash, backup, pointer, refusal, dry-run, and byte-for-byte assertion. No corpus was shrunk; the 96 MiB streaming test and its 24 MiB allocation ceiling remain unchanged. Crash tests already reuse the test executable. Production migration code and durability operations are unchanged.

Validation of this step: `go test -race -count=1 ./internal/migrate/...` passed (21.707 s while env stress was running).

## Scope

Changes are confined to migration tests, env tests and their helper, and this requested lane note. No module or Makefile changes. Further validation and env findings follow in the next commit.
