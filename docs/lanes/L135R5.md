# L135R5 — fail closed where bash and zsh read a line differently

## Base

`lane-L135R4` (5a9f8a47), rebased onto plugin main 8fe20b38 (R4 head 59671b35).
The lane merges cleanly onto the current main a82a26a3 (`git merge-tree`).

## What changed

`internal/guard/host_targets.go` and a new test file,
`internal/guard/host_write_targets_fail_closed_test.go`. No existing test or row is edited.

1. Carriage return. `\r` outside quotes is a word byte to both shells; the tokenizer
   now refuses the line (it is no longer a word end). Rows cr_*.
2. `$$` is one unit (the PID). A `'` (unquoted), `(` or `{` right after it is
   refused: zsh reads `$$'..'` as ANSI-C and `"$$("` as `$$(`, bash 3.2 reads
   `$` then `$(`. Rows dd_*.
3. `$'..'` and `$".."`: the token carries `ansi`; a redirect target or an operand of a
   non-read command holding one is refused (the guard does not decode them).
   `echo $'a\tb'`, `cut -d$'\t'` and `IFS=$'\n' read` stay allowed. Rows ansi_*, locale_quote.
4. Heredocs `<<W`, `<<-W`, `<<'W'`, `<<"W"`, `<<\W` at the top level and in `$( )` and
   `${ }` groups: the body is skipped up to the delimiter line (`<<-` strips tabs); an
   unquoted body still scans `$( )`, `${ }` and backticks; a missing delimiter, a
   delimiter with `$` or a backtick, or a backslash-newline after a `<<` is refused.
   `git commit -F - <<'EOF'` and `git commit -m "$(cat <<'EOF' ..)"` with apostrophes stay
   allowed. Rows doc_*.
5. Inside `".."`: a backtick group in the bash reading ends at the first unescaped
   backtick (only `\` and the backtick are special). For `${..}` in `".."`, zsh reads `'`
   as a plain byte, bash as a quote: `hostSegments` returns the bash reading and, when
   it differs, the zsh reading too (marked `restart`, which resets the cd base). Rows dq_*,
   zsh_reading_after_cd, TestHostZshReadingRestartsAtCwd.

## L135R6

Base `lane-L135R5` (3f140787), not rebased. Branch `lane-L135R6`.

### What changed

`internal/guard/host_targets.go`: at the top level the inside of `'..'` and `$'..'` is
literal. A `$(`, `${` or backtick there no longer opens a group, so its extent is not
consumed and the commands after the closing `'` are scanned. Groups already read `'..'`
and `$'..'` this way (`hostShellGroupAs`); the top-level tokenizer did not. Both single-quoted
forms are covered: `$'..'` showed the same bypass (rows ansi_sq_*).

New rows in `failClosedRows`, each run from the project folder and the repo folder:
sq_dollar_paren, sq_backtick, sq_brace, ansi_sq_dollar_paren, ansi_sq_backtick,
ansi_sq_brace (deny); sq_date `echo '$(date)'`, sq_brace_grep `grep '${x}' file` (allow).
Every deny row writes the policy file under bash 3.2 and zsh 5.9 on the laptop.
