## Changes

- Added U+FFFE and U+FFFF to the shared rename/decline refusal check in
  `internal/task`, identified from the L69F note. These are Unicode
  noncharacters, not Cc characters. Both fail with `ErrEditUsage` before
  resolution, locking, or writing, using the existing control-character text.
- Added both code points to the direct validation table and four CLI rows.
  CLI usage refusals assert the exact diagnostic, empty stdout, unchanged file
  bytes, and no new files, including the existing control-character rows.
- Added the `title: "a" b` frontmatter row for both readers. The legacy fallback
  must preserve `"a" b` in full; silently accepting only `a` loses input.
- Documented exit 2 for titles and decline reasons containing control
  characters, including tab/newline, as well as the two noncharacters and bidi
  override/isolate characters, before whitespace normalization.
