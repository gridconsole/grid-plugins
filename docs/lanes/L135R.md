## Decision on `writesProjectWorkflow`

The brief says never drop `writesProjectWorkflow` and keep all 54 L135 rows. The
rebase did not conflict, so L135's deletion of the function applied. Restoring
main's function verbatim turns two of the 54 rows red (`read_then_write`:
`cat alias; echo x > notes.md`, `cd_expansion_read`: `cd ${DEST}; cat alias`),
because it scans every word of any command that holds a `>` or a non-read
segment. The function is therefore restored by name and call, but narrowed:
it walks the same segments as the new scan, skips segments that only read, scans
the body of every substitution, and resolves every literal word of the rest as
before. Parity words the lexer might miss in future still reach it. If the
orchestrator prefers the verbatim function, that means editing two L135 rows;
to retire it instead, delete the function and its call in `EvaluateHost`.

## What changed (`internal/guard/host_targets.go`, `host.go`)

1. Lexer. `>|`, `>&`, `&>`, `&>>`, `<>`, `>>`, `<`, `<<`, `<<<`, `<&` are read as one
   operator each, an all-digit word glued before `<`/`>` is an fd prefix, and
   `>&N`/`>&-` are fd duplications, not targets. `<>` is a write.
2. Substitutions. The body of every `$(..)`, backtick, `<(..)` and `>(..)`, and
   any of those nested in `${..}`, is scanned as a command of its own, recursively,
   in assignments and read-only commands too, from the directory the surrounding
   command has reached. More than 16 levels fail closed.
3. `k=v` words are checked whole and by their value (`cp /dev/null P/a=b/../alias`).
4. Globs. `[!` is read as `[^` before Go matches. A redirect target holding a
   bracket expression Go cannot parse, or `[:` `[=` `[.`, is refused when it can
   sit under a Grid root. A plain operand with such a bracket reads it as `*`
   (so `sed -i 's/[[:space:]]*$//'` and `python3 -c 'a[:3]'` still run in a task
   folder, and `tee workflow[[:alpha:]].md` is still refused).
5. Expansion. `~+`, `$HOME`, `${HOME}`, `$GRID_HOME`, `$GRID_PROJECTS` and `$PWD`
   are filled from the guard's environment (PWD from the directory the scan has
   reached) before the check, also in `cd` targets. Any other variable stays as
   before: a redirect target with an expansion under a Grid root is refused.
6. `cd` skips its options (`-P -L -e -@ --`); `cd -`, a bare `cd` or more than one
   directory make the base uncertain.
7. False positives. A plain operand (not a redirect target) holding a `$` is judged
   as a pattern with `*` for each expansion: refused under a Grid root only when
   its name part can be a protected name (`dd of=workflow${E}s.md`,
   `tee $DIR/workflows.md`). `node "$CLAUDE_PLUGIN_ROOT/scripts/proof-add.mjs"`,
   `git commit -m "$MSG"`, `git commit -m "fix $(date)"` and `cp $SRC artifacts/x.png`
   run again from a task folder.
8. Grid roots are resolved on first use, so read-only commands (`echo hi`, `ls`)
   skip the file-system work that L135 did for every command.

## Not fixed (allowed on base and lane, outside the brief)

`bash -c`, `sh -c`, `eval` strings; brace expansion (`tee workflow{s,x}.md`);
flag-joined values (`sort -o<P>/workflow${E}s.md`); `cd P || exit`, `pushd`,
`builtin cd`, `{ cd P; }`; `env -C P dd of=alias`; `X=<P>/alias; echo x > $X`;
zsh `workflow(s|x).md`. A textual guard will keep leaking; the durable fix is a
file boundary the agent user cannot write across.

After an unknown `cd $VAR`, every later relative operand is refused (`cd $WORK &&
go build ./...`), inside and outside Grid roots; main allows it. This is L135's
uncertain-cd rule, kept as is.
