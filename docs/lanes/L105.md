## Implementation

`internal/persongate` owns the 19-verb floor, `Check`, process snapshots, private
account-directory validation, locks, and fsynced JSONL receipts. Environment
markers only refuse; `CLAUDECODE` alone is permitted. R1 examines the whole
ancestry before R2 chooses the first person entry point. Native Claude's
`claude/versions/<version>` executable suffix is also recognized: the installed
binary's basename is a version, not `claude`. This evidence-driven addition
prevents a real bypass of the design's original basename list.

Linux reads process stat/exe/cmdline, including the cmdline fallback. Darwin uses
absolute `ps` calls and joins their results so a vanished process is absent.
Windows uses Toolhelp, process creation times, and process command-line queries;
a reused/dead parent ends the chain. Other operating systems fail closed.
Unix files use no-follow opens and flock. Windows uses the existing stdlib-backed
LockFileEx/no-follow helpers, checks ownership and write ACLs, and creates a
protected account-only directory. Native Windows behavior remains unexecuted on
this Linux runner; cross-compilation passes.

The directory comes from `os/user.Current().HomeDir`, independently of CLI Home,
GRID_HOME, HOME, and XDG settings. Unix also verifies it with `LookupId`: the
pure-Go Linux implementation can otherwise fall back to environment values when
an account is missing. A receipt contains time, verb, task, argv SHA-256, via,
and chain basenames. Directory and receipt-file symlinks are refused.

CLI dispatch gates the floor before writes, with injected `Env.Procs` and
`Env.PersonDir` for tests. `personWrite` and `agentShell` remain extra refusals;
`personWrite` callers now return 3. Task event/history receipts carry `via`.
The question writer reads the same injected environment as the gate and honors
GRID_ACTOR after a successful check, retaining GRID_MEMBER as its fallback.
`question answer` was absent on the base and now delegates to the existing
answer implementation. No task-store enforcement or endpoint fields were removed.

The lease-and-fence question withdrawal path remains separate: a valid lease
works under a Codex tree, and a stale fence still fails with the existing
`question: stale lease` / exit 1 behavior without changing the task. `deliver`
still writes `gate: ship` under that tree. No skill or agent command invoking
`task status` was found, so no running-state exception was needed.

Read-only settings lists, help, and setup previews remain open. Operand-free
setup gates through a callback immediately before a confirmed write, including
removal; project setup is gated at dispatch. `person check --json` reports
allow/reason/via and includes the standard refusal fields when refused.

Task-local `workflow.md` accepts `person_verbs: [deliver, task attach]` or a map
such as `person_verbs: {deliver: [owner]}`. It can only add to the floor. L122
also reads leading YAML front matter in `projects/<name>/workflows.md`, falling
back to workspace `workflows.md` when the project does not set `person_verbs`.
Project policy wholly replaces workspace policy; either replaces the project
level default `[signal act turn, signal act dismiss, signal act snooze]`
(default, owner may change), and `[]` adds no person verbs. `signal act` covers
all acts and `signal dismiss` is `signal act dismiss`. Task-scoped calls use only
the task policy. Invalid values warn and retain the floor per L129; task I/O
and parse failures retain command/store diagnostics. Project read failures
also warn and retain the floor. Hook event execution bypasses policy; explicit
`hook level` settings writes retain their floor gate. A verified person policy
line `remove task close` can relax the floor's terminal/receipt checks, but
never agent checks. Extra launcher names are one basename per line in
`launchers`, with blank lines/comments ignored.

Small changes beyond the listed files were necessary:

- `internal/workflow/person.go` reads the new additive policy without replacing
  the existing workflow reader or its gate-post policy.
- `internal/task/write.go` adds the optional `via` receipt field; approval/refusal
  command schemas and goldens retain all old fields and accept the addition.
- Command inventory, parser annotations, help goldens, and old CLI fixtures now
  represent the new subcommand, refusal code, and explicit fake terminal tree.
- Settings write parsers accept `--json`; successful settings writes also return
  JSON when requested. Claude settings tests cover both person-folder deny rules.
- The startup hook's old `!grid approve` advice contradicted the new rule; its
  sentence, assertion, and corresponding golden outputs now name the Grid app
  or a separate terminal. Delivery documentation names exit 3.
