## Limitations

The MCP follow-up is outside this rework's scope. Native macOS and
Windows execution was not available here; cross-compilation checks the builds,
not runtime behavior. Windows dev-process supervision remains unsupported.
Legacy dev records without a start token use PID/group liveness. A surviving
group can be stopped after its leader exits. A live leader with a recorded token
that cannot be read is retained with a GC warning; a different token proves
that the reservation is stale and must not signal the new process.
macOS process tokens use the existing second-resolution `ps lstart` mechanism.
Shutdown grace periods still hold the allocator lock; health polling does not.
Merge commands now require contract-form holder IDs before writing.


## Rework after review

The review identified a shutdown regression and three follow-ups. All four are
addressed without changing the contract schemas or other protected packages.

1. `ProcessMatches` accepts a live group after its leader exits, including a
   leader that exits during the start-token lookup. The existing shutdown ladder
   rechecks before each signal and still refuses a mismatched live leader.
   `TestStopAfterGroupLeaderExits` starts `/bin/sh -c 'sleep 30 & sleep 0.3'`
   in its own group, reaps the leader and checks that both `StopRecord` and
   `Stop` stop the surviving child. Pipe EOF verifies termination even where
   unreaped orphan zombies remain visible to kill(0).
2. Records written before L42 without `pid_start` retain the original PID/group
   liveness behavior. `TestLegacyRecordStopsGroup` and the legacy variant of
   `TestDevServerLifecycle` cover shutdown and env down. GC warns and retains
   individual reservations when process verification, shutdown or lease reads
   fail, including damaged blocks; unrelated dead reservations are still removed.
   `TestGCLegacyRecordDoesNotBlockOtherReservations` and
   `TestGCSkipsUnverifiableRecords` cover those cases. This restores the dev
   process-group behavior at `docs/go-architecture.md:246`; skipping uncertain
   records is a conservative implementation of reclaiming only proven-dead or
   expired ownership at `docs/go-architecture.md:245`.
3. The merge CLI uses `contract.ValidWorker` to reject malformed holders with
   exit 2 and a clear message before creating lease files. New grants carry
   `gen` from the stored lease; renew and release retain it. Fresh leases still
   start at zero, the unbound generation (`docs/feed-contract.md:49`). Tests
   cover malformed inputs and both released and expired stored leases with
   generation 7. Every lifecycle write in that test passes
   `contract.Validate("lease", data)`, including the merge schema's holder
   pattern (`contract/schemas/merge-lease.json:19`).
4. Routine failure SourceID retains its original RFC3339Nano representation.
   It is a deduplication key and is excluded from timestamp normalization.
   `TestRoutineFailureMatchesPreL42Signal` loads a dismissed signal with the old
   ID, nanosecond source suffix and second-precision record timestamps. A retry
   matches it without adding another note or changing the original bytes.
   This preserves the existing failure-signal behavior (`docs/lanes/L36.md:23`)
   and introduces no difference from the old ID format.

Rework acceptance passed on Linux: `make test` with the default TMPDIR and no
new matching temporary entries, `make lint`, the exact race command above, and
both Windows and Darwin cross-builds. Native execution on those platforms was
not available.
