# C-win-child-env: on Windows, the agent probe and routine runs hand their child the Windows variables the other side already keeps, and no Unix PATH folders

Base: plugin main 55c46cbd (`git rev-parse HEAD` at the start). Branch lane-C-win-child-env. Two code commits plus this file. The Why lines read again on this base and still hold: `internal/routine/execute.go:170` (nine keys), `internal/agent/runner.go` before the edit (`systemPath` :39, `dirs := append([]string{filepath.Dir(binary)}, systemPath...)` :67, `runtime.GOOS` :53/:57/:69, `os.PathListSeparator` :68), `internal/agent/runner_test.go:89` (the expected PATH).

## Decision (the reviewer can overrule it)

On Windows the probe PATH is the binary's folder, then `<SYSTEMROOT>\System32` and `<SYSTEMROOT>` from the base environment (none when SYSTEMROOT is absent or empty). This lane does not claim this makes any particular shim start; it only stops handing Unix folders to a Windows child and keeps the system folder reachable. If the reviewer wants the probe PATH to carry the person's whole PATH, that is a different lane.

## What changed

- `internal/routine/execute.go:170`: the routine child's key list gains `APPDATA`, `LOCALAPPDATA`, `USERNAME`, `PATHEXT`, `ComSpec`, read through `get` (p.Getenv or os.Getenv) like the nine before; empty values stay out. The list is the same on every OS.
- `internal/agent/runner.go`: `childEnv` reads the base environment and calls the new pure `childEnvFor(goos, listSep, base, home, name, binary)` with `runtime.GOOS` and `string(os.PathListSeparator)`. On windows: PATH is the binary's folder, `<SYSTEMROOT>\System32`, `<SYSTEMROOT>` (SYSTEMROOT found case-insensitively in base, first non-empty), joined with `listSep`; `PATHEXT` and `COMSPEC` pass beside the existing Windows keys (case-insensitive, entry as given). Other goos: the same lines as before (binary folder by `path.Dir`, then `systemPath`).
- Tests: `internal/routine/execute_env_lane_test.go`, `internal/agent/childenv_lane_test.go`; `runner_test.go:89` calls `wantProbePath(exe)`.

Noted, not changed: Windows entries with an empty key (`=C:=C:\...`) are skipped as before (their key is empty and matches nothing). A SYSTEMROOT that ends in `\` gives `C:\Windows\System32` by trimming one trailing `\` for the System32 join only.
