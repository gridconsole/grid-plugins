## Behavior

Guests see only invited projects and cannot change project settings.
`workflow.Read` now requires the caller resolver. Discovery applies
`GuestProjectAllowed` before opening project records or workflow files. It
retains the original hardened discovery, workspace workflow, response fields,
revision hashes, parser and per-file errors; it does not replace discovery with
the registry loader, which would lose independent damaged-record reporting.
Unknown and uninvited guest selectors, including IDs, produce exit 1, empty
stdout and exactly `grid: project is missing or ambiguous` plus a newline.
No-project listings omit hidden projects, including malformed hidden records.

`Caller.IsGuest` maps through `contract.TierFor`. Person-team roles (owner,
member, lead) keep their access. Guest and external tiers require invitations.
Since the contract's Agent tier is also its unknown-role fallback, only the
existing explicit machine-role allowlist retains machine access: empty/local
CLI, cli, host, worker, agent, builder, checker, curator, designer, library,
operator, planner, researcher, reviewer, runner and scout. Every other string
is a guest. Tests cover every accepted role, case and whitespace normalization,
one optional `grid-` prefix, bare prefixes and repeated prefixes. Wire contract
tiers are unchanged. Project-md uses this same classification for write denial.

The seven requested writes refuse guests with exit 1, empty stdout and the
existing command error shape (`<command>: ...` or `grid: ...`), using
`guests cannot change project settings`. Checks happen before input consumption
where applicable and before any mutation or lock. Existing Personal lookup
refusals remain intact. Settings lists and invited project reads still work.
Owner and member success rows assert both exit 0 and a changed tree.

## Supporting scope

The brief has no explicit file touch list. The necessary supporting changes are
`internal/where/guest.go` for shared role classification,
`internal/projectmd/projectmd.go` to prevent external/unknown callers bypassing
its existing guest write check, and `internal/workflow/{files,read}.go` plus
existing reader tests for mandatory resolver propagation. This preserves the
existing caller propagation audit without adding an exception or an unstamped
production read API. The role matrix lives in `project_role_test.go` so it can
be copied directly onto main without depending on L98R-only test helpers.

`internal/cli/settings.go` is the existing common adapter for hook, agent,
skill and project setup. Its single check also covers skill enable. The project
mutation check also covers add, relink and scan --apply; the routine check
covers every non-list operation, preventing sibling verbs from changing the
same settings. Read-only scan/list behavior is retained. No data source was
replaced, no endpoint field was dropped, and go.mod and Makefile are unchanged.

The first full-suite run found `TestFolderAtPersonalPolicy/alpha/guest` still
expecting guest access without an invitation after the L98R merge. The minimal
additional test-only change in `internal/task/history_test.go` adds the alpha
invitation and stamps the guest member identity; its assertions and task
production code are unchanged.
