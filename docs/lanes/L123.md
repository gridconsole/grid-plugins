# L123: explicit project names precede IDs

Base: plugin main `8c1666aa461febbc2f59fd1c40d8ac2ed0bfc402`.

`findProject` keeps its signature and caller, searches all exact folder names
first, then accepts only a unique nonempty ID. Duplicate IDs without a name
match return no record. The caller distinguishes this failure from an unknown
selector and wraps the existing unregistered-project error with
`ambiguous project id`; the diagnostic includes only the requested value, never
competing project names or folders. Personal's early case-insensitive handling
and policy checks remain unchanged.

Regression coverage includes both record orders, a name matching duplicate IDs,
unique ID fallback, unknown and empty IDs, duplicate-ID refusals with and without
a task selector, and Personal selection/refusal when another record has that ID.
The contract now states that an exact folder name wins over an ID.
