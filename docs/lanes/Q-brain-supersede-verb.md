## What changed

- `internal/brain/supersede_verb.go` (new): `Store.Supersede(oldID, newID, reason, origin) (SupersedeResult, error)`. Under the level lock: scan, find both accepted notes, refuse as in row 4, then the new note's link (`recordVersion`, `atomicWrite`, `logAudit` status `linked`), then the old note through `markSuperseded`, then `RebuildIndex` after the lock. A completed pair returns `Wrote: false` before anything is written.
- `internal/brain/store.go`: `markSuperseded` takes a `why`; a non-empty one is appended to the audit reason (`superseded by <id>: <why>`). The accept path passes `""`, so O's lines and tests are unchanged.
- `internal/braincmd/supersede.go` (new), dispatch line and usage text in `command.go`.
- `contract/commands.json` regenerated by `make generate`.
- Shared tables that list every command, one row added each: `internal/cli/contract_inventory_test.go` (operand and required flags), `internal/cli/guest_parity_test.go` (arguments and the exit 3 text), `testdata/golden/brain-help.golden` (usage text).
- New tests: `internal/brain/supersede_verb_test.go`, `internal/braincmd/supersede_test.go`.

## Choices to look at

- Exit codes: 2 when the command line is malformed (operand count, `--by` or `--reason` absent, `--level` against an id's level); 1 when the store refuses (including a bad reason value, so an empty `--reason ""` is 1); 3 for the role.
- A reason must be 8 to 160 characters on one line and more than one word, and must also pass `Link.Validate` (so "see also", "related" and a link-name-only reason are refused). One-word is refused because row 4 lists it; the 8-character rule alone would pass "superseded".
- Beyond the brief: an old note already superseded by a different note is refused (clear message, exit 1) instead of silently doing nothing, because the helper would skip it while the link was still added.
- Order inside the lock is new note's link first, old note's mark second, so a stop between them leaves a link to a live note and a re-run finishes the mark. A stop after the old note is written but before its audit line leaves that line missing; a re-run reports "already superseded" and does not repair it (repairing would need a write on the repeat path).
- New audit status `linked` for the new note's change. The new note's `updated` is set to the time of the change; the old note's `updated` is not touched, as in O's helper.
- Ids: `brain:<level>/<name>`, or a bare name at the default level (the project when one resolves, otherwise home). Notes at two levels are refused.
