## Base and changes

Reset `lane-L104R` to `origin/lane-L104` at

`LoadPlan` now checks the exact text it reads with `task.ApprovedDigest`,
`plan.Hash`, and `plan.Digest` before decoding any Job fields. Its directory
parameter no longer shadows the task package. This closes the render and verify
fallback bypass when both intent pointers refer to `intent.md#request`.
The existing anchor approval check remains in place.

The file resolver compares its existing source stat with the stat of the root's
`plan.md` using `os.SameFile`. One identity result controls approval, specialized
plan anchor selection, and cache bypass. File cache lookup now follows identity
checking, so symlinks, hard links, and case variants cannot reuse unchecked plan
text. Brain source caching and repo/prototype source behavior remain intact.
Verify continues to prefer saved Job metadata when available.

No explicit touch list was supplied beyond the cited implementation locations.
Supporting test changes initially covered `internal/job` and `internal/job/jobcmd`:
the checklist parser test reapproves its edits, record tests use the existing
approved fixture, and the testdata record scan copies each discovered plan into
that fixture and approves it. This preserves their parser and schema assertions
without bypassing the new production gate or modifying checked-in testdata.
The first race and full-suite runs exposed two more fixtures without approval:
`internal/plan/legacy_test.go` and `internal/cli/feed_record_test.go`. The former
now approves converted plans through the shared fixture. The feed harness uses
a ULID task identity that the numbered-task approval API cannot read, so its
test loads the same plan bytes through the approved fixture while keeping the
original feed task, identity, and round-trip assertions intact. These small
supporting changes preserve the original conversion and feed coverage. The
module and Makefile were not changed.
