# L136R: keep owner and member task path forms

Base: `bcd162dc857f3b61aa55e07c5d46fc5b7c5a029f` (`lane-L136`, reviewed REWORK).
Branch: `lane-L136R`. Code and tests are in `30686837`; this report is the only change on top of it.

## What changed

1. `internal/job/jobcmd/command.go`, `resolveTask`: a local folder with `plan.md`, or a task
   inferred from the working directory, is returned as the path given for owners and members
   (`!Caller.IsGuest()`), exactly as on `lane-L134`. Only guests send it through the
   project-membership resolver, so every guest form still ends in `task not found`. A task
   folder outside the Grid home (a path or a cwd) works again for owners and members, and a
   symlinked path comes back as the symlink, not its target.
2. `internal/job/jobcmd/context_test.go`, `TestTaskPathMembership`:
   - the invited guest is compared with `gridhome.Real(taskPath)`; owner and member with the path
     given (the darwin `/private/var` against `/var` failure);
   - new rows for every state: a task folder outside the Grid home by absolute path, by relative
     path and by cwd. Owner and member get that path back; uninvited, no-roles, unknown and invited
     guests are refused with no path;
   - a symlinked task path: owner and member get the link, the invited guest gets `Real(target)`.

## One existing test changed

`TestTaskPathResolverRefusal` (added by L136) ran as the fixture owner and expected the `ResolveTask`
callback to be called four times. With owners and members keeping their local path, an owner never
reaches the callback, so that premise cannot hold. The only edit is the precondition: the test now
sets `env.Resolver.Caller = where.Caller{Role: "guest", Member: "gus"}` before the loop. The
selectors, the four-call count, the nested-cwd inference and the "refusal is final" assertions are
unchanged. The owner side of the same behaviour is now covered by the new `TestTaskPathMembership`
rows. No other test was edited; no test was removed.
