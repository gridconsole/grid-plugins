# L54: Read people and name approvers

Base: `60ce72d`. Work is on `lane-L54`.

## Built

`internal/people` owns the executable people schema and reads only through
`brain.Store.ConfigNames`, `ReadConfig`, and `brain.DecodeConfig`. `Store.List`
returns sorted entries, schema problems, and a separate filesystem error.
`Store.Get` returns one entry; a missing handle wraps `fs.ErrNotExist`.
Project files shadow home files by handle. An invalid project file also shadows
its home counterpart, so it cannot silently restore an old home approval grant.
Handles must match their filenames.

`people.Entries(entries).Approvers(area, owner)` selects unique sorted owner or
member handles with an exact `approves` or `decides` link target. It returns the
supplied owner when none match. Selection operates on already-read entries so
an IO failure cannot silently become an owner fallback. Guests, `owns`, `knows`,
and body prose do not grant approvals.

The CLI table registers only the existing `person` entry:

```sh
grid person list --json
grid person show reviewer --project example --json
grid person approvers --area release --task T-01 --project example --json
```

`--task` accepts a folder or an id through the existing task resolver. An id is
resolved within `--project` or the current task/project context. A task folder
also supplies its project when `--project` is omitted. Personal tasks read the
home people topic. Without either flag, people commands read home only.
An explicitly conflicting task and project is refused.

List JSON is `{"people":[...],"problems":[...]}`. Show JSON is the entry,
including its body. Approvers JSON is
`{"approvers":[...],"source":"people"}` or `"source":"default"`.
Invalid notes are reported on stderr for plain lists and approver queries;
JSON lists include them in `problems`. Empty arrays are encoded as `[]`.
Exit codes are 0 for success, 1 for read failures or unknown handles, and 2
for usage errors. A missing match requires `--task` and a nonempty `owner` in
task.md; neither the environment nor a hard-coded person supplies the default.
Old tasks without owner fields still work when a people entry matches; they
produce a usage error when fallback is necessary.

## Defaults and intended differences

The schema keys `handle`, `name`, `role`, and `links` are **default, owner may
change**. The current reader strictly accepts this executable schema and the
roles owner/member/guest. A changed schema needs a corresponding reader change;
unknown fields are reported, never guessed or migrated. Links retain the
`brain.Link` shape (`to`, `rel`, `summary`, `why`). Targets are exact area strings,
so the knowledge-note validator's brain/job/person address restriction is not
applied here. Non-approval relations remain context.

- The old questions skill used project roles, `owns`/`knows` links, or prose
  before falling back to the owner (`old-plugin/skills/questions/SKILL.md:14`).
  This lane provides deterministic approval selection with `approves`/`decides`
  and guest exclusion. It does not replace question routing. The new topic's
  intended readers are specified in `docs/brain-feed.md:252` and `:292`.
- Old brain writers emitted generic note fields and string links
  (`old-plugin/brain/brain.mjs:44`, `:54`). Such cached people notes remain
  untouched and appear as problems alongside valid entries, following the
  executable-config distinction in `docs/brain-feed.md:261`.
- Project people override personal people, with no repository or team-level
  lookup, as specified in `docs/brain-feed.md:285` and
  `docs/go-architecture.md:392`.
- There is no `person add` and no initialization, lock, index, log, or Feed
  write. The server owns roles and sync fills this read cache
  (`docs/brain-feed.md:301`, `docs/go-architecture.md:396`), superseding the
  generic config-writer example at `docs/brain-feed.md:300`.

## Verification

```sh
make test
make lint
go test -race ./internal/people/... ./internal/cli/...
GOOS=windows go build ./...
GOOS=darwin go build ./...
```

All five checks passed. `make test` used the default TMPDIR and reported no new
matching temporary entries. Race tests passed for both packages; Windows and
Darwin builds passed on the Linux host.

The regression tests were also copied into an isolated archive of `60ce72d`:
people tests fail because the package implementation is absent, and the CLI
golden test fails with `person: not built yet` (exit 2). The archive was removed.
Fixtures cover old people notes and task.md without owner fields. Tests snapshot
every path and file byte in the Grid home before and after successful and failing
commands, including project overrides. No test introduces a child process.

## Boundaries

This lane supplies the reader and selection API. Wiring approval gates, `grid
ask`, Feed/MCP writers, or the Orchestrator to enforce that policy belongs to
their lanes; those paths are explicitly outside L54's permitted changes. Server
sync and role updates are also outside scope. Cross-platform builds do not
substitute for running the tests on native macOS or Windows.
