# L14 - Job runtime (internal/job, grid job render, lint, show)

Rework after the review of the first L14 branch. Specs: job-contract.md, brain-feed.md, feed-contract.md.

## What changed in the rework

1. Trust tiers are set from the source (internal/job/source.go, jobcmd/command.go). The task owner's role in
   task.md (`owner: member|guest`) sets the tier of intent.md (member = person-team, guest = person-guest, anything
   else = external, fail closed). plan.md is agent text, other task files are external, a brain note carries the tier
   its origin recorded. Constants come from internal/contract.
2. Everything from a guest or external source, summary and relation lines included, renders inside the `<data>`
   fence (internal/job/render.go: `fenced`, `sourceBlock`, `brainBlock`). Guest and external text also turns
   skill shell execution off in the saved inputs.
3. Personal notes never enter a synced file. `brain:home/<name>` renders as a pointer only: no summary, text, digest,
   topic or links in brief.md or jobs/<J>/inputs.json (`pointer_only`). Lint warns (`job.personal-pointer`).
   Project files come only from the project's own folders on this computer, read from the project record in the
   Grid home; task.md can no longer name roots. A path is refused unless it resolves (symlinks followed) inside a
   project folder; the check walks the ancestors with os.SameFile, so case-insensitive file systems and symlinks
   cannot get around it.
4. Brain ids use the `brain:<home|project>/<name>` shape and are read through internal/brain (`Store.Show`, accepted
   notes only, superseded notes are not served). The index generation pinned in inputs.json comes from
   `Store.Index()`.
5. Front matter is read with go.yaml.in/yaml/v4 (internal/job/frontmatter); dates stay text, duplicate keys fail.

## Tests

internal/job/jobtest builds a Grid home (project record, task, one accepted note). New tests: render_test.go
(fence, tiers, personal note, outside files and symlinks, brain ids), jobcmd/command_test.go (owner role, personal
note in saved files, index generation).

## Differences and gaps

- `grid job` is in internal/job/jobcmd, not internal/jobcmd. The `job` row in cli.go now runs render, lint and show;
  next, post, ack, result, cancel, tree and blocked stay with the Feed lane.
- The new fence tests were not run against the old render code in a detached worktree; the old code printed the
  summary and the relation line of a guest note outside the fence, which the tests look for.
- Review items that were not must-fix were not reworked.
- `prototype` in task.md is still read, but resolved against the project folder and contained like any file.
