# L135 — shell write targets

## Changes

- Preserve glob and expansion markers while scanning shell words. Inspect output
  redirects and possible file operands of commands not known to be read-only;
  echo/printf data and input redirects are not write targets.
- Expand target globs with `filepath.Glob`, resolve matching symlink aliases, and
  use `filepath.Match` against protected basenames even when policy files or
  matching project directories do not exist yet. This covers project/workspace
  `workflows.md`, task `task.md` and `workflow.md`, and the existing fixed gate
  and settings names.
- Refuse expansion-bearing write targets under Grid roots, including relative
  targets from a Grid cwd, without executing substitutions. Check containment
  before path cleaning can erase an expansion followed by a parent component.
- Inspect the value of `key=value` operands, including `of=`, `--output=`, and
  `--file=`. Preserve quoted paths containing spaces.
- Track literal `cd` commands separated by `&&`, semicolons, or newlines. An
  expansion in a possible Grid directory makes later relative writes uncertain;
  further relative directory changes preserve that uncertainty. An absolute
  literal directory restores a known base. Explicit outside output targets stay
  allowed.
- Reuse existing gate, task-workflow, and settings refusal messages. Existing
  textual verb and protected-name rules remain in place. The scanner is a
  conservative static guard, not general shell execution or a sandbox.

Small additions beyond the named implementation file:
`internal/guard/host_targets.go` contains the dedicated word scanner and target
checks; `internal/guard/host_write_targets_test.go` holds the regression table.
Keeping these separate avoids enlarging the existing host rule definitions.
No module, Makefile, endpoint, or data-source change was needed.

## Regression evidence

The 54-row table includes each requested bypass and negative cases for ordinary
outside glob writes, echo data containing an environment variable, outside `dd`
output, and protected-name reads. Outside paths are derived from the test fixture
rather than embedding machine paths. Additional rows exercise missing policy
files, directory globs, aliases, nested and unfinished substitutions, quoted
paths, chained directory changes, and read-only segments beside unrelated writes.

Copied the final test file into an isolated archive of the rebased baseline and
ran:

```sh
go test -count=1 ./internal/guard -run '^TestHostWriteTargets$'
```

`cd` cases also failed closed accidentally because the old global word scan saw
an alias. The new tests retain those cases and add independently failing absolute
and changed-directory variants. Two baseline failures are false refusals of
