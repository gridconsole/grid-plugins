# L148: person gate on task-level usage budget set and clear

Base: `lane-L147F` at `5809a1bf` (plugin main `653340e1` included). Branch: `lane-L148`.

## Defect

`grid usage budget set|clear --task` went straight to `Configure`. Only `--workspace`
checked a role. A session held at its L147 budget could lift the hold with one Bash call.

## What changed

- `internal/persongate/gate.go`: `usage budget set` and `usage budget clear` join the
  person-gate floor, the same table that gates approve, decide and the task writes. The
  gate decides from process ancestry and the agent environment markers, never from
  GRID_ROLE alone. `usage budget show` is not on the floor, so reads stay open.
- `internal/cli/usage.go`: `parseBudgetWrite` parses the flags, then calls `gateCommand`
  (so `person_gate.go` owns the check, the refusal text, exit 3 and the `person_required`
  JSON) before any flag diagnostic and before `Configure`. The gate runs only when the
  flags parsed and `--workspace` is not set:
  - a call that fails to parse still exits 2 and writes nothing;
  - `--workspace` keeps its own role gate, untouched (and `--task --workspace`, where
    Go's flag package takes `--workspace` as the value of `--task`, is a task write and is
    gated);
  - an unexpected operand (`usage budget set T-01`) is refused before the "unexpected
    argument" error, as every floor verb is.
- `internal/cli/cli.go`: `Run` skips the early gate for these two verbs (as for
  `signal move`), because the handler gates them once it knows whether `--workspace` was
  meant.
- `contract/README.md`: the usage budget section says the task-level write is person-only.
- `docs/settings.md` has no floor list, so it is unchanged. The usage help text is
  unchanged, so `testdata/golden/usage-help.golden` is unchanged.

## Tests

New, `internal/cli/usage_budget_gate_test.go`, one block per verb (set, clear):
agent refused (exit 3, `person_required`, `agent_ancestor`, stderr text, files and budget
unchanged), person allowed (exit 0, budget changed, receipt for the verb in the person
log), read allowed (`usage budget show` from an agent context), agent environment refused
(GRID_AGENT, GRID_LEASE, GRID_ROLE worker and builder), and every task selector refused
(cwd, `--task` path, id, `--task=`, `--workspace` as a task value, stray operand). A
second test pins that a parse error still exits 2 and that `--workspace` set and clear are
not refused by this gate.

Registry rows for what the lane adds (no assertion changed):
`TestPersonFloorInventory` (two names appended), `TestPersonVerbTerminal` (two cases with
`--tokens`), and the guest-parity floor map (two names). `TestPersonVerbRefusals` and the
invalid-policy floor test iterate `Floor()` and cover the new verbs without a change.

### The one existing-test edit

`usageTask` (`internal/cli/usage_test.go`) set `GRID_ROLE=worker` for every usage test.
The person gate treats that role as an agent (`agent_env`), so every task-level
`usage budget set|clear` row in the fixture would exit 3. The role was not needed: with
the line removed on the base, `go test -count=1 -run 'Usage|Token|Budget|Threshold'
./internal/cli/` printed `ok`. The line is removed and nothing else in those tests changed;
the coordinator approved this edit.

## Noticed, not changed

- `persongate.Check` refuses role `worker` as `agent_env`, while the personal-access decision
  maps the worker's GRID_ROLE=worker to `cli`.
- `usage budget set --workspace` accepts an empty GRID_ROLE (`usage/workspace.go`), so an
  agent with no role set can write the workspace token budget. This lane leaves that path as is.
- A person's call that fails with an unexpected operand now writes a gate receipt before the
  usage error, because the gate runs ahead of that diagnostic like every other floor verb.
