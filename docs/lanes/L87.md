## Changes and direct-call audit

The CLI passes its existing `resolver(env)` into job trace and workflow write. Trace uses `Resolver.TasksDirs()` and the caller-aware `projects.Store.List()` for ID lookup. Write uses the supplied resolver for project selection before reading input or creating a lock. Neither the Personal policy nor the choke-point allowlist changed.

Audit command:

```sh
rg -n 'gridhome\.TasksDirs\(|where\.Resolver\{' --glob '*.go' --glob '!**/*_test.go'
```

The two reported bypasses were the only unapproved production matches. Remaining matches are existing, documented exceptions:

- `internal/where/personal.go`: caller-aware task-root enumeration.
- `internal/cli/cli.go`: shared CLI resolver stamps caller identity.
- `internal/guard/settings.go`: guard resolver stamps caller identity from its environment.
- `internal/task/create.go` (two calls): global ID allocation and staging cleanup require all roots.
- `internal/task/history.go`: `FolderAt` serves hooks in agent sessions.
