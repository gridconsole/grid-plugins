# J-worker-list-app-files: `grid worker list` reads the files the app's worker writes

Branch lane-J-worker-list-app-files, from main. Repo: plugin.

The bug (real run, 11 Nov): `grid worker list` failed on a Grid home where `grid-worker start` ran, with `grid: worker.lock: unexpected end of JSON input`. `Store.List` read `worker.json` and `worker.lock` as JSON; the app writes an EMPTY, OS-locked `worker.lock` and a `worker-status.json` with `{pid, version, started_at, uptime_seconds, address, token}` (app main, internal/kernel/worker/instance.go: `openWorkerLock`, `endpoint`, `atomicJSON`, `Close`).

## What changed

- `internal/worker/worker.go`: rewritten. `Store.List` reads `worker-status.json` (pid, version, started_at, address; the token is never decoded) and probes `worker.lock` with `fslock.TryLockExclusive` (open read-only without creating, release at once). Lock held: state `running`, presence `reported`. Lock free and a status file left: `stopped`, `stale`. Neither: empty list. `Status`, `Lock`, `Validate`, `Store.Now` and the presence value `unknown` are gone. An empty `worker-status.json` counts as absent; malformed JSON, a symlink, a directory or a file over 64 KiB is still an error.
- `internal/cli/worker.go:59-66`: text prints machine, pid, version, started_at, address, state, presence. JSON is `{machine, pid, version, started_at, address, state, presence}`.
- `contract/schemas/cmd-worker-list.json`: the new entry (`version` is a string, `address` is new, `updated_at` is gone, all seven required, no extras). Fixtures `contract/fixtures/cmd-worker-list/valid/populated.json`, `invalid/missing-field.json`, `invalid/wrong-type.json` follow it (the old shape fails the new schema). `contract/README.md:147` line reference.
- `internal/cli/open_start.go:48-51`: comment only. `open_start_test.go`: the fixture holds an empty `worker.lock` and writes `worker-status.json`; a shell script cannot hold the OS lock, so the test process plays the worker once the fake `grid-worker` has been run.
- New tests: `internal/worker/app_files_test.go`, `internal/cli/worker_app_files_test.go`.

## Decisions to look at

- A held lock with no status file yet (the app takes the lock before it writes the file) or an empty one lists as `running`/`reported` with pid 0, version "", address "" and started_at `0001-01-01T00:00:00Z`. The brief did not say; the lock is how the app decides, so `grid open` does not start a second worker in that window. `app_files_test.go:148` pins it.
- `machine` is `gridhome.Machine` of the home, and is "" when the home has no machine file; the entry is still listed.
- The probe cannot ask for a shared try-lock (`fslock` has none), so two probes at the same instant can see each other's lock as held. `grid open` decides under its own `open-start.lock`; a concurrent `grid worker list` could print `running` for that instant. No retry added. The app's `lockRetries` (3 times 100 ms, `instance.go:43-47`) already absorbs a probe that holds the lock while it starts.
