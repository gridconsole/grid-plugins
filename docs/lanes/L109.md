## Problem and result

Task-scoped budget commands could neither show nor save the workspace-wide
`tokens_per_task` default without resolving a task. Budget show, set and clear
now accept `--workspace`, bypass task resolution, and return only
`tokens_per_task` as an integer or null. Existing task budget responses and
precedence remain intact; `TestTokenBudgetCLI` still verifies a task override
and restoration of the workspace default after clearing it.

`Store.WorkspaceTokens` is the moved, exported reader with the original rules:
missing, linked, non-regular, unreadable, oversized, invalid UTF-8 or invalid
positive-digit settings mean no default. Its front-matter dialect is the existing
`taskfile.ParseFrontmatter`, not general YAML.

Writes hold the persistent exclusive `.workspace.lock` from before reading
through atomic replacement. The destination uses `atomicfile.WriteRoot` on an
`os.Root` for GRID_HOME. Existing lock and input files are opened without following
links and checked against the pinned root's entries. Writes reject unsafe files,
invalid UTF-8, oversized input/output and unterminated front matter. Replacement
preserves file permissions. Only token-key lines change; comments, other keys,
line endings and body bytes survive. Duplicate token-key lines collapse to one
on set and are all removed on clear. An absent key is added last; absent front
matter is prepended, and an absent file is created. Empty front matter remains
editable after clearing its sole key. No-op clears leave the workspace inode,
mtime and contents unchanged; the persistent coordination lock may be created.

Invalid workspace flag combinations, missing set tokens and nonpositive or
invalid integer amounts exit 2 before workspace access. Refused roles exit 3
before workspace access or lock creation. The shared CLI format-version guard
is unchanged.

## Policies

The replaceable policies receive `GRID_ROLE`, with defaults trimming whitespace:

| Policy | Workflow key | Allowed by default |
| --- | --- | --- |
| `usage.WorkspaceBudgetReadAllowed` | `token_limit_read_roles` | empty local role, owner, member |
| `usage.WorkspaceBudgetWriteAllowed` | `token_limit_write_roles` | empty local role, owner |

Guest and unknown roles fail closed. Configure replacements before concurrent
calls; the CLI does not read a workflow file to configure these defaults.
Tests exercise both default roles and replacement callbacks.

## A63 invocation contract

Exact commands and numeric JSON responses (examples use N = 100):

```text
grid usage budget show --workspace --json
{"tokens_per_task":100}

grid usage budget show --workspace --json
{"tokens_per_task":null}

grid usage budget set --workspace --tokens 100 --json
{"tokens_per_task":100}

grid usage budget clear --workspace --json
{"tokens_per_task":null}

grid usage budget clear --workspace --tokens --json
{"tokens_per_task":null}
```

The two show results correspond to a valid default and no default. Plain show
prints `tokens_per_task 100` or `tokens_per_task none`. Set requires an integer
N of at least 1, parsed by the existing `usageTokens`; values remain exact
through uint64, including `18446744073709551615`. Set reports its committed
value; another writer can subsequently replace it.

App-runner argv after the `grid` executable:

```json
["usage","budget","show","--workspace","--json"]
["usage","budget","set","--workspace","--tokens","100","--json"]
["usage","budget","clear","--workspace","--json"]
["usage","budget","clear","--workspace","--tokens","--json"]
```

For A63, map `tokens_per_task` directly to `{tokensPerTask: number|null}` for
`GET /api/token_limit` and `POST /api/settings/save_token_limit`. Use set for a
positive value and clear for null; do not resolve a task or read workspace.md in
the app. `--task`, `--dollars` and `--minutes` cannot accompany `--workspace`.
Set without `--tokens` exits 2. Clear removes the workspace default, leaving any
existing task overrides effective.
