# L134: guest parity across project-taking commands

Base plugin main: `2014b233cc839ed379bdde39fd2063751d0effd0`. Branch: `lane-L134`.

Added one table-driven `TestGuestProjectParity` in `internal/cli/guest_parity_test.go`.
It reads the embedded `contract/commands.json` produced by `make generate`, requires an
explicit argument recipe for every project/task/note route, rejects stale recipes,
and expands selectors and JSON modes from that inventory. Removing the `where`
recipe was verified to fail with `missing guest parity command: where`.

Each invocation goes through `cli.Run`, the real entry called by `cmd/grid/main.go`,
including parsing, dispatch and origin gates. Each row uses a temporary GRID_HOME
and runs four independently rebuilt states with identical arguments and paths:
(a) project alpha with a roles file listing someone else; (b) alpha with no roles
file; (c) no alpha project or task; (d) alpha inviting guest gus. The first three
compare exit status, stdout and stderr byte for byte. The invited case has its own
assertion even for skipped leak rows. No IDs, timestamps, paths or other output
are normalized during comparison.

Coverage: 117 command routes, 529 selector/action forms, 1058 plain/JSON invocations, and 4232 CLI calls. All routes support JSON, including the explicit hook supplement. There are 10 known leak skips (five forms in both modes); all invited sanity assertions pass.

Selectors include project names and IDs, task IDs and absolute task paths,
project-plus-task selections, positional shorthands and every current `--note`
option. The five `--note` flags on approve, decide, refusal decide, brain decide
and proof add carry text/reasons; their rows include the project-resolving task
operand or flag. No current `--note` option is a note locator; a newly introduced
one must be classified explicitly.

Coverage details and scope decisions:

- The generated inventory misses the operand-dependent `setup <project>` parser
  and `hook level --project` flags. The test supplements those two routes locally.
  The merge-lease inventory also needs explicit `lease take|release|status task`
  variants; those are covered with both task and project selectors.
- `signal act` covers turn, add, note, snooze, dismiss, wake and reopen. Its
  unconditional guest refusal, and the same refusal for signal dismiss/move,
  must match exactly across all four fixture states.
- Person-gated commands and guest-prohibited settings/workflow writes have
  explicit expected early refusals; arbitrary usage errors cannot qualify.
  `feed types` intentionally returns the public post-type catalog regardless
  of scope, so its invited assertion requires successful catalog output.
- `job render --task` is rejected by its shared parser; render's actual task
  operand is covered. `lease renew task` is not a supported operation.
- `eval run [task]` selects an evaluation-suite case, not a Grid project/task,
  and is excluded. Project registration/scan paths are not existing-project
  selectors. No existing data source, endpoint or production behavior changed.
- No touch list was supplied beyond the test/report scope. Changes are confined
  to the new CLI test and this lane note; go.mod and generated files are unchanged.

Known leaks (left unfixed):

The shared `jobcmd.resolveTask` first accepts a directory containing `plan.md`,
before invoking the resolver that checks guest project membership. Consequently
these path forms distinguish both hidden-project states from an unknown project:

| Command | Leaking forms |
| --- | --- |
| `job lint` | `--task <TASK>` |
| `job render` | positional `<TASK> I-01` |
| `job show` | `J-01 --task <TASK>` and positional `<TASK> J-01` |
| `job verify` | `J-01 --task <TASK>` |

Each affected parity subtest executes all cases, checks the exact known baseline,
then calls `t.Skip("L134 leak: <command>")`. A different output fails; if parity is
fixed later, the row passes without skipping. The invited sanity subtest is never
skipped. The ordinary task-ID rows for these commands pass.
