# Lane L4: guard hooks

Built with the existing Go 1.27 module and standard library only. The existing
`go.mod` and Makefile were retained.

## Delivered

- `internal/hookio`: typed PreToolUse, PermissionRequest, Stop and SubagentStop
  inputs; object-only JSON decoding; stdin reading capped at three seconds,
  including parsing bytes received before the cap; compact allow, deny and ask
  decisions; PermissionRequest directory grants; deny > ask > allow arbitration.
  Output has the legacy property order, no HTML escaping and no trailing newline.
- `internal/taskfile`: `ParseFrontmatter`, the scalar brief reader, and
  `HistoryLine`. The parser preserves the legacy string scalars, inline and block
  lists, nested objects, odd-key flag, comments and comma-splitting behavior.
  History lines are neither cleaned nor newline-terminated.
- `internal/guard`: plan, host, brief and home evaluators. They read files but
  never write files, change environment variables, execute commands or use the
  network. The filesystem base resolves relative cwd and environment paths; it
  is not a chroot. Evaluation is deterministic for an unchanged filesystem and
  supplied environment. Path checks follow existing and dangling symlinks.
- Recording adapters, each with exactly this callable signature:
  `func(stdin []byte, env map[string]string) (stdout []byte, exit int)`:
  `guard.PlanGuard`, `guard.HostGuard`, `guard.BriefLint`, `guard.HomeAllow`.
  They return exit zero, and silence means defer to normal permissions.
  Supply `HOME`, Grid folder variables, plugin variables and `PWD` in the map as
  needed. No ambient environment variables are read by the evaluators.
- `grid hook pretooluse` and `grid hook permissionrequest` compose the guards and
  the new only-writer rule. The CLI supplies the process environment explicitly.
  Stop/SubagentStop input types are available for the later stop-check work.
- Table-driven permitted/refused cases cover every legacy header rule. Additional
  cases cover CRLF and JavaScript replacement interpretations, MultiEdit,
  malformed workflows, pointer inheritance, dangling symlinks, shell recall
  checks, brief fields and headings, script identity, quoting and permission
  envelopes. HomeAllow's refused cases are silence, because it never denies.

## Intentional differences and their sources

1. Folder discovery uses the single home, `GRID_HOME` or `HOME/.grid`, instead of
   reading desktop workspace configuration. `GRID_PROJECTS` is still honored for
   explicit legacy fixtures. With neither folder variables nor HOME, guards are
   silent. The CLI supplies its resolved home even in standalone sessions.
   Sources: `docs/plugin-design.md:137`, `docs/plugin-design.md:151`,
   `docs/feed-contract.md:17`.
2. HostGuard still protects both derivations of the legacy `.host` folder. It
   also protects task `feed/` paths, including case aliases and symlink targets:
   answers and gate-controlling records share Feed files, so protecting selected
   lines would be insufficient. Its shell fence additionally recognizes literal
   `feed` path components and `grid approve` / `grid answer` calls. A plain
   `grid feed` invocation is allowed through to the CLI; shell operators remove
   that exemption. HostGuard cannot be
   disabled with `GRID_PLAN_GUARD=off`. These extra denials use a new explanation.
   Sources: `docs/plugin-design.md:92`, `docs/feed-contract.md:17`,
   `docs/feed-contract.md:21`, `docs/feed-contract.md:22`.
3. BriefLint preserves the five legacy frontmatter keys and nine headings, but
   its repair instruction names `grid job lint` and `grid job render`, replacing
   the removed brief-writing agent. It does not append the old dispatch pointer:
   evaluators are read-only, and Job dispatch belongs to the CLI's Job machinery.
   Sources: `docs/plugin-design.md:223`, `docs/plugin-design.md:466`.
4. The event dispatcher adds `EvaluateOnlyWriter`: file tools cannot directly
   change task folders, the brain or project records, regardless of role or the
   plan-guard switch. This is separate from PlanGuard so its legacy rules and
   diagnostics remain directly comparable. Both event entry points arbitrate
   denials before a home grant; PermissionRequest refusals use its decision
   envelope. The CLI event argument selects the envelope and its cwd fills a
   missing input cwd. Sources: `docs/plugin-design.md:49`,
   `docs/plugin-design.md:90`, `docs/plugin-design.md:135`.
5. A winning home fallback is counted outside the pure evaluators. The CLI
   appends one event/tool-only JSON line to
   `CLAUDE_PLUGIN_DATA/home-allow.jsonl`, or to
   `GRID_HOME/.hook-counts/home-allow.jsonl` when plugin data is absent. Counter
   failures do not change decisions. No command, path, prompt or identity is
   recorded. Source: `docs/plugin-design.md:90`.
6. The compatibility allowance for old skill scripts uses the launcher's trusted
   `CLAUDE_PLUGIN_ROOT` because a compiled Go package has no JavaScript module
   location. It still requires a real regular file directly under
   `skills/<skill>/scripts/`, and never executes it. With no installation root it
   makes no script grant. The new CLI does not broadly allow arbitrary `grid`
   commands; setup permissions are a separate concern. Sources:
   `docs/plugin-design.md:49`, `docs/plugin-design.md:102`.

The required pure-function boundary and explicit filesystem base are API changes,
not new permission rules. Legacy side effects are not reproduced inside them.

## Validation

Run from the checkout:

```sh
export GOCACHE="$PWD/.cache/go-build"
make test
make lint
go test ./...
go test -race ./internal/hookio ./internal/guard ./internal/hook
```

The local cache is ignored by Git and avoids a non-writable default build cache.
All of these checks pass. `make lint` runs go vet and the repository's gofmt check.

Optional byte-for-byte comparisons against a read-only legacy checkout:

```sh
GRID_LEGACY_PLUGIN=/path/to/old-plugin go test ./internal/guard
```

Node is needed only for that optional test. It runs the old hooks against
`t.TempDir()` fixtures and compares compatible cases' stdout and exit status.
Those comparisons passed against the supplied reference. The normal suite has
no Node or reference-checkout dependency. Tests do not execute allowed scripts.

## Boundaries and remaining work

- Full Job schema validation, Job posting/rendering, dispatch bookkeeping,
  stop-check execution and worker settings are not implemented here: the checkout
  only has their CLI placeholders, and this lane delivers the four guard hooks.
  BriefLint remains the compatibility file-completeness check; it does not claim
  to validate a new Job envelope.
- The legacy role checks remain in PlanGuard to meet this lane's parity contract.
  Moving policy into the agents topic needs that topic loader, which is absent
  from this checkout (`docs/plugin-design.md:365`).
- Bash checks are text fences, not shell interpretation or a sandbox. Computed
  paths and filesystem changes after evaluation require the worker's deny
  settings and isolation (`docs/plugin-design.md:90`,
  `docs/plugin-design.md:92`). File-tool only-writer enforcement is implemented;
  arbitrary shell write prevention is not claimed.
- The three-second reader can leave one blocked goroutine for a non-closable
  Reader that never returns. The one-event CLI exits after the decision; callers
  embedding it should close pipes they own. Guards retain legacy fail-open
  behavior for bad input and unreadable optional files.
- Checks ran on Linux. Case-alias and symlink fixtures exercise the legacy rules,
  but native macOS and Windows filesystem behavior was not tested here.
