## Problem and change

The old extension check accepted Windows batch names ending in dots or spaces,
and agent checks never inspected symlink targets before probing them.

`isBatchLauncher` remains filesystem-free and platform independent. It takes
the final component using either slash style, strips all trailing dots and
ASCII spaces, refuses an empty result, and compares extensions without case
sensitivity. This also handles Windows paths when tests run on another OS.

`isResolvedBatchLauncher` checks the supplied name first, then uses `Lstat` to
identify a final-component symlink and `EvalSymlinks` to inspect its target.
Batch targets and resolution errors, including dangling links and loops, are
refused. Ordinary non-symlink lookup/probe behavior is preserved.
`check` uses this helper at the existing refusal point, retaining the install
fix line, early return, and all report fields. PATH order, PATHEXT handling,
and the resolver functions are unchanged.

The replaceable package default is `BatchExtensions = []string{".bat", ".cmd"}`;
its workflow key is **`agent_batch_extensions`**. Configure the variable before
concurrent checks. The replacement test restores it with `t.Cleanup`, checks
that replacement removes the defaults, and verifies the new extension reaches
the same install-fix/no-probe path. Empty normalized names remain refused.

All changes are within the touch list: `internal/agent/resolve.go`,
`internal/agent/check.go`, `internal/agent/resolve_test.go`, and this report.
No missing infrastructure or out-of-scope changes were needed.
