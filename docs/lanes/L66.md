## Regressions demonstrated before the fix

The first test commit (`96cf27c`) ran against unchanged production code:

- Mode-000 workflow files exposed an OS open error instead of a short reason.
  The permission test ran as a non-root Unix user; it skips root and Windows.
- Symlinked workflow files leaked the temporary home path into the complete JSON
  response. Directory errors used the internal `projects/` path spelling.
- A symlinked `projects/b` pointing outside the home, or a mode-000 project

  and a healthy project selected by either name or ID. `projects.Store.List`

test. Replacing a regular workflow file with a FIFO blocked the old reader;
the test killed it at its two-second deadline. An already-present FIFO returned
the wrong diagnostic spelling. No blocked test goroutine is left behind.

## Changes

- Public file diagnostics use an `errors.Is` mapper for permission, disappearance,
  and known content/type/identity failures. Unknown failures become `cannot read`.
  Filesystem and project-parser error strings never reach the response.
- The established JSON contract is preserved: `errors[].file` carries
  `workflows.md` or `<project>/workflows.md`, and `errors[].message` carries only
  the short reason. This retains existing exact-message assertions for size and
  UTF-8 failures. `Problem.String()` renders the label and reason together.
- Unix opens use `os.Root.OpenFile` with `O_RDONLY|O_NONBLOCK`; Windows retains
  `Root.Open`. Component checks reject symlinks, and descriptor type, identity,
  and post-open leaf checks run before reading. Failed opens also classify a
  swapped socket or symlink without exposing an OS error.
- Workflow-specific discovery reads project records independently, retaining
  alphabetical ordering, name/ID selection, ambiguity checks, and omission of
  unregistered folders. A bad project produces one workflow-file problem while
  healthy workspace/project templates remain available. Selecting that bad
  project by name also returns its per-file problem with CLI exit 0. An
  inaccessible record cannot provide an ID, so it remains selectable by name.
- Discovery pins the projects directory and uses the same guarded file reader
  for project metadata. Failures of the overall projects directory remain
  command-level errors with sanitized messages.

Regression coverage includes complete-JSON home-path checks, wrapped error
classification, real CLI exit codes and selections, FIFO reads before/after
Lstat, sockets and a device, and post-Lstat replacements by a regular file,
symlink, directory or missing leaf. Each subprocess read has a two-second
deadline. Socket fixtures use relative paths for long macOS temporary roots.
