## Built and captured

- `fmt-origin` validates the decoded stamp. CLI proposal/import captures replace
  only the random id with a synthetic id. The test injects a forged trusted
  stamp through note front matter and body, then checks the writer's replacement
  and acceptance behavior. An old origin-less Markdown fixture is parsed and
  imported by main through the `upgrade` fixture set. The schema rejects absent
  stamps; external import supplies provenance before validation. The test also
  verifies that unstamped notes cannot enter accepted knowledge.
- `fmt-job-render` validates the existing `{brief, inputs}` representation of
  `brief.md` and `inputs.json`. The real `grid job render` dispatcher path writes
  full and budget-elided fixtures. Tests read the saved bytes, validate the raw
  input metadata, check `show`, and verify idempotent rendering. No additional
  persisted wrapper or writer was introduced.
- `fmt-sync-manifest` is spec-only. Its fixtures cover one person's two computers
  in cut 1 and a project with two repos and a guest in cut 2. The schema documents
  the seven fixed class policies outside manifest instances and validates project
  identity, normalized remotes, task binding, machine ownership declarations and
  role declarations. Repo-path selection
  and a policy override requesting secret storage are invalid examples, each
  changing one rule. Machine ids and task machine bindings require ULIDs.
- All schemas omit `x-class` and `x-roles`. Tests compare `PostTypes()` with the
  complete pre-change baseline and compare `grid feed types --json` byte for
  byte, including the trailing newline. The existing contract fixture runner
  automatically checks at least two valid and two invalid examples per schema.

## Defaults and observed differences

The 8 November follow-up decisions settle origin strictness, personal-note
scope, manifest policy placement and machine ULIDs. Other lane defaults remain
**default, owner may change**. The complete fields and
`diverges` rows, with doc:line and code path:line, are in `contract/formats.md`.

1. Saved renders follow main: `<task>/jobs/<job-id>/brief.md`, `inputs.json` and
   ancillary `job.yaml`. Both full text and source snapshots exist. Separate
   per-attempt bundles do not; an altered render for the same id is refused
   (`findings-concept.md:144`; `internal/job/jobcmd/save.go:26-54`). The JSON
   Schema validates a lossless two-file projection, not an invented saved file.
   Generation may be a content digest when there is no index
   (`job-contract.md:80`; `internal/job/jobcmd/command.go:119-122,451-467`).
   Personal source bodies/digests are intentionally absent from snapshots
   (`brain-feed.md:285-286`; `internal/job/source.go:161-164`).
2. Main's tiers win: `person-team`, `person-guest`, `agent`, `external`
   (`internal/contract/types.go:12-17`). These match `brain-feed.md:15` and
   `job-contract.md:87` exactly. Older `findings-brain.md:62` maps member to
   person-team, guest to person-guest, external to external, unknown imports to
   external; it has no separate agent word. Local CLI sessions use agent and
   random ids, not authenticated team/guest identity
   (`internal/brain/store.go:150-163`). Guest/external proposals are rejected,
   rather than listed as one labelled index line (`findings-brain.md:69`;
   `internal/brain/store.go:461-462`, `internal/brain/topics.go:227-229`).
3. Task files use last-writer-wins per file and retain the loser as
   `<file>.conflict-<machine>`. Folded Feed state is rebuilt from Feed records on
   the authoritative machine and never merged. Brain entries use versions with
   `superseded_by`, including private personal notes. These are unresolved sync
   policy defaults (`findings-runtime.md:193`; `findings-concept.md:185`;
   `brain-feed.md:18,262,274`). Clock tie-breaking and transport are not built.
4. The manifest's version is `manifest_v: 1` (`findings-runtime.md:193`).
5. Proposed manifest location is `$GRID_HOME/sync/manifest.json`. Field spellings,
   policy tokens, person/project identifier restrictions, dotted-host remote
   syntax and selection representation are defaults; no path or wire shape is supplied by
   the cited docs (`go-architecture.md:13,392`; `brain-feed.md:285-286`).
6. Personal notes sync only among their owner's computers; secrets never sync.
   This is the 8 November decision, following `go-architecture.md:13` and
   `brain-feed.md:286`. Raw Feed remains deferred, including in the cut-2 example
   (`feed-contract.md:13`).
7. Legacy absence is readable only at the parse/import boundary. The strict
   schema requires kind, id and tier and rejects null. The documented external
   import path normalizes provenance before validation; the accepted-note reader
   excludes old unstamped notes (`brain-feed.md:15`;
   `internal/brain/markdown.go:22-34`, `internal/brain/topics.go:223-229`).

## Validation and reproduction

Required checks passed on the supplied checkout:

```text
make test
make lint
GOOS=windows go build ./...
GOOS=darwin go build ./...
go test ./contract/... ./internal/contract/...
```

`make test` uses the caller's default TMPDIR and reports no new matching temp
entries. The capture suite uses the existing `jobtest` fixture and `cli.Run`
harness in process, with `t.TempDir` cleanup; it starts no persistent child
processes. The platform checks are cross-builds, not runtime tests on those OSes.

To deliberately recapture the synthetic writer fixtures after reviewing a format
change:

```text
go test ./contract/formats -update-format-fixtures
```

Normal tests never update fixtures. The invalid fixtures are single-rule
mutations; inspect them alongside any deliberate recapture. Changes in the
Feed baseline should be reviewed independently, never regenerated to hide an
accidental format registration.

## Not implemented

`grid sync` is still a nil command (`internal/cli/cli.go:122`), so no manifest
capture, transport, server authorization or real conflict resolution can run.
The default proposed filename is not a real installed artifact. Schema checks
do not prove origin authenticity, check account/machine/reference equality,
verify hashes, scan files for secrets or enforce server roles; the relevant
writers/server remain responsible. The capture tests establish only the current
CLI stamping behavior. Missing per-attempt render storage, authenticated origin
integration and the spec discrepancies remain documented rather than repaired,
within the original lane scope. Per-attempt prompt storage belongs to L45F.
