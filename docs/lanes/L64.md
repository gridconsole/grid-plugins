## Implementation and scope

`settings.ResolveHookLevel` is the common runtime reader. It carries the previous
home/project selection from `guard.configuredLevel` into the settings level
reader, including machine fallback and explicit task/project selection. Defaults
are overlaid by personal settings and then project settings. It reads no files
for AlwaysBlock names. Hook adapters report errors on stderr; an unreadable file
or resolution error returns the enforcing level, never an `off` or partial
personal override. A guard retains its original refusal and reports the error;
the existing permission fallback still denies on settings failure. Stop-check
still blocks unfinished work when settings fail. Context and log hooks continue
as on. SessionStart retains its unreadable-settings context note as well.

Settings are applied at the shared runtime functions, covering both registered
events and component commands. Event bundles keep independent controls: disabling
SessionStart context does not disable usage recording, disabling history does not
disable recall context, and disabling PreCompact guidance does not disable task
activity. The home permission counter and its record format are unchanged.

Production changes stay within the touch list. The existing
`internal/guard/settings_test.go` also calls the level adapter to prove that an
unreadable setting preserves the original denial, including its reason; this is
the smallest guard-test extension needed for that requirement. No CLI settings,
Claude settings integration, filesystem locks, contract files or module files
were changed.
