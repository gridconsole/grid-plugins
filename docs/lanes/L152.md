# L152: eval trace the agent cannot forge, and top-level-only trace checks

Base: main at 3cd7d904. Branch: lane-L152. Packages: `internal/eval` only.

## What changed
- `runner.go`, `trace.go`: the agent's stdout is kept in memory (`cappedBuffer`, same `Runner.TraceLimit` cap, same `truncated` meaning) and the trace checks parse those bytes. No `trace.jsonl` is written any more, so an agent that writes `$HOME/../trace.jsonl` changes nothing the checks read. A forged file with an empty stdout gives `error` "no trace".
- `ToolCall` gained `Parent`: the tool-use id of the subagent's parent call, empty for the run's own calls.
- `Check` gained `top_level` (bool, omitempty, default false = previous behaviour) on `tool_used` and `tool_order`. With it only calls with no parent count, and indexes are recounted over those calls. A non-bool fails the load in the strict decoder; `top_level` on any other check type fails the load naming the check id.

## top_level reference
| Field | Types | Meaning |
|---|---|---|
| `top_level` | `tool_used`, `tool_order` | `true`: ignore calls made inside subagents; `count_min`, `absent`, and the before/after indexes use only the run's own calls |

## Source of the parent key
`parent_tool_use_id` on the top-level message object: `null` for the run's own messages, the parent's tool-use id for subagent messages. Read from the string table of the installed Claude Code binary, the stream-json emitter (`{type:"assistant",message:...,parent_tool_use_id:null,...}` and the subagent form `parent_tool_use_id:<parentToolUseID>`). No transcript content was read.
