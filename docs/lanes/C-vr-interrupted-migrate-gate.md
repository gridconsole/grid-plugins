2. **Symlinks.** The brief says `filepath.Clean(home)`. `Scan` and `Rollback` write the journal at `gridhome.Real(home)` (plan.go:84, rollback.go:134). The two agree for a path with no symlink in it, which holds for the harness and the default `~/.grid`. A `GRID_HOME` that is a symlink, or sits under a symlinked folder (for example `/tmp` on macOS), would have its journal beside the resolved path, and `Pending` would not see it. I followed the brief; `gridhome.Real(home)` in `Pending` would close it at the cost of one `EvalSymlinks` per command.
3. **The journal also exists while a migrate is running** (phase `preparing`, home untouched), so another grid command or hook started during `grid migrate --apply` refuses or stays silent until it ends. That is what "the journal exists" means in the brief; the extra test `a_journal_beside_a_home_that_exists_refuses_as_well` pins it.
4. A journal that migrate cannot read (`cannot read the migration journal ... then remove the journal`, recover.go:149) still makes every command say to run `grid migrate --apply`, and that run then explains what to check. Not changed.
