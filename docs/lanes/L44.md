# Lane L44

Added `plan.Upgrade`, the `grid plan migrate` command, legacy-format CLI hints,
and in-memory conversion for revision comparisons. Items remains unchanged and
validates every successful conversion. The converter uses the existing YAML
library and shared front-matter reader, and preserves Job field text and order.
Migration writes exclusively through Store.Write. Approval files remain intact.

The work is not fully accepted. The supplied history reference is unavailable,
and the recovered fixtures conflict with the preservation requirements. Form C
also cannot pass the current store's installed-revision check. These issues
were raised for clarification; no answer was received during implementation.

All commands pass. `make test` used the default TMPDIR and reported no temporary

The focused tests cover A, pure B, revised B and C conversion goldens; current
no-ops and idempotence; migrated hashes; C Job equality after LoadPlan; unknown
fields, unmatched Jobs, mixed forms and line-numbered errors; dry-run output and
absence of writes; A/B installation and exact archives; approval refusal and
confirmation; missing citations; migration hints; and immutable archived B diffs
in both directions. The C installation test explicitly records the store's
revision refusal rather than presenting it as a successful migration.

A repeat full test run encountered an existing reserved-port collision in
`TestEnvironmentCLI`; a subsequent standalone `make test` passed without leaks.

## Rework

The 8 November owner decisions supersede the unresolved requirements above.
Form B accepts sentence verification alongside structured fields and prose-only
steps. Verification stays prose, with its original wording and casing; no
command is invented. Wrapped sentences remain prose, fenced Verify examples
remain unchanged, and a blank inside an indented step is refused at its line.
The real historical B input now drives the conversion golden and archive diff
tests. Form C continues to retain explicit item, title and intent fields.

The root DONE.md was removed; this section holds the L44R completion notes.
Focused conversion and archive-diff tests pass, including CRLF conversion.

Migration now uses Store.Migrate, which reads and upgrades again under the plan
lock, checks both approval.json and approval-ship.json there, and calls the
same installer as Store.Write. The explicit form C path archives an unnumbered
source as revision 1 and installs revision 2. Ordinary writes still require
the installed revision heading. Diff accepts a valid unnumbered form C archive
only as revision 1. CLI tests cover both approval files, lock ordering, the
form C archive, changed approval hashes and a second migration doing nothing.

The CLI now offers the migration preview hint only when Upgrade succeeds.
Regression tests cover unconvertible A/B/C plans through items, check and write.

The hand-edited form-b-fields fixtures were removed. Conversion, hash, CLI and
diff tests now use form-b.md; the archived B diff uses its exact original bytes
and revision number. Its new expected hash was computed with the read-only old
plugin's plan-hash.mjs. C's expected fixture already retained the owner-selected
fields; its golden and full Job equality test remain green.

The intended differences from the old plugin are now:

- Legacy steps gain checklist Jobs structure; sentence verification remains
  prose and does not become executable verification. A prose-only step has no
  Job for LoadPlan to select. B still accepts prose alongside structured fields.
  See docs/plan.md:199 and reference old-plugin/skills/plan/SKILL.md:89.
- Host, needs and evidence remain prose; host does not select a worker. C keeps
  explicit item, title and intent fields and uses non-code for writer Jobs.
  See docs/plan.md:199, docs/job-contract.md:11 and reference
  old-plugin/skills/plan/SKILL.md:90-91.
- Closing verification becomes a Verify section with unchanged wording and
  casing. Fenced examples are untouched. A blank inside a step is refused with
  its line number, consistent with the old format's no-blank rule.
  See docs/plan.md:203 and reference old-plugin/skills/plan/SKILL.md:89-93.
- Migration is explicit, checks both approval files under the plan lock and
  leaves them unchanged. Unnumbered form C alone gets the revision 1 archive /
  revision 2 installation policy. The new hash invalidates old approvals.
  See docs/plan.md:184, docs/plan.md:190 and reference
  old-plugin/skills/plan/SKILL.md:81.
- Diff upgrades archives only in memory; invalid conversions do not receive a
  migration hint. See docs/plan.md:211. The migration write and approval rule
  lives in Store.Migrate; call-site searches found no migration writers in Feed,
  MCP, Orchestrator or hooks. Ordinary Store.Write keeps its existing policy.
