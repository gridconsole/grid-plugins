# Lane L18: Feed MCP and the Codex path

Built `internal/mcp`: a stdio, newline-delimited JSON-RPC 2.0 server supporting
`initialize`, `notifications/initialized`, `tools/list`, `tools/call`, and
`ping`. It negotiates the three versions supported by the old plugin
(`2025-06-18`, `2025-03-26`, `2024-11-05`). Unsupported versions receive the
newest supported version. Only JSON-RPC goes to stdout.

The five tools are `feed_post`, `feed_read`, `feed_state`, `feed_types`, and
`feed_handover`. Each advertises and validates a JSON input schema and calls
`internal/feed` directly. The CLI and MCP share task resolution, format checks,
writer identity, and session defaults. Tool arguments cannot supply writer or
lease authority. Guest/external bodies are emitted once inside Feed's fixed
warning/data fence; metadata and repeated state bodies refer to that block by
record ID. Stored records and state retain their original format.

Registered `grid mcp` in the existing command table. The existing `.mcp.json`
already starts `${CLAUDE_PLUGIN_ROOT}/bin/grid` with `args: ["mcp"]` as
`grid-feed`; it was retained and tested rather than duplicated. Initialization,
tool discovery, and `feed_types` work without a configured Grid home.

Codex uses `grid feed post|read|state` in its shell, with no Feed MCP
configuration. Added `GRID_FEED_TASK`, write defaults for `GRID_JOB` and
`GRID_ATTEMPT`, and validation of the optional `GRID_WORKER` assertion against
the CLI's member/machine identity. Existing role, lease, generation/fence and
wake defaults remain shared. Read Job filters remain explicit. Usage and shell
fallback instructions are in [docs/feed-mcp.md](../feed-mcp.md).

Two regressions discovered during verification were fixed separately:

- Git discovery now verifies `.git` markers with Git. An empty marker above
  temporary fixtures no longer makes every fixture a repository. This lets
  `make test` pass using the default temporary directory.
- Expanded large Feed bodies are decoded into a fresh map, so the storage
  reference does not leak into the body or break an identical retry. This
  changes no on-disk record fields.

`internal/where`, `internal/project`, `go.mod`, and the Makefile are unchanged.
The only edit to `internal/cli/cli.go` is command-table registration.

## Tests and execution

```sh
make build
./dist/grid mcp
make test
make lint
make golden
go test -race ./internal/mcp ./internal/feed ./internal/cli
```

Use the default `TMPDIR`; no sandbox-specific temporary-directory override is
needed. The MCP session golden is `testdata/golden/mcp-session.golden`.
Regenerate it with
`UPDATE_GOLDEN=1 go test ./internal/mcp -run TestSessionGolden`.

Table-driven tests use pipes in both directions and temporary Feed stores.
Coverage includes every method and tool, all negotiated versions, initialization
ordering, notifications with no side effects, request IDs, malformed JSON and
envelopes, recovery on the next line, tool errors, argument types, identity
forgery, read filters, stale leases, large-body retries, data fences, and repeated
state projections. Transport tests cover I/O failures and the message bound.
CLI tests verify manifest registration, no-environment discovery, cross-front-end
reads/writes, environment defaults, and operation with no executable on PATH.

Verified `make test`, `make lint`, race tests, and builds for Linux amd64/arm64,
Darwin amd64/arm64, and Windows amd64. A real `bin/grid mcp` smoke session passed
initialize, tools/list, feed_types and ping, with protocol-only stdout and empty
stderr. Windows compilation does not enable Feed locking on Windows; that
platform remains unsupported by the inherited Feed implementation.

## Not exercised or outside this lane

- A closed grid-worker strict-MCP launch could not be run because that worker is
  not in this checkout. The real plugin launcher and tool discovery are tested;
  the app must still pass the declared server through its strict configuration
  (`docs/brain-feed.md:206`, `docs/brain-feed.md:375`).
- The macOS tests now run natively: `go test` of the MCP, CLI, Feed, gitx and
  packaging packages passes on a macOS host (with `-race` for MCP, Feed and
  gitx), in addition to Linux. Windows builds pass, but the existing Feed
  platform restriction remains.
- No live Claude or Codex agent session was launched. The Codex CLI-only path is
  exercised through the actual command dispatcher and shared Feed store without
  MCP configuration. Codex plugin installation, `grid setup codex` agent TOML,
  shell-link installation, worker supervision and liveness remain separate
  components (`docs/plugin-design.md:84`, `docs/plugin-design.md:123`,
  `docs/brain-feed.md:210`).
- This checkout has no shipped agent or skill prose yet. The shell fallback is
  documented here and in the usage guide; future agent/skill files must carry
  the same fallback (`docs/brain-feed.md:207`).
- Project-defined Feed types, lease acquisition, scheduling, sync and MCP beyond
  the five Feed tools remain outside this lane and the inherited Feed API.

## Review follow-ups

- Session precedence: for MCP, `GRID_FEED_TASK`, `GRID_JOB` and `GRID_ATTEMPT`
  win over the `task`/`project`, `job` and `attempt` arguments. A differing
  argument is refused with an error naming the variable (`sessionStore` and
  `sessionDefaults` in `internal/cli/feed.go`). The `grid feed` flags keep
  overriding the environment.
- `gitx.IsRepoRoot` compares Git's top level with the folder through
  `os.SameFile`, so a symlink or another spelling of the same folder on a
  case-insensitive file system is still the root. The old path-string compare
  failed the case test on macOS.
