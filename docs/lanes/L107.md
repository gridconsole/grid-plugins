Regression tests and the race seam were committed in `0a17d08`; file identity
and handle fixes in `e17f9e4`; whole-file approval binding in `f2be276`.

The implementation now opens a source once, uses `File.Stat` on that handle,
compares it against the task's `plan.md` for every file pointer kind, and reads
the same handle's bytes. The comparison uses `f.Task`, independently of the
repo or prototype root. Plan aliases bypass cached text, require approval for
anchors, and use the same step/verify selection as the canonical plan.
Approval and the source digest use the bytes read from the handle; CRLF
normalization happens only for rendering. Project containment and source tiers
retain their existing behavior.

`plan.Digest` is now SHA-256 of the complete file bytes, including line one.
The legacy six-digit `plan.Hash` remains compatible for display and explicit
approval commands. Existing receipts are valid only when their stored full
digest matches the new whole-file digest (and the other receipt checks pass).
Old canonical digests that differ, and receipts with no full digest, require
explicit re-approval with the current `--plan-hash`; implicit approval does not
upgrade them. Any byte edit, including a revision heading, status text, tick,
whitespace, or line ending, now invalidates approval. Re-approval records the
current full digest. LoadPlan and anchored plan reads remain unconditionally
gated, as in L104R. Anchor-less pointer behavior remains outside this lane.
