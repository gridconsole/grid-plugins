## What changed

- `grid workflow show --task <task folder or id> [--project p] [--json] [--policy]`. The task is resolved with `resolver(env).Resolve(where.Query{Cwd, Task, Project})`, as `grid plan` resolves it. Its task.md goes to `workflow.TaskWorkflow(r, scope.Project, text)`. Every read is done before anything is written to stdout.
- JSON: the read of the task's project (workflow.Answer, unchanged, embedded) plus `task`: `{id, workflow, source, file, rounds, steps[{name, kind, agent, approvers}]}`. `id` is task.md's `id`, else the folder name. `source` comes from the template's file label: `brain:project/…` gives brain:project, `brain:home/…` gives brain:home, `<p>/workflows.md` gives project, `workflows.md` gives workspace. Step name and kind are TaskWorkflow's. Agent and approvers come from the template's steps for the task's size, paired in order and checked by name.
- Built-in: only when TaskWorkflow's error text is exactly `the workspace has no default workflow` (it has no sentinel error). The flow is Run (run), then Check (check, grid-reviewer), rounds 2, matching app judge.go. Any other error goes to stderr as `grid workflow show: <err>` with exit 1 and no stdout. A resolve error records its code (`no_such_task` envelope with `--json`), as other `--task` verbs do.
- Text: `workflow: <name|(none)>`, `source: <source>`, `rounds: <n|(none)>`, one `step: <name> (<kind>[, <agent>])` per step.
- `grid workflow --help` prints a second usage line for the `--task` form. The existing usage line is unchanged (workflow_policy_test.go:203 pins it).
- Schema: optional top-level `task` with its own `additionalProperties: false`. The source enum has six values. `workflow`, `file` and `rounds` may be null. commands.json lists `--task` (takes value, not required).
