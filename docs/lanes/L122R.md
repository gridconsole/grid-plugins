## Changes

- Protect workspace and project `workflows.md` with the shared gate reason,
  including Write, Edit, MultiEdit, Bash redirects, tee, sed, and symlink aliases.
  Shell alias matching resolves literal quoted words, including spaces. Reads
  remain allowed, and existing task `workflow.md` behavior is preserved.
- Signal verbs apply project policy, then workspace inheritance, then defaults.
  Task policy adds to that set even from a task cwd or with `--act add --task`.
  Each scope's matching role restriction remains effective. A missing explicit
  task also cannot suppress the project check; normal dispatch validation stays
  in place.
- Add `--to` to skipped option values. Invalid task and project person values
  use exactly `grid: warning: invalid person_verbs; ignoring the key and keeping the person-only floor`.
  Multiple invalid scopes produce at most one such warning. Invalid extensions
  do not discard another valid scope or the person-only floor.
- Reconcile the contract's task-only statement with project/workspace policy.
  Non-signal task-scoped commands retain task-only policy.

Small change beyond the named touch files: add
`internal/guard/host_project_workflow_test.go` for the 24-case guard matrix.
All other implementation and test changes are in the requested files; no
workflow reader change was needed. The module, Makefile, signal data source,
endpoint fields, and dispatch behavior remain intact.

The first broad validation caught duplicate withdrawal diagnostics when the
person gate warned for all task read failures. The final implementation warns
for invalid person values, while task I/O and YAML parse errors retain their
existing command/store diagnostics. Existing withdrawal tests remain unchanged.
