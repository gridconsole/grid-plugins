# Lane L17: grid task

Implemented `internal/task` and registered `grid task new`, `grid task show` and `grid task list` in the existing command table. The project package is unchanged; `internal/where` gained the Personal task folder (`personal/tasks/`) after review.

Creation allocates the next home-wide `T-NN` under a cross-process exclusive `flock` taken through `internal/fslock`, resolves and registers the project while holding that lock, stages `intent.md` and YAML `task.md`, syncs both files and the staging folder, then publishes the complete task folder by rename and syncs the tasks folder. The kernel releases the lock when a process exits. Personal tasks use `personal/tasks/` and `project: personal`; `gridhome.TasksDir` owns that layout, and `where` and `grid session` reach a Personal task through it. The person's request is preserved byte for byte. Show folds the record and intent into a read-only view; list sorts by numeric id and supports an exact state filter. Plain and JSON outputs are documented in `contract/README.md`.

## Run and verify

```sh
make build
./dist/grid task new "Fix the search label" --size small --json
./dist/grid task show T-01 --json
./dist/grid task list --state queued --json
make test
make lint
```

`make test` includes table-driven tests with temporary homes, project registration and selection, Personal fallback, exact intent preservation, YAML parsing, numeric ordering, state filtering, malformed data, JSON goldens and a two-process allocation race. The two children create 24 complete tasks across Personal and the same newly registered project, then verify all ids are distinct and consecutive. `make golden` runs the writer and CLI golden tests. Both `make test` and `make lint` pass. `make build` also passes with `GOOS=linux` and `GOOS=darwin`, each with `GOARCH=amd64` and `GOARCH=arm64`.

## Limits and remaining work

All requested L17 commands and checks are complete. The following broader design work is outside this slice:

- The task fold reads `task.md` and `intent.md`; it does not fold Feed events or drive execution. Feed and lifecycle writers do not exist in this checkout. Workflow names are stored without loading or executing topic rules. The workflow and Feed responsibilities are described in `docs/plugin-design.md:159` and `:160`.
- This slice provides local `T-NN` allocation, as requested. Task ULIDs, server-assigned numbers and offline host tags from `docs/plugin-design.md:141` and `docs/go-architecture.md:264` remain for identity and sync integration. Project and machine identities are generated locally as ULIDs.
- Existing project records are preserved and first-write repo metadata is recorded using the existing resolver. Full project merge, moved-folder repair, discovery of additional repos in an already registered multi-repo project, and overlapping project refusal remain with the project slice (`docs/plugin-design.md:135` and `:136`).
- Old JavaScript writers use another lock protocol and must not write concurrently with this CLI. References were read-only, so the old scripts were not removed; migration of their `status`, inline workflow and local timestamps is left to `grid migrate` (`docs/plugin-design.md:145`).
- Locking follows the lease and session packages: `internal/fslock` implements it on Linux and macOS, and `grid task new` fails with its "not supported" error elsewhere, so `GOOS=windows go build ./...` passes. Interrupted creation can leave a hidden `.new-*` staging folder; readers and allocation ignore it, and the next `grid task new` removes ones older than five minutes under the allocation lock. No task recovery command is included in this lane.
