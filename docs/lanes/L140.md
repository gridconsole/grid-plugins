# L140: guest path follow-ups from the L136R review

Base: `42947044e49c5db95a59f074d7c3372176c5fafb` (`lane-L136R`, accepted, not on main yet).
Branch: `lane-L140`.

## What changed

1. `internal/where/where.go`, `explicitTask`: a guest (`Resolver.guest()`) who passes a task path
   outside the Grid home gets `task not found`, the answer for an unknown task, not
   `task path <path> is outside the Grid home <home>`. Owners, members and agent roles keep
   the old message byte for byte. The same text covers an absolute path, `../` and `./`
   forms, a relative path with slashes, and a symlink inside the Grid home that leaves it.
2. `internal/job/jobcmd/command.go`: `grid job show <file>` and `grid job lint <file>` (no `--task`)
   read a file by path with no membership check. For a guest, `guestFile` now sends the file's
   directory through `resolveTask`, the resolver the other job commands use, before the file is
   statted or read. A file in an uninvited project, in no task, outside the Grid home or in a
   task that does not exist answers `task not found` with exit 1, in plain and `--json`, so an
   existing and a missing file cannot be told apart. A file that is a link leaving the task is
   refused the same way. For lint the resolved task folder is the source root. Owners and
   members run the code they ran before.
3. Tests, all new (no existing test edited):
   - `internal/where/guest_test.go` `TestGuestOutsideGridHomePath`: guest, external and unknown
     roles, five path forms; the error equals the unknown-task error and holds neither the Grid home
     nor the temp root. Owner, member and builder keep the old message.
   - `internal/job/jobcmd/context_test.go` `TestGuestFilePathMembership`: show and lint, plain and
     `--json`, for uninvited, no-roles, unknown, invited, member and owner, on a task file, a
     task file by a path relative to the cwd, a file outside any task and a link out of the task.
     Guest refusals are exactly `task not found`, with no Grid home and no file content. The invited
     guest reads the task file; owner and member read all four as before (lint of a brief outside
     any task keeps exit 1 and its findings).
   - `internal/cli/guest_leaks_test.go` `TestGuestWhereTaskOutsideGridHome`: through the real CLI,
     `where --task <outside>`.
   - `internal/cli/guest_parity_test.go`: two new parity rows, `job show` and `job lint` with a
     task file by path and no `--task`, plain and JSON (the `file` form, placeholder
     `{task-file}`). Existing rows and placeholders are unchanged.
