# L62 — Claude Code setup block

Implemented on `lane-L62`, based on `main` at `f39661a`. Documentation checked on 2026-11-08. The only edit to an existing production file is a branch at the top of `internal/cli/settings.go:runSetup`; the original project-answers path remains byte-for-byte identical.

## Behavior

`grid setup [--yes] [--json]` previews and installs the personal Claude Code block. `grid setup --remove [--yes] [--json]` previews and removes its recorded entries. `grid setup --help` names these forms and the existing project form. Project arguments, including flags before the operand and `--answers -`, retain their existing behavior and golden output.

The preview prints missing entries with `+`, present entries with `=`, the JSON block, and (on a terminal) `Write these? [y/N] `. Removal lists existing owned entries with `-` and asks `Remove these? [y/N] `. Only `y` or `yes`, case-insensitively, accepts. Other input prints `Nothing written.` with exit 0. Non-terminal input never prompts or writes without `--yes`; JSON also needs `--yes` to write. JSON output has exactly `path`, `added`, `present`, and `written`; for removal, `added` lists the recorded entries selected for removal. Missing records produce `Nothing to remove.` (or the empty JSON result).

Invalid JSON, duplicate object keys in edited objects, and malformed edited arrays are refused with the specified invalid-settings message and exit 2. A changed snapshot is refused with `Settings file changed while writing. Nothing written.` and exit 1. No-op installs preserve both files, including the original ownership record.

## Reserved paths and persistence

The deny data follows `EvaluateOnlyWriter` in `internal/guard/writer.go`, including the helpers it calls:

| Reserved kind | Grid-relative pattern before case expansion |
| --- | --- |
| Project task folder and descendants | `projects/*/tasks/[Tt]-[0-9]*/**` |
| Personal task folder and descendants | `personal/tasks/[Tt]-[0-9]*/**` |
| Project brain | `projects/*/knowledge/**` |
| Home brain | `knowledge/**` |
| Project record | `projects/*/project.md` |

Names folded by the guard use explicit letter classes in the generated patterns; numeric task prefixes follow the guard's `T-\d+` criterion. CLI tests compare matching against the live guard for both Edit and Write, including near misses, nested files, and case variants. A reviewed snapshot of `writer.go` makes any newly added reserved kind fail tests until the block and parity coverage are reconciled. These are Claude permission patterns, not an implementation of the guard's symlink resolution or general filesystem enforcement.

Settings edits preserve top-level and nested key order, raw values of unrelated keys (including large numbers), and the order of existing permission entries. Only missing strings are appended. Existing modes are retained; new settings and ownership records use 0600, and missing directories use 0700. The settings file may be a symlink **only to an existing regular file**: its resolved target is atomically replaced and the symlink remains. Dangling links, directory targets, and other nonregular files are refused.

Files are staged with `internal/atomicfile`, then the settings bytes, target, mode, existence, and ownership record are rechecked immediately before the final rename. Tests inject changes after staging and before that check. Stages are cleaned up on refusal. This is an optimistic check, not an OS-level compare-and-swap: an external writer after the last read can still race the rename.

`<grid home>/setup/claude-block.json` binds ownership to the settings path and records only entries setup added. Later partial installs retain earlier ownership and add only newly missing entries; entries already owned by the person are never claimed. Removal preserves unrelated settings, deletes the ownership record after success, and can leave empty permission arrays or objects. Settings replacement and record replacement/deletion are separate filesystem operations, not one crash-atomic transaction; interruption between them can require manual reconciliation.
