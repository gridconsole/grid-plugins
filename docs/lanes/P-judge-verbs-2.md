## What changed

- `internal/judge/state.go`: `State.Tip` reads the task's remote as it is now (a full ref gives its SHA there, or "" when the ref is absent). `State.HeadRef` is `refs/grid/<T>/head`. With `Tip` nil, no remote is read.
- `internal/judge/rework.go`: `reworkBase` uses the remote when `Tip` is set. It returns the head ref's SHA, else the tip of the target branch: `--target`, else the first branch-named `target` or `base` along the builder's chain (`targetOf`). A name without `refs/` is read as `refs/heads/<name>`. If the remote cannot be read, or holds no such branch, `Rework` returns an error and posts nothing. New: `HeadRef(task)` and `RemoteTip(dir, remote)`, which runs `git ls-remote` with `GIT_TERMINAL_PROMPT=0` and matches the exact ref name.
- `internal/cli/judge.go`: `grid judge rework --remote <remote>` (a remote of the checkout it runs in, a URL or a path). `<T>` is the T-<n> id at the front of the task folder's name. The usage line explains it.
- `contract/commands.json`: `--remote` (value, optional) under judge → rework.

## NOT VERIFIED and open items

- The orchestrator (its lane) must pass `--remote` for the rework base to be read live. Without it, the old fallback stays: the newest head post's SHA, else the target branch as named.
- `<T>` is read from the task folder's name (`T-07-example` gives `T-07`). A task folder without a T-<n> prefix makes `--remote` fail with a message; such folders were not looked for.
- The remote is read with `git ls-remote` only. Auth prompts are turned off, so a remote that needs credentials fails rather than waits. This was tested only against local bare remotes.
