# L61: land follow-ups

Land reads the selected task workflow from
`projects/<project>/knowledge/workflows/<workflow>.md`. This checkout has no
`internal/workflow` reader. The front-matter field `land-approval` accepts
`plan`, `ship`, or `none`; an absent field or unselected workflow defaults to
`plan`. Missing selected workflows and malformed policies fail closed.
The deploy rule's legacy `needs-approve` field does not select policy.
Dry-run JSON includes `approval_gate` so the required gate is reviewable.

`grid approve` now records a SHA-256 `lands_hash` beside `plan_hash` in the
existing authoritative plan or ship receipt. The digest covers the parsed
lands rule, not Markdown formatting. Existing receipts without this binding
need fresh approval before landing. Approving a changed binding over an
existing receipt requires the explicit `--plan-hash` review token, as a changed
plan already did. Projects without a deploy topic retain ordinary approvals.
The task package adds the receipt field and a gate-selecting locked reader;
the CLI approval wiring captures the lands rule through `land.Store.Approve`.
Land never trusts `approvals/land.json`. Missing, stale, wrong-gate, or unbound
receipts return final-rejection exit status 3.

The workflow and lands-mutation regressions were run against the original
implementation and failed for the expected behavior. The forged fixture now
contains `plan.hash`; a paired test rejects that fixture and succeeds only
when an authoritative approval is added.

Deploy rules may include `env: [DEPLOY_TOKEN, REGION]`, a list of environment
variable names. The child receives only PATH, HOME, USERPROFILE, SystemRoot,
TEMP, TMP, LANG, those explicitly named variables, and the four generated
GRID land metadata variables. Explicitly listing a GRID metadata name cannot
override its generated value. The allowlist itself is part of the approved
rule digest. Values are inherited at execution and are not stored in receipts.

Land has a bounded process runner in `internal/land` to keep this change out of
the shared eval package. It retains eval's result format and 64 KiB per-stream
output limits. Linux and macOS kill the process group; Windows uses the OS
`System32/taskkill.exe /T /F /PID` on cancellation, with a bounded timeout for
taskkill and a direct-process fallback if the OS tool fails. Windows runtime
execution is not exercised on this Linux runner; Windows build and vet passed.

Land start/result history now uses `task.AppendHistory`, sharing the inode
lock with hook appenders. A missing history file is initialized exclusively
without replacing an existing file. No-approval workflows still receive start
and outcome lines. Symlinks are refused before command execution. The parallel
land/hook regression reproduced lost lines with the old Note writer and passes
30 repetitions with the append writer. Other task commands' journal writers
are unchanged.

The secret-environment regression failed before filtering was implemented.
The forgery test was also mutation-checked: temporarily removing the entire
authoritative approval check caused
`TestForgedApprovalRequiresAuthoritativeReceipt` to fail, while the restored
implementation passed. The Unix timeout test starts a TERM-ignoring descendant
and verifies that it cannot produce a delayed side effect after timeout.

All required validation passed on the final implementation:

```sh
go test -race -count=1 ./internal/land ./internal/task ./internal/cli
go test ./internal/land -run TestConcurrentHistoryAppend -count=30
make lint
make test
GOOS=windows go build ./...
GOOS=windows go vet ./internal/land/...
GOOS=darwin go build ./...
```

`make test` also reported no temporary-file leaks. The workflow gate, changed
lands rule, secret environment, and concurrent append tests reproduced their
respective failures before the fixes. CLI coverage verifies that a changed
approved lands target returns exit 3 without executing the command. Runtime
process-tree coverage was exercised on Linux; Darwin was cross-built only.

## Rework

L61R starts from `origin/lane-L61` (`e861df9`) and rebases onto `origin/main`
(`f39661a`); main was already an ancestor, so no conflicts needed resolution.

The host guard now fences `approval-ship.json` alongside `approval.json` in
both its shell-name and task-file checks. These are the two approval receipts
read by land and approve. Existing gate, settings, and feed protections remain
in place. The denial message names both approval files. Tests cover agent
Write, Edit, MultiEdit, and NotebookEdit calls for project and personal tasks,
plus Bash redirects, tee, cp, mv, sed -i, and python -c with relative, absolute,
and case-alias paths. Reads and lookalike filenames retain their prior behavior.
This remains the host guard's textual fence, not an OS filesystem sandbox.

`TestHostApprovalReceipts` and `TestAgentCannotForgeShipApproval` were first
run against the unchanged lane-L61 implementation and failed: the agent Write
was allowed, the correctly hashed forged ship receipt reached disk, and land
ran the deploy command. After the fix, the same test refuses the Write, leaves
the receipt absent, and verifies that land returns `ErrRejected` without the
command's side effect. A subsequent person approval releases that same command.

The stricter approval policy now wins. `land-approval: none` combined with
`needs-approve: true` requires a plan receipt, and dry-run reports `plan` as its
effective gate. Explicit plan and ship gates remain required even when the
deploy rule says false. This supersedes the earlier statement that the legacy
field does not select policy. The six-combination policy test failed on
lane-L61 for none/true, including an unexpected deploy side effect, and passes
after the fix. Existing no-approval fixtures now explicitly opt out in both
the workflow and the deploy rule.

The deploy allowlist retains its existing common variables and adds COMSPEC,
PATHEXT, APPDATA, LOCALAPPDATA, ProgramData, SystemDrive, and windir on Windows,
and TMPDIR and USER on macOS. SSH_AUTH_SOCK remains excluded unless explicitly
listed in `lands.env`. Pure Linux, Darwin, and Windows table tests cover the
defaults, explicit credential opt-in, Windows case-insensitive matching, and
Unix case-sensitive matching. After extracting the existing filter into a
pure helper, the Darwin and Windows cases failed before adding the platform
variables. Windows cancellation now uses `C:\Windows\System32\taskkill.exe`
when SystemRoot is unset; pure path tests cover the fallback, custom roots,
and trailing separators without requiring a Windows runtime.

All rework validation passed:

```sh

make lint
go test -race -count=1 ./internal/guard/... ./internal/land/... ./internal/task/... ./internal/cli/...
GOOS=windows go build ./...
GOOS=darwin go build ./...
```

`make lint` ran `go vet ./...` and the formatting check. `make test` ran the
uncached full suite and reported no temporary-file leaks. The new guard and
land regressions pass, as do the existing protections. Runtime execution was
tested on Linux; Windows and macOS were cross-built, with their environment
policies and the Windows taskkill path exercised through pure functions.
