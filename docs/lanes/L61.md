# L61: land follow-ups

Land reads the selected task workflow from
`projects/<project>/knowledge/workflows/<workflow>.md`. This checkout has no
`internal/workflow` reader. The front-matter field `land-approval` accepts
`plan`, `ship`, or `none`; an absent field or unselected workflow defaults to
`plan`. Missing selected workflows and malformed policies fail closed.
The deploy rule's legacy `needs-approve` field does not select policy.
Dry-run JSON includes `approval_gate` so the required gate is reviewable.

`grid approve` now records a SHA-256 `lands_hash` beside `plan_hash` in the
existing authoritative plan or ship receipt. The digest covers the parsed
lands rule, not Markdown formatting. Existing receipts without this binding
need fresh approval before landing. Approving a changed binding over an
existing receipt requires the explicit `--plan-hash` review token, as a changed
plan already did. Projects without a deploy topic retain ordinary approvals.
The task package adds the receipt field and a gate-selecting locked reader;
the CLI approval wiring captures the lands rule through `land.Store.Approve`.
Land never trusts `approvals/land.json`. Missing, stale, wrong-gate, or unbound
receipts return final-rejection exit status 3.

The workflow and lands-mutation regressions were run against the original
implementation and failed for the expected behavior. The forged fixture now
contains `plan.hash`; a paired test rejects that fixture and succeeds only
when an authoritative approval is added.

Validation results and the remaining runtime changes will be recorded here
before completion.

Deploy rules may include `env: [DEPLOY_TOKEN, REGION]`, a list of environment
variable names. The child receives only PATH, HOME, USERPROFILE, SystemRoot,
TEMP, TMP, LANG, those explicitly named variables, and the four generated
GRID land metadata variables. Explicitly listing a GRID metadata name cannot
override its generated value. The allowlist itself is part of the approved
rule digest. Values are inherited at execution and are not stored in receipts.

Land has a bounded process runner in `internal/land` to keep this change out of
the shared eval package. It retains eval's result format and 64 KiB per-stream
output limits. Linux and macOS kill the process group; Windows uses the OS
`System32/taskkill.exe /T /F /PID` on cancellation, with a bounded timeout for
taskkill and a direct-process fallback if the OS tool fails. Windows runtime
execution is not exercised on this Linux runner; Windows build and vet are
required checks.

Land start/result history now uses `task.AppendHistory`, sharing the inode
lock with hook appenders. A missing history file is initialized exclusively
without replacing an existing file. No-approval workflows still receive start
and outcome lines. Symlinks are refused before command execution. The parallel
land/hook regression reproduced lost lines with the old Note writer and passes
30 repetitions with the append writer. Other task commands' journal writers
are unchanged.

The secret-environment regression failed before filtering was implemented.
The forgery test was also mutation-checked: temporarily removing the entire
authoritative approval check caused
`TestForgedApprovalRequiresAuthoritativeReceipt` to fail, while the restored
implementation passed. The Unix timeout test starts a TERM-ignoring descendant
and verifies that it cannot produce a delayed side effect after timeout.
