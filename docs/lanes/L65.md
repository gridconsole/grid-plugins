# L65: refusal exit codes

Base: plugin main `349b3e671d17da6c77dd5e3876bce57cc21291a3`.
Branch: `lane-L65`.

## Behavior

- Intent claim, renew, release and done classify `ErrClaimed` and `ErrDone` as
  **5 taken**, and `ErrClaim` (no current token) as **3 rejected**. Diagnostics
  remain byte-for-byte unchanged. Storage and scope errors remain **1 failed**;
  missing required CLI arguments remain **2 usage**. A matching done replay
  still succeeds. Renew, release and done currently return `ErrDone` or
  `ErrClaim`; the shared classifier also handles wrapped `ErrClaimed`.
- `refuseJobSide` wraps both Job-side kinds and Job-lease refusals in
  `feed.InvalidRecordError`, preserving their text and making
  `errors.Is(err, feed.ErrInvalidRecord)` true. Feed CLI refusals now exit 3.
- General help and the contract document status 5 and the new status 3 cases.
  The help exit-status line is pinned by an inline golden in
  `internal/cli/exit_refusal_test.go`.

## MCP

There is **no dedicated `ErrInvalidRecord` mapping or rejection-kind enum** in
`internal/mcp`. At the base SHA, `internal/mcp/server.go:170-172` passes all tool
call errors to `toolError`; `internal/mcp/tools.go:153-156` produces
`isError: true` with a text content object containing `{"error":"<diagnostic>"}`.
Job-side refusal uses that same existing result as an invalid record. No MCP
production code changed. The new external-package MCP test invokes the real
`grid mcp` entry point and session callback, compares the result shape with an
invalid-body rejection, and verifies all Feed file bytes remain unchanged.

## App follow-up

An app lane should update the exit-code readers in `cmd/grid-worker` and
`internal/kernel/plugincli/client.go:84` (location supplied in the lane brief):

- Recognize **5 taken** from claim, renew, release and done, and skip the intent
  quietly. Do not report it as a storage failure or put it into failure retries.
  Ownership may change, so future normal polling may encounter it again.
- Treat **3 rejected** as final for the submitted token or record; stop acting
  with that token. Preserve **1 failed** for errors that may be retried.
- Add consumer coverage for 0 followed by 5, completed-intent 5, and stale-token 3.

These are follow-up requirements, not app changes made by this plugin lane.
