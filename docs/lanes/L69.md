## Changes and choices

- Added `grid task rename <T-NN> --title <text> [--project <p>] [--json]` and `grid task decline <T-NN> --reason <text> [--project <p>] [--json]`, with golden task help coverage. Existing plain and JSON write receipt formats are retained.
- Rename collapses Unicode whitespace and counts Unicode code points after collapse, accepting 1–200. CR, LF, NEL, Unicode line/paragraph separators, NUL and invalid UTF-8 are rejected before writing. The normalized title is compared exactly with the stored title. Closed tasks and unchanged titles exit 3; invalid titles exit 2.
- Decline collapses all whitespace, including line breaks. An empty reason, NUL or invalid UTF-8 exits 2. No additional reason-length limit is imposed. Closed tasks and `kind: planner` exit 3; planner detection decodes YAML, including aliases. Other kinds and an absent kind can be declined.
- Decline updates `state`, `next` and `updated`. The host person is `GRID_ACTOR`, falling back to `GRID_WHO`, then `you` for `next`. Host person whitespace is collapsed for `next`; invalid UTF-8 or NUL fails. The receipt retains the existing author shape, with `local` for an absent author and the member audit role preserved. No operating-system identity is inferred by either verb.
- History remains a JSON object per Markdown bullet under the existing commit protocol. `what` is `rename` or `decline`; `note` is exactly `renamed · <title>` or `closed · declined · <reason>` after normalization. JSON escaping preserves quotes and punctuation. Existing history is retained; each successful write adds one receipt. The receipt's UTC timestamp is also written to `updated`.
- `RenameAllowed` and `DeclineAllowed` are replaceable `func(role string) bool` variables. Defaults allow empty, owner and member, and deny guest and other unknown roles (including `cli`). The caller passes a trimmed host role independently of the audit role's owner default. Input validation precedes policy checks; policies run before resolution or locking. Closed-state rejection precedes unchanged-title or planner rejection. A host or workflow can replace them during initialization, before concurrent writes; runtime mutation is not synchronized. The future workflow keys are `task_rename_roles` and `task_decline_roles`. No workflow file is read, and these operations request no owner approval.
- `--project` resolves registered project names or ids, with case-insensitive Personal selection, and constrains the locked task's project. With no project, existing home-wide task-id lookup applies; duplicate ids remain errors. Scope and filesystem failures exit 1. Global exit-code handling is unchanged.
- To honor the narrow `write.go` edit boundary, it remains untouched. The new writers reuse the transaction primitives behind `Change`: `withWrite` for locking, recovery and rereading, `Fold` for validation, and `commitWrite` for the redo journal, history and atomic publication. They do not invoke the state-only `Change` method itself. The task-file read also uses the existing no-follow reader. Rejected writes produce no new receipt; guest and custom-policy refusals create no files.
- Rename changes only title and updated, preserving other bytes, including quotes, unknown keys, comments, body and LF/CRLF endings. Missing updated is appended to the header. Targeted YAML edits use source positions, since the general YAML reserializer can alter unrelated formatting. Block and quoted multiline scalar values can be replaced. Flow-style top-level headers, anchored or aliased edited values, indented edited keys, and values starting below their key are refused with exit 1 before commit. This avoids silently altering other fields through aliases or reformatting.
- Decline preserves unrelated fields and adds missing next/updated in sorted order. Unlike the Rust application lifecycle, these plugin verbs do not add Undo or lane fields, alter folders, touch execution, or change intent/summary.
