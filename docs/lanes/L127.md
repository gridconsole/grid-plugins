## Changes

Setup and doctor now share `readClaudeFile`, including symlink resolution,
regular-file validation, opening, and reading. Regular, readable targets are
accepted. Dangling links report `Claude settings file is a dangling symlink`;
nonregular targets report `Claude settings file is not a regular file`.
The shared reader checks the opened file's identity and rejects a final target
replaced by a symlink. Setup retains its existing detailed errors and write-time
change checks; doctor receives path-free reasons. Doctor never changes the link,
target, or setup ownership record.

An unavailable Grid home leaves the allow check in its existing position with
`ok: true`, detail `skipped: Grid home is unavailable`, and no fix hint. The check
does not read settings in that case. With otherwise healthy installation checks,
a missing home produces exactly one failure and exit 1. A home that is a file
also skips the allow check.

Missing rules and missing settings use `Run grid setup`. Invalid JSON or
structure, unreadable files, dangling links, and nonregular targets use
`Fix or move the Claude settings file, then run grid setup.` Invalid permission
anchors instead ask to fix the Grid home location before running setup. No hint
includes a path or settings value. Existing check order and JSON fields remain.

README and contract documentation describe only these behavior and text changes.
Only the missing-home doctor golden changes; the other doctor goldens remain
byte-for-byte unchanged.

## Supporting changes

  `claudeReadError.Error` and `claudeReadError.Unwrap` methods in `claude.go`.

source was replaced and no fields or unrelated behavior were removed.
