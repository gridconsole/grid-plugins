# Lane L22: task questions, updated by L39

`grid answer <task> Q-N "text"` is the only answer command. `grid question` provides add, withdraw, list, tick and sync. The answer command has no nested alias or free attribution flag.

```sh
grid question add "Which format?" --who owner \
  --option CSV --option JSON --recommended CSV \
  --default CSV --applies 2026-11-09T10:00:00Z --blocking \
  --job J-2.1 --item 3
grid answer T-01 Q-1 "Use both formats"
grid question list --json
grid question sync T-01
grid question withdraw Q-2 --reason "No longer needed"
grid question tick
```

Question subcommands use the enclosing task or `--task <path-or-id>`; sync also accepts a positional task. Answer takes an explicit task. Resolution uses the existing Grid-home resolver. The task must already have a stable Feed ULID in task.md (`ulid`, or `id` for a Feed-only task), as required by the Feed writer. No task is created implicitly. Flags may precede or follow operands; `--` protects literal operands starting with a dash.

Options are optional, including an empty list. When options exist, `--recommended` must name one of them. Free-text answers are always accepted. `--who` defaults to `owner`; `--blocking` defaults to false. Default text and an RFC3339 deadline are required. `--age-after` defaults to eight hours and must be a positive whole number of seconds. Optional `--job` accepts hierarchical J-ids; `--item` is a positive plan item number.

The CLI uses the Feed caller identity: `GRID_MEMBER`, otherwise git's configured email, otherwise the OS user; `GRID_ROLE` defaults to member. History records the actual caller's id and role, never the question's recipient or an attribution flag. A guest may answer only a question addressed to that guest's id. Owner, member and lead roles may answer a question addressed to anyone, including a guest. Agent and CLI roles cannot answer person gates. Host guards still refuse an agent answering its own gate or writing question files directly.

## Feed authority and recovery

Add appends a question record through `internal/feed`. Answer appends an answer with `re` equal to that question's record ULID. Both use the caller's fence-0 writer, even when lease variables are present. Only after that append succeeds does the store write `questions/Q-N.md` through `internal/atomicfile`.

The file is a projection, not an editable source of decisions. Its required `post` names the Feed question; each history entry has its answer/control `post`, caller `who`, caller `role`, time, kind and text. Its gate includes `id`, `kind: person`, `default` and `at`, exactly as posted. Job, item, options, recommendation and aging interval are retained in the question post so deletion loses no projection metadata. Times use UTC with three fractional digits. The shared schemas validate Feed records and question files; no Go source in `internal/contract` changes.

List reconstructs questions in memory from an admitted Feed snapshot without locks or file writes, including cache writes. Sync and mutations use the existing task question lock to repair missing or changed backed projections. An append that succeeds before a projection failure remains authoritative: sync or a retry repairs the file. Identical answer retries append no second answer. Unbacked Q-N.md files remain byte-identical, are listed with a "not in the Feed" warning and reserve their ids; changing them requires migration first. Other Markdown names, including old per-recipient files, are skipped with a warning and remain untouched. Duplicate Q-ids in the Feed fail explicitly rather than silently choosing one.

The Feed adapter closes a person gate when it has one distinct eligible answer. Conflicting answers imported from independent writers require an existing task control to select one; a due default can still release the gate. Explicit selections of eligible person answers retain their authority; arrival time never chooses a conflict winner. The adapter updates the shared state projection's question, Needs you and Job open-question lists. Contract verdicts remain unchanged. It does not issue Job status controls or run an Orchestrator.

## Deadline and withdrawal controls

A passed default releases the person gate from the folded question and read clock alone. Withdrawal, aging and optional tick audit events append task-lease control records before updating files. Their schema adds `question_event`, `text` and an aging `level`, with the existing task-lease requirements unchanged. A caller performing these mutations must supply an already granted and handed-over task tenure through `GRID_LEASE=task` and `GRID_LEASE_EPOCH=<generation>.<fence>`. The CLI does not acquire a lease or manufacture a handover. A tick with nothing due needs no control write.

Only open questions can be newly withdrawn. Repeated withdrawals and identical answers are no-ops. A different human answer cannot overwrite a recorded answer. A late answer replaces a default while retaining its control event if tick recorded one. A deadline-only default has no history event. Blocking questions age at one and two intervals, at most twice; a due default takes precedence. No arbitrary external action runs when a default applies. Feed fencing excludes stale controls during reconstruction.

## Verification and remaining integration

Run `make test` with the default TMPDIR and `make lint`. Cross-build with `GOOS=windows go build ./...` and `GOOS=darwin go build ./...`. Focused suites are `go test ./internal/question ./internal/feed ./internal/cli ./internal/guard ./internal/contract`. The golden question list normalizes random post ULIDs; regenerate it with `UPDATE_GOLDEN=1 go test ./internal/question`.

Tests cover posting and file agreement, deletion and corruption recovery, free text, guest authorization, role stamping, schema fields, removed command surfaces, conflicting candidates, explicit selections, stale controls, concurrent allocation/ticks, deadline boundaries and symlink handling. The existing fslock platform implementation and atomicfile helper provide portability; ancestor symlinks are resolved without assuming a literal temporary-directory path.

Automatic command/hook/worker ticks, Job resumption, task.md/history.md planner edits, legacy migration and UI rendering remain separate integrations. The protected shared contract fold still implements explicit answer selection; Feed consumers must use `feed.Store.State`, `SaveState` or `FoldRead` to obtain the person-gate extension. See [L39 completion notes](L39.md) for the old-plugin differences and reference lines.
