# O-brain-supersede-on-accept: accepting a note that supersedes another marks the old one and the index stops counting it

Repo: plugin, lane branch lane-O-brain-supersede-on-accept, from main 330256ce. Reissue of the withdrawn L-brain-supersede-on-accept; this one adds no refusal at accept.

## What changed

- `internal/brain/store.go`: new `supersede` and `markSuperseded`, called from the accept branch of `decide` after the new note is published and its decision logged, and before the proposal is marked accepted (so an interrupted accept is retried and finishes). A link with rel `supersedes` to `brain:<this level>/<name>` (an `#anchor` is ignored) names an accepted note at the same level. That note is rewritten with `superseded_by: brain:<level>/<new name>` and no other field changes (`updated` stays). Order is the decision's order: version through `recordVersion`, then the note, then one audit line (status `superseded`, reason `superseded by brain:<level>/<new name>`, origin of the accepted proposal, topic, version and hash), so `grid brain changes` and revert see it. Nothing is deleted.
- `internal/brain/task_decide.go`: `DecideTask` accept and merge-into call the same helper after `logDecision`, with the proposal's own links (a merge appends them to the target) and the proposal's origin. The receipt's `Done` return stays the early exit, so a repeat writes nothing.
- `internal/brain/index.go` `rows`: a note with `superseded_by` is not counted in a topic's `Entries`. `Index()`, `RebuildIndex`, `index.md` and the SessionStart text all come from `rows`, so all four drop it.
- `internal/brain/supersede_test.go`: nine test functions, new file.

Choices the brief left open:

- A target that is missing, at the other level, a `job:` or `person:` target, the new note itself, or not a valid accepted note is a plain link: the accept succeeds, nothing is marked, no log line. Same when the proposal is merged into a target.
- A note already superseded keeps its mark; a second superseder does not overwrite it.
- A new note that is itself superseded (a merge-into onto a superseded target) marks nothing, so two notes never end up each superseded by the other and both gone from Search.
- Retry: a note already marked by this same note is not rewritten. If its newest version holds its current bytes, only the audit line is written again (`logAudit` drops a line that is already there). This closes the window between the note write and the log line.

## Open items

- A hand-written old note with no version history gets its first version from the marking, so v1 holds the marked bytes and there is no copy of the unmarked note to revert to. Notes accepted through Accept or DecideTask have v1 as published. Not changed: the brief asks only for the new bytes to get a version.
- `rows` still returns every note to `RebuildIndex`, so a superseded note's outgoing links stay in `backlinks.json`, and a topic's `last_change` still counts its `updated`. The brief names only Entries.
- A superseded note is still returned by `Store.entries` and `Show` (by design: the brief wants Show to keep working); only `Search` and the index count drop it.
- The audit status `superseded` is new; `parseAudit` accepts any status, and braincmd and cli tests pass, but a reader that switches on status (a UI) would show it as an unknown word.
