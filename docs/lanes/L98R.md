# L98R: guest role normalization and project-md access

Branch: `lane-L98R`. Started from `origin/lane-L98` and rebased onto plugin
main `08f896491ebf56da3015f6028807b5431cc9b1f0` as requested. The regression
baseline is plugin main `105d48dc4e1ac683bb3e0e2c1ea4a5478df58208`.

## Changes and policy

`where.Resolver.guest()` now uses
`contract.TierFor(r.Caller.Role) == contract.PersonGuest`, matching the shared
role normalization. Both `grid-guest` and ` GRID-GUEST ` receive the same
membership checks as `guest`. Regression rows cover task roots, project lists,
and explicit `where --project beta --json` refusal.

`projectmd.Key` now requires a resolver, and the CLI supplies its caller-aware
resolver. The package loads projects through `Resolver.Projects()`, which checks
membership before reading metadata. This also preserves project-name and ID
lookup while hiding malformed records belonging to uninvited projects.

For guests, unknown and uninvited projects return exit 1, empty stdout, and
exactly `project-md: project not found` followed by a newline, for both get and
set and in both plain and JSON modes. The supplied selector is not echoed.
An invited guest retains the existing get output. All guest sets are refused
before taking the projects lock or editing the file; an invited guest receives
`project-md: guests cannot write project.md` followed by a newline.

No implemented project setting grants guests permission to write project.md.
The default therefore refuses set for all guests, as requested. This follows
the guest brain-write default documented by `contract/formats.md` and the
`project_brain` policy in `contract/schemas/fmt-sync-manifest.json` at plugin
main `08f896491ebf56da3015f6028807b5431cc9b1f0`; no new grant setting was invented.
Owner and member behavior is unchanged, including sets by project ID and gets
by name without a membership document.

## Scope and tests

The new CLI matrix checks `guest`, `grid-guest`, and ` GRID-GUEST ` with invited
and uninvited identities, project names and IDs, plain and JSON output,
byte-identical unknown/uninvited responses, unchanged file bytes after refused
sets, and absence of the projects lock. Separate cases cover malformed hidden
metadata and unchanged owner/member reads and writes.

The only supporting API adjustment is in
`internal/projectmd/projectmd_test.go`: its existing lock/mode test now passes
an explicit resolver to the mandatory caller-aware API.

The full suite also required a minimal change outside the touch list:
`internal/guard/home_personal_test.go` now explicitly invites `gus` in
`TestHomeRoleAccess` and `TestHomeGlobStructure`; the latter also stamps the
member identity. These tests expect an active guest project, but their fixtures
had no membership document. Their assertions and production guard behavior
are unchanged. This report is the only added file. `go.mod` and `Makefile`
are unchanged, and no root DONE.md was added.
