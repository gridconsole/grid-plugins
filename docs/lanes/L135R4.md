# L135R4 — quote groups and comments in the host guard

## Base

`lane-L135R3` (c3731470), rebased onto plugin main `03a9e574` (the rebase was
clean). Code head `275c660b`; this report is the commit on top of it.

## What changed

`internal/guard/host_targets.go` and `internal/guard/host.go` (one refusal check),
plus a new test file, `internal/guard/host_write_targets_quote_groups_test.go`. No
existing test is edited. The correction to the L135R3 "Known cost" paragraph is in
`docs/lanes/L135R3.md` (the pinned line was refused on main and on L135RR too).

1. Single quotes (must-fix 1). In a `'..'` group nothing but `'` is special, not a
   backslash. `hostShellGroup` returns at the first `'`. Rows sq1-sq5.
2. Double quotes (must-fix 2). In a `".."` group only `\`, `"`, a backtick, `$(` and
   `${` are special; `'`, `(` and `{` are skipped as literals. Rows dq1, dq2.
3. `$'..'` (found while doing 1). It is the one single-quoted form where a backslash
   escapes, so `$'\''` is one quote. Making the backslash literal in `'..'` would
   have broken it (a new bypass against L135R3), so `hostShellGroup` and
   `hostShellTokens` skip `$'..'` with backslash escapes. Rows ansi_*.
4. Comments (must-fix 3). A `#` at the start of a word (after a blank, `;`, `&`, `|`,
   `<`, `>`, `(`, `)` or a newline, not inside a word, not in quotes) begins a comment
   that ends at the newline. `hostShellGroup` skips it in a `( )` group, and
   `hostShellTokens` skips it at the top level (`comment`, with `started` telling a
   word that has begun, even an empty `''`). A `$( )` or backtick in a comment is
   still scanned, because an unquoted heredoc line runs it; it ends as a token with
   no text, which `hostSegments` keeps in `comments` and scans.
5. Continuations in comments. A comment ends at its newline even after a backslash,
   so `echo a # c \` NL `tee alias </dev/null` runs tee. `hostJoinLines` used to join
   that pair and hide tee in the comment. It now returns a second value, set when a
   backslash-newline pair falls on a line after a comment `#`; the tokenizer ends its
   list with a `hostRefuse` token and both consumers (`protectedWriteReason`,
   `writesProjectWorkflow`) refuse the command. This is the fail-closed part: the join
   cannot tell a comment from a `#` inside quotes when the text holds a substitution,
   a backtick, a heredoc or `$'..'`; then every `#` at the start of a word counts,
   quoted or not (`echo "fix #12" $(date) \` NL ` b` is refused). With none of those
   the quotes are tracked and only a real comment counts (`echo "fix #12" \` NL ` b`
   runs). In that mode a backslash inside `'..'` is literal.

### Real shells

Every deny row, run with `alias -> workflows.md` in a scratch folder, `timeout 10`:
bash 5.3.9 (VM) truncates the file for all 25 rows that write, and zsh 5.9 and bash
3.2 (laptop) for all but three. The three that bash 3.2 does not truncate
(`comment_continuation_group`, `comment_quote_group_tail`,

file in all three. Output: scratchpad `r4-bash539.txt`, `r4-bash32.txt`, `r4-zsh.txt`.
