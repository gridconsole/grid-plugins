# L130: person tests isolate inherited agent environments

Base: plugin main `704045cd93d4fc4bfdb1117f188d7dcdd06bff9a` (after `f68cf6e3`). Implementation: `0dbc17b0ba7033387aa9a91ee03471c389cfb8ee`.

## Scope and behavior

The brief's marker inventory differs from this base. The production gate reads `GRID_AGENT`, `GRID_WORKER`, `GRID_WORKER_ID`, `GRID_LEASE`, `GRID_LEASE_EPOCH`, `GRID_JOB`, `CLAUDE_CODE_CHILD_SESSION`, every environment name beginning with `GRID_WORKER` or `GRID_LEASE`, and the verb-sensitive `GRID_ROLE`. It does not reject `AI_AGENT`, `CLAUDECODE`, arbitrary `CLAUDE_CODE_*`, `CLAUDE_PID`, or `CLAUDE_EFFORT`; the existing `TestProcessGate/ide` explicitly allows `CLAUDECODE`. This lane preserves those semantics.

`persongate.EnvironmentKeys` now owns the list and wildcard discovery used by both `Check` and `testenv.Person`. Role policy still runs separately after the unconditional marker checks. Process ancestry, person-directory validation, policy, receipts, CLI dispatch, and the verb floor are unchanged.

`testenv.Person(t)` uses `t.Setenv(key, "")` at fixture construction, restoring inherited values at cleanup. It is called by the existing CLI `personTestEnv` helper and the question package's CLI withdrawal test before explicit role/agent setup. It never runs during command dispatch. Tests that set markers afterward still reach the real gate. There is no test runner wrapper or production bypass.

The minimal supporting changes outside the CLI tests are the gate's shared list, the helper and its restoration regression in the existing `internal/testenv` package, and replacement of the question CLI test's copied marker list. Writer-specific `GRID_FEED_TASK` and `GRID_ATTEMPT` setup remains. No endpoint source, field, behavior, gate, guard, or hook assertion was removed.

## Test audit

Searched all `*_test.go` files for `approve`, `answer`, `question`, `person`, gate helpers and marker names, then every verb in `persongate.Floor()`. Also searched for `cli.Run`, direct `Run` calls, CLI environment construction, and executable subprocesses so aliases, table-driven commands, and helper processes were included.

The floor is: `approve`, `refusal decide`, `decide`, `answer`, `question answer`, `question withdraw`, `task status`, `task stop`, `task close`, `task reopen`, `task delete`, `task restore`, `task rename`, `task decline`, `hook level`, `agent set`, `skill enable`, `skill disable`, and `setup`. The audit also includes `person check` and workflow-added verbs such as `task show` and `deliver`.

| Tests / entry points | Isolation and disposition |
| --- | --- |
| CLI tests using `newHarness`, `harnessFor`, `feedHarness`, and `orchestratorHarness` | All reach `personTestEnv`, which now calls the shared helper. This covers person/approval/decision/question tests; task lifecycle and operand tables; plan digest and policy tests; settings, setup, skill and hook-level writes; workflow additions; contract command inventory; and gate/withdrawal scenarios. |
| CLI standalone environments in `land_test.go`, `delivery_test.go` (`TestHistoryCommandProcess`), and `agent_test.go` | Already call `personTestEnv`, so inherit the same isolation without per-test marker copies. |
| `internal/question/withdraw_cli_test.go`: `TestPersonWithdrawCLI` | Calls the shared helper before table-specific markers. Includes question creation, prior answers, person withdrawal, and agent/worker/role refusals. |
| `internal/settings/claude_cli_rework_test.go`: `TestClaudeReworkCLIProjectAnchors`, `TestClaudeCLIHomePatternCharacters`, `TestClaudeReworkCLIRemoveForgedRecord` | Already provide closed `Getenv` seams and terminal process fixtures; no inherited values reach the gate. No change needed. |
| `internal/persongate/gate_test.go` | `request` supplies a closed `Getenv`; marker tests supply their own `Getenv` and `Environ`. Ancestry, role, policy and directory tests retain their assertions. |
| `internal/golden/corpus_test.go`, `contract/formats/formats_test.go` | CLI adapters supply fixture-only `Getenv` functions. Replay fixtures retain their own environment and behavior. |
| `internal/mcp/refusal_test.go`, packaging launchers, workflow CLI subprocess tests, other direct CLI environments | Calls are MCP/feed, version/hooks, workflow reads, project metadata, job rendering, usage, agent checks or signal operations; they do not introduce an unisolated person-only command. |
| Store, workflow, feed, task, job, brain-command, orchestrator, guard and hook matches | Use store APIs or explicit identity/environment seams rather than the person CLI dispatcher. Guard and hook assertions remain unchanged. |

`TestPersonEnvironmentRefusals` covers each shared key plus new names in both wildcard families. It first seeds an inherited marker and requires `person check` to succeed after harness setup, then explicitly sets that marker and requires both `task close` and `person check` to refuse with `agent_env` without changing task files. `TestPersonRestoresEnvironment` checks restoration, unrelated environment preservation, and explicit agent setup after isolation.
