# Lane L23 completion

Built `internal/plan` and registered `grid plan hash`, `items`, `write`, and `diff`.
The commands support plain text and JSON, resolve tasks through `internal/where`,
and accept `--task` and `--project`. Usage, formats, storage, and error behavior
are documented in [docs/plan.md](docs/plan.md).

Hash reproduces the old script's normalization. Items exposes stable ids,
titles, states, and the present `write`, `after`, `review`, `risk`, and `verify`
fields. Write enforces recall, increments the installed revision, preserves the
previous bytes, and atomically replaces `plan.md` under an fslock lock. Diff
reports added, removed, and changed items with before/after text and positions.

No Feed or task record shape was introduced. No task records or Feed posts are
written. The protected packages are unchanged; `internal/cli/cli.go` only changes
the existing plan command registration. No dependency was added.

## Validation

Run from the checkout root with the default temporary directory:

```sh
make test
make lint
go test -race ./internal/plan
GOOS=windows go build ./...
GOOS=darwin go build ./...
```

All these commands passed on the Linux development host. Tests use `t.TempDir`
and do not replace TMPDIR. Goldens cover realistic plans, item fields and states,
hash values generated by the old JavaScript function, revision comparisons, and
both CLI output formats. Other tests cover hash stability and meaningful changes,
gate refusals, malformed fields and revisions, archive conflicts, exact history
preservation, task resolution, symlink refusal, symlinked task roots, simultaneous
writers, and readers observing complete files.

`make golden` checks goldens. `UPDATE_GOLDEN=1 make golden` rewrites golden outputs;
the fixed legacy hash oracle in `internal/plan/testdata/hashes.json` is not
rewritten by the Go tests. JavaScript is not needed to run the tests.

## Limits and unavailable material

The reference tree contains no `prototype/plan*.html`; it contains
`prototype/plan-pages.json`. The task-page approval and revision implementations
at the lines above supplied the UI behavior. No prototype files were modified.

Native macOS tests could not run on this Linux host. The Darwin build passed;
tests resolve symlinked roots and use portable Go APIs. Native Windows locking
and no-follow opening remain unsupported by the existing protected fslock
package, so the Windows build passes but storage commands return its explanatory
error. No platform-specific syscall was added.

`grid plan check`, cycle/risk/review validation, approval recording, Feed emission,
HTML rendering, and the prototype's decimal wording revisions are outside this
lane's four-command scope. Revisions here are positive integers, matching the
old hash script. The revision archive and plan replacement are individually
atomic, not a multi-file power-loss transaction; directory entries are not
explicitly synced. A process interrupted after archiving can safely retry.
