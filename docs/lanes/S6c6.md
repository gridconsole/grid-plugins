# S6c6: remove the person-by-path part of question gates

Base: lane-S6aB d67f1824. Lane head: see the last line of this file's bundle report.

## What I found

On this base no code reads the process tree to decide who a poster is: S6b removed it
(`internal/cli/role_policy.go` says so and reads `GRID_ROLE` only). `grep` for `/proc`,
`Getppid`, "ancestry" in non-test Go finds only session identification (`task attach`,
port claims), which does not decide who is a person.

The one piece left that decided "person" without looking at a role was `refuseAnswerPost`
(`internal/cli/feed.go`): it refused every `answer` post on `grid feed post`, `grid job post`
and the MCP `feed_post`, for all roles, so that an agent on those paths could not close a
gate. The person's way in was only the `grid answer` verb. That is a path rule standing in for
the removed ancestry check, so it goes.

## What changed

- `internal/cli/feed.go`: delete `refuseAnswerPost` and its call in `grid feed post`.
- `internal/cli/orchestrator.go`: drop the call in `grid job post`.
- `internal/cli/mcp.go`: drop the call in the MCP session hook.
- Tests (all in `internal/cli`): delete `TestFeedPostRefusesAnswer`, `TestJobPostRefusesAnswer`
  and the `answer post` row of `TestRecordExitFeed`; add `answer_post_roles_test.go` with
  `TestFeedPostAnswerRoleAdmission` and `TestJobPostAnswerRoleAdmission`.

Unchanged on purpose (Q3 as decided): `feed.PersonAnswer` and `FoldReadAt` (role admission:
owner, member, lead; guest only for its own question; agent and cli never), the
`GatePostRoles` check in `internal/feed/store.go`, the eligibility filter in
`internal/orchestrator/events.go`, `internal/workflow/gates.go`, `question.Store.Answer`,
`workflowRoleRefusal` (`person_verbs`). No file under internal/feed, internal/orchestrator,
internal/workflow or internal/question is touched.

After the change an `answer` post is an ordinary post. Whether it closes a gate is decided by
the gate's role admission: `GRID_ROLE` unset or member, owner, lead close it; a guest closes it
only on a question addressed to that guest (otherwise the feed store refuses, exit 3); roles
agent, cli and worker store the post and leave the gate open.
