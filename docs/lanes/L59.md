# L59: grid intent release

Base: `origin/main` at `783685044d763857d6c86cff08496dd98437759d`.
Branch: `lane-L59`.

## Behavior

Added `grid intent release <id> --token <claim token>`. It immediately makes a
live claimed intent pending, permitting another worker to claim it without
waiting five minutes. The original token can no longer renew, complete, or
release the intent. A later claim gets a fresh token.

The command follows renew/done's argument shape: the ID precedes flags,
`--claim` aliases `--token`, and `GRID_INTENT_CLAIM` supplies the default token.
It also accepts the existing `--task`, `--project`, and `--json` flags. The
releasing identity comes from the claim's `who`, not a caller-supplied label.
Success exits 0; wrong, expired, replaced, already released, or completed
claims exit 1 without changing stored record bytes. Missing arguments and
unsupported flags exit 2, matching the existing verbs.

Release holds the same `intents/.lock` as claim, renew, done, and list. Under
that lock it validates the current live token and atomically replaces
`intents/<id>.release.json` using the existing synced JSON writer. The record
contains `token`, `who`, and `created`, with the same UTC millisecond timestamp
format as the other persisted records. This is the latest release receipt;
a later successful release replaces it.

The release receipt invalidates only its matching claim token. Keeping the
old `.claim` file until the next claim makes the state transition and audit
receipt one atomic publication rather than separate audit and deletion writes.
All intent state checks honor the receipt; a later token remains independent.
Readers inspecting `.claim` directly must also honor the matching release
receipt; old CLI versions do not understand the new receipt.

The immutable request is never rewritten. This checkout has no built-in intent
attempt counter, so release does not introduce or reset one. A regression test
seeds `attempt: 7` in the request and verifies its exact bytes survive release,
reclaim, and another release.

MCP exposes Feed tools, not the intent verbs, so no MCP tool was added.
`contract/commands.json` does not exist on this base, so no command registry
was created. `go.mod` and README remain unchanged.

## README entry text

`grid intent release <id> --token <claim token> [--task <task>] [--project <project>] [--json]`
returns a live claim to the pending queue immediately, preserving the request
and its attempt metadata. Only the current unexpired claim token may release;
wrong or expired tokens and completed intents exit 1 without changes. Like
renew and done, release accepts `--claim` as a token alias and defaults to
`GRID_INTENT_CLAIM`. The release receipt records the claim holder and release
time; `--json` prints that receipt. Workers should release after cancellation
or a recoverable handler failure while they still hold a live claim.

## Regression evidence

Before implementation, `go test ./internal/cli -run TestIntentRelease -count=1`
failed on the base implementation with `intent: unknown action release`.
Those regression tests were committed before the implementation.

Coverage includes immediate reclaim by another worker, both token flags and
the environment default, JSON and text output, usage errors, byte-for-byte
non-mutation on refused releases, exact expiry, missing stores, persisted audit
data, attempt metadata preservation, and fencing of the released token from
renew/done. Twenty competing claimers race a release, checking at most one
winner and that the old holder cannot affect it. Release also races done;
exactly one transition succeeds.

The initial full checks uncovered an unrelated baseline failure in
`TestRecordExitWorkerArgv`: it expected `feed post` to accept Job-side writes,
but the existing CLI refuses them. The same failure reproduced in a temporary
archive of `origin/main` with
`go test ./internal/cli -run '^TestRecordExitWorkerArgv$' -count=1`.
A separate test-only commit updates those cases to assert exit 1, the existing
redirect message, and no new Feed records on either attempt. Runtime Feed
behavior is unchanged; Job validation remains covered by `TestRecordExitJob`.
