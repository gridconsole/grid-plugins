# L133: hide other callers' Personal workflows

Branch: `lane-L133`. Plugin main was
`2014b233cc839ed379bdde39fd2063751d0effd0`, which did not contain L126's
shared picker. Applied the requested reset to L126
`bd0ad798e678238109045c1077221fa1f8b5320e` and rebase onto plugin main;
the resulting pre-change base was `d853bf7d43e0fb30bdf59950f76c0a24963c8d0a`.

Extracted the write path's case-insensitive Personal registry check into
`where.Resolver.PersonalProjectAllowed`. Both `projects.Store.List` (used by
workflow write) and workflow show's independent discovery call this helper.
Show filters before opening the project record, so hidden malformed records
cannot add diagnostics or affect the public listing. Guest invitation checks
remain in place.

Identity still comes from `where.CallerFrom` through the CLI resolver:
`GRID_ROLE` and `GRID_MEMBER`, with the existing `PersonalOK` policy and its
`PersonalAllowed` override. The existing default recognizes the machine owner's
role; no new owner field, identity source, or workflow storage location was added.

The shared selection error is now generic for callers denied Personal access,
as it already was for guests. For a member, `--project personal`,
`--project id-personal`, and `--project unknown` all return exit 1, empty stdout,
and exactly this stderr in both plain and JSON modes:

```text
grid: project is missing or ambiguous
```

This also makes write's lookup refusals generic for those callers. Callers
allowed Personal retain L126's selector diagnostic. Owner reads remain available
by name, ID, and unfiltered listing. There is no `workflow show --policy` flag
in this base, so no policy output mode was added.

L126's exact-name-before-unique-ID picker remains unchanged. Show still uses
its per-record reader and reports errors in visible damaged records; write
still uses the strict project store. No output fields, revision handling,
workflow parsing, or existing data sources were removed or substituted.

The brief supplied no explicit touch list. The small changes outside
`internal/workflow` are the extracted helper in `internal/where/personal.go`,
its use in `internal/projects/projects.go`, CLI regression coverage, and this
note. One existing write-policy test now expects the generic refusal; its
policy and unchanged-file assertions remain intact.
