## Pending scope decision

The existing shared helper `internal/atomicfile.Write` accepts an ordinary pathname and performs `os.CreateTemp`, `os.Rename`, and directory sync using that pathname. Its callers include project and settings writers. `Safe` plus an `os.Root` read cannot confine that helper's later path-based write if an ancestor is swapped for a symlink. The only existing root-confined atomic writer is an unexported, separate implementation in `internal/brain/store.go`; it cannot be reused from workflow.

The user was asked to permit updates to `internal/atomicfile/atomicfile.go` and `internal/atomicfile/atomicfile_test.go`, outside the original allowlist. The proposed extension adds `WriteRoot` and shares the write/chmod/fsync/rename sequence with `Write`. It pins the destination directory with `os.Root` and keeps all destination operations relative to that handle. Tests replace the original directory with an outside symlink after opening the root and check that writing still reaches the pinned directory, preserves permissions, leaves the outside directory untouched, and removes temporary files.

Until that permission arrives, those shared files remain unchanged. The implementation is a draft requiring `atomicfile.WriteRoot`; validation uses a Go overlay containing the proposed helper and its tests. This is not a claim that the unmodified checkout passes. The review files and overlay are under `/tmp/l68-review`.

## Behavior and policy

The new writer selects exactly one registered project by name or ID, matching show's selection predicate. No selector writes only the workspace file. It reads at most 32 KiB plus one byte, checks UTF-8 and Rust's first-line heading rule, and lists every `Parse` diagnostic before opening the destination lock. The `.workflows.lock` file stays in place and uses `fslock.LockExclusive`. The revision comparison and save both happen while holding it. Existing bytes are hashed even when oversized or invalid UTF-8, allowing repair with a known revision. New revisions match show's SHA-256 prefix.

`none` represents absence, not an empty existing file. Conflicts return exactly `workflow changed since read` and exit 3 through the write branch, without changing the shared exit-code classifier. Invalid input returns exit 2 because Rust calls it `bad_request` (400), distinct from conflict (409). Unknown/ambiguous projects fail without echoing the selector. Filesystem failures use fixed path-free diagnostics; parser values containing path-like text are redacted. JSON returns `{file, rev}` and plain output is one `<file> <rev>` line, using show's relative labels.

`workflow.WriteDefaultAllowed` is a replaceable policy function used only by the CLI. Its default permits empty `GRID_ROLE`, `owner`, and `member`, and refuses every other role before opening input or creating anything. Applications remain responsible for authorization. The future workflow policy key should be `workflow.write.allowed_roles`; it should replace this default at host initialization, before concurrent calls. This lane does not add policy parsing or change workflow gates.
