The second orchestrator note supersedes the original exit-1 requirement for
invalid person policy. This lane preserves L129's requested behavior: warn on
invalid `person_verbs`, discard the extension, and retain the floor. Project
reader/parse failures do the same. Consequently a broken project policy can
allow a non-floor signal act; it does not preserve the replaceable default.
The invalid-value regression intentionally verifies a warning and successful
turn, rather than the superseded exit-1/no-write behavior. Existing task I/O
and parse errors remain available to command/store diagnostics without adding
a duplicate gate warning. All task reader errors still return errors, never
an accepted policy. A later L129 landing must retain both sides of the gate.

Hook events bypass policy before any workflow read, including malformed
policy. The existing `hook level` settings mutation remains on the floor;
this exception distinguishes the settings command from hook execution.

## Behavior and security boundary

- Leading YAML front matter is accepted before the workflows heading. Existing
  workspace and project fixture outputs are identical with and without the
  added block. Existing unprefixed parse cases retain their diagnostics;
  prefixed diagnostics retain physical source line numbers.
- `ProjectPersonVerbs` reads `projects/<name>/workflows.md` first, then workspace
  `workflows.md` if the project key is unset. A set value replaces inheritance
  wholly. Neither set means `[signal act turn, signal act dismiss, signal act
  snooze]` (default, owner may change); `[]` means no added person verbs.
- List/map validation is shared with task policy, including the same role
  names. Project reads reuse the existing 32 KiB cap, UTF-8 check, and symlink
  refusal, including ancestor components. Errors contain no filesystem paths
  or caller-provided YAML values.
- Task person and plan-token readers now use L116B's `readTaskPolicy`: 1 MiB
  whole-file cap, no following `workflow.md` symlinks. Missing-file behavior
  remains unchanged. Both readers have oversize and symlink regressions.
- Project context uses the existing caller-aware resolver, through cwd or
  `--project`. Task-scoped calls use only task policy. Signal act matching
  recognizes split/equal flags, single-dash forms, last-value semantics, and
  the option fence; it skips other signal option values. Default act is note.
  `signal dismiss` matches `signal act dismiss`; `signal act` covers all acts.
- The gate runs before dispatch and signal validation/guest/state checks.
  A refused gate returns exit 3, the `grid signal act:` person hint on stderr,
  and exactly one `person_required` object on stdout with `--json`. Only calls
  that pass or do not require the gate reach the existing signal guest refusal.
  Existing caller visibility and role rules remain unchanged; this does not
  grant guest roles new person permissions. Refusal tests compare the entire
  Grid data tree to prove no signal/task/settings write occurred.
