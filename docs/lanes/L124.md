## Contract and security boundary

`grid workflow show --json --policy [--project <name-or-id>]` adds only `policy`
to the existing files/templates/errors envelope. Each visible file has one entry
in file order, with the same project name (or null for workspace). Each of four
allowlisted keys carries its value, source, and workflow origin when applicable.
Without `--policy`, JSON and plain output retain their existing bytes. Policy
without JSON exits 2 with usage.

Project values replace workspace values wholly, and workspace values replace
defaults. Empty lists and maps are deliberate refusals. A missing act in a set
`inbox_act_roles` map gets no roles; no default acts are merged into it. Defaults
are `refusal_message: plugin`, all seven inbox acts allowed for owner/member/local/
agent, and owner/member for document writes and task undo. Guest is invalid in
inbox role lists, independently of the existing unconditional guest refusal.

Only `refusal_message`, `inbox_act_roles`, `project_document_write_roles`, and
`task_undo_roles` enter the policy block. Excluded: `task_file_revision_roles`
(its default is a rule, not a role list), `updates_folder` (future),
`gate_post_roles` (gate policy owned by `gates.go`), and `person_verbs` (task/gate
policy with project inheritance owned by L122). Other keys are ignored by this
reader, even when their values would be invalid for another consumer.

Resolution consumes the `File.Text` already read by `readFiles`; it adds neither
a file opener nor a YAML parser. L122's existing `parseFrontmatter` splitter and
YAML dialect are reused unchanged. Existing byte caps, symlink refusal, source
identity checks, guest filtering, templates, and diagnostics remain in place.
Malformed policy fails before encoding any stdout, with one fixed key-and-level
stderr line and no values, paths, or project names. Read failures also fail closed
as invalid front matter, rather than manufacturing permissive defaults from an
unavailable file. Hidden guest projects are filtered before policy evaluation;
requests by hidden name or ID remain byte-identical to unknown project requests.

No A60 person-only verb is added or changed: workflow show is a read. There are
no changes to signal-act enforcement, `person_gate.go`, `person.go`,
`project_person.go`, or `person_verbs` semantics.

## Small supporting changes

The dispatcher in `internal/cli/cli.go` delegates its existing gate call through
a wrapper in `internal/cli/workflow.go`. This is the small change outside the
workflow reader and its CLI entry needed for the exact single-line diagnostic:
L122's pre-dispatch policy reader otherwise emits a warning before malformed
front matter reaches workflow show. The wrapper buffers diagnostics only for
an explicitly enabled policy read, discards successful gate warnings, and
preserves gate decisions, mutations to the command environment, and refusal
stdout/stderr unchanged. A regression test compares gate refusals byte for byte.
It does not bypass person authorization. The generated `contract/commands.json`
adds the flag through `make generate`.
