# L85 — Task folder operands

Base: plugin main `6dff18acff33cd1a1122bbebefc2149c68d6ddee`.
Branch: `lane-L85`.

## Changes

`internal/cli/task_operand.go` supplies one shared resolver for `task show`,
`approve`, `refusal decide`, the new `decide` alias, and `task close`, `stop`,
`reopen`, `status`, `history`, `attach`, `rename` and `decline`.

Display IDs keep the existing home-wide lookup and duplicate-ID rejection.
Folder names must match exactly, including the renamed suffix. Absolute and
current-directory-relative folder paths must name a direct child of an
accessible project's tasks directory. Both lexical and canonical parents are
checked; outside paths, cross-project/outside symlink targets, and any `..`
component exit 2. Resolution uses `resolver(env)`, its caller-filtered
`TasksDirs`, and its `Resolve` policy check; Personal access is not widened.
Writers receive the resolved ID and retain their existing locks, state checks,
approval checks, and agent attachment restrictions.

Show JSON adds `folder` beside `id` and `path`; write JSON adds `folder` beside
the existing `task` display ID. The folder is a basename, including its suffix.
Persisted history receipts, attachment JSON, and history's array shape are
unchanged. Plain output is unchanged. Help, the contract README, command
inventory, three output schemas and their six valid fixtures were updated.

No explicit touch list was supplied. Supporting changes outside the task CLI
files are limited to registering the requested alias in `internal/cli/cli.go`,
updating the parser inventory annotations and generated `contract/commands.json`,
and keeping schemas, fixtures, documentation and goldens consistent.
`make test` also exposed two pre-existing source-audit failures in unchanged
base files: `internal/job/jobcmd/trace.go` directly enumerates all task roots,
and `internal/workflow/write.go` constructs a resolver for registered-project
enumeration. Two exact-file exceptions were added to the existing allowlist in
`internal/where/choke_test.go`. Trace's legacy API has no caller; workflow Write
has a separate CLI role gate. This is an audit annotation only: neither API's
production behavior or caller policy was changed, and the exceptions do not
cover the new CLI resolver. Propagating caller identity through the legacy
Trace API remains separate work. Neither
`go.mod` nor the Makefile was recreated or changed. No Rust checkout was needed.

## Task-operand audit

Audited CLI source for `Task:`, `String("task"`, `StringVar` task flags,
`Show`, `ResolveTask`, and positional task annotations in `contract/commands.json`;
followed delegates into question, jobcmd, braincmd and evalcmd.

| Commands | Disposition and reason |
| --- | --- |
| `task show`, `approve`, `refusal decide`, `decide`, `task close/stop/reopen` | Routed through the new resolver; required app verbs. |
| `task status/history/attach/rename/decline` | Routed through the same resolver because these also consume a positional display ID. Existing attachment and edit policies remain in their stores. |
| `where`; `plan write/check/items/hash/diff`; `person approvers` | Keep caller-aware `where.Resolve`: already accept task folders and have project/context selection contracts rather than home-wide task-record lookup. |
| `task move`; `session start/stop/send/pause/resume/handback/switch`; `intent list/claim/renew/release/done` | Keep `intentScope`/`livenessScope` and their project-aware folder resolution. These create or manage worker intents and must preserve their project and target selection semantics. Includes legacy positional task move syntax. |
| `session list/show`; `lease take/renew/release/status` (task and merge) | Keep caller-aware liveness/Feed scope resolution; some calls intentionally select all project tasks or a project-level merge lease. |
| `feed post/read/state/types/handover/fold/tick`; `job next/post/ack/result/cancel/tree/blocked` | Keep Feed/orchestrator scope resolution, which already accepts folder operands and combines project, task and lease scope. |
| `job render/lint/show/verify` | Keep the jobcmd `ResolveTask` adapter to caller-aware `where.Resolve`; these commands also accept job files and job/item operands. `job cycles/floor` consume graph files, not task operands. |
| `artifact import/link/list/publish`; `usage post/show/budget set/show/clear/threshold set/show/clear`; bare `usage` | Keep `taskFor` or caller-aware `where.Resolve`; folder input already works and bare usage can intentionally have no task scope. |
| `question add/list/sync/tick/withdraw`; `answer` | Keep the question package's caller-aware resolver and its person/worker policy; folder forms already exist, including positional task input to sync and answer. |
| `deliver --task`; `proof add/index --task`; `history add --task`; `land <task>` | Retain their existing task-store ID interfaces in this lane. They are separate delivery, evidence, history-append and deployment contracts, not the requested task menu verbs; changing their result/error contracts is deferred. |
| `brain show/search/keep --task`; `brain decide <task>` | Retain the braincmd task-store ID interface. `brain decide` decides a knowledge proposal, not a refused command; the new top-level alias delegates only to `refusal decide`. |
| `eval run [task]` | Its task operand names an evaluation case, not a Grid task folder. No resolver change. |

The retained command families keep their existing exit and JSON contracts; this
lane does not claim the new strict path/exit-2 contract for those families.

## Validation

The regression matrix covers all seven requested command spellings with IDs,
renamed folder names, absolute paths and relative paths. JSON and plain output
are compared across fresh equivalent task states, normalizing only fixture
roots and timestamps. Every required verb rejects outside paths, symlink
escapes, `..`, and embedded traversal without changing task.md. Additional tests
cover exact suffix matching, cross-project symlinks, owner/member/guest Personal
policy, shared-project resolution, the other routed task verbs, and help goldens.
