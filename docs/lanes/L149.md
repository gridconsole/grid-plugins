# L149: workspace token budget write needs a person

Base: `lane-L148` at `497dfc6b`. Branch: `lane-L149`.

## Defect

`grid usage budget set|clear --workspace` only checked `GRID_ROLE` (default policy: empty
role or owner). An agent process with no role set, under a Claude Code or Codex ancestor,
passed that check and could change the workspace token budget that every task falls back to.
L148 gated the task-level write only.

Also fixes L148 review must-fix 1: on `lane-L148` the Run carve-out skips the early
workflow-policy gate for every `usage budget set|clear`, and the handler gated only the
non-`--workspace` form, so a workflow `person_verbs` extension (`[usage budget set]`,
`[usage]`, `{usage budget set: [owner]}`) no longer refused the `--workspace` form, which base
`5809a1bf` refused. Routing the `--workspace` write through `gateCommand` (floor plus workflow
policy, the same call as the task write) closes it in the same place. A parse or flag error
still exits 2 for an agent too, because the gate runs after the flag diagnostics and the role
check; no refusal was loosened and `TestUsageBudgetGateKeepsSyntaxAndWorkspaceAnswers` needed
no change beyond the person context above.

## What changed

- `internal/cli/usage.go`: a `--workspace` write now runs `gateCommand` (the same call that
  gates the task write, so the refusal is the same: exit 3, `person_required`, the reason
  code, the hint, and a receipt for a person) in `runWorkspaceBudgetGated`.
  - Order, so nothing the existing path answered changes: flag parse and diagnostics (exit 2)
    -> the existing caller role policy (`WorkspaceBudgetWriteAllowed`, exit 3, kept as it was:
    it is the stronger check for roles) -> the person gate -> the store write. The person
    gate is on top of the role check; it does not replace it.
  - `usage budget show --workspace` never runs the gate.
  - `runWorkspaceBudget` keeps its signature and is the ungated seam an existing store-error
    test calls; the command path calls `runWorkspaceBudgetGated` and always passes the gate.
- `internal/cli/cli.go`, `usage.go` comments: the handler gates both write forms.
- `contract/README.md`: the usage budget section says `usage budget set|clear` is a
  person-only write with or without `--workspace`, and that a workspace write that passes the
  role check still needs a person, even with an empty role.
- Help text and `testdata/golden/usage-help.golden` are unchanged (the help never mentioned
  who may write). `contract/commands.json` is generated and `make generate` leaves it
  unchanged.

## Noticed, not changed

- `persongate.Check` refuses every `GRID_ROLE` other than empty, owner, member and cli as
  `agent_env`, so a replaced `WorkspaceBudgetWriteAllowed` policy that admits another role
  (for example `lead`) can never write through the CLI now. The role policy can only narrow
  who may write; it cannot widen past the person gate.
- A person's `--workspace` call that fails the role check exits 3 with the role line and no
  `person_required` JSON, because the role check runs before the gate.
