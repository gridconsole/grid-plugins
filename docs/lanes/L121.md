# L121: doctor checks the setup allow block

Base: plugin main `8c1666aa461febbc2f59fd1c40d8ac2ed0bfc402`.
Branch: `lane-L121`.
Regression commit: `20963f7`.
Implementation commit: `7af60a4`.

## Change

`grid doctor` now includes `allow block` in plain output, JSON `checks`, and the
bundle report. It succeeds only when all of setup's allow rules are present.
Missing rules are listed verbatim, with this fix hint:

> Run grid setup to add the allow block; grid setup --remove takes it out.

`internal/settings/claude_status.go` provides a read-only status helper returning
present and missing rules, or a path-free reason. Missing files, invalid JSON or
structure, symlinked files (including dangling links), unreadable files, and
nonregular files have distinct diagnostics. The helper refuses to follow the
final symlink and checks the opened file's identity. It never creates settings,
rewrites them, or updates setup's ownership record.

Setup and status share one private allow-rule builder and its validated anchor.
Setup's deny and environment entries retain their behavior. A shared path
resolver preserves `CLAUDE_CONFIG_DIR` and otherwise uses `env.Home` with
`.claude/settings.json`; it does not consult XDG. Doctor options inject the user
home and settings path for tests. The allow check runs even if plugin hooks fail.

Bundles explicitly redact the settings path before home substitution, including
custom destinations outside the home directory and Windows separator, case, and
JSON-escaped variants. Existing report fields and checks remain present.

## Supporting changes

- `internal/doctor/bundle.go` carries the settings path into the existing
  redactor; this is needed to redact custom destinations outside the user home.
- Existing doctor fixtures now install or inject a healthy allow block, and five
  doctor golden files include the additional check without dropping older checks.
- `internal/cli/settings_choke_test.go` allows the two new read-only exports by
  exact function and source file. The Store construction restrictions and mutation
  tests remain intact. This small guard update is needed for the new settings API.
- README now has a doctor section. `contract/README.md` lists the complete check
  order and existing failure-only `fix` field; its older list omitted installation
  checks as well as the new allow block.
