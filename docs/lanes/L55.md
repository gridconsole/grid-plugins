# L55: Unique gate ids and deterministic legacy readiness

Implemented on `lane-L55`, based on `main` at
`60ce72dab9d39878a713a93f8a0c11ac65d1c057`.

## Behavior

- `feed.Store.Post` reserves question gate ids across the whole task Feed.
  A task-wide file lock covers the cross-writer uniqueness check and append,
  including concurrent writers with different tenure files. The check reads
  existing questions, including held records and expanded spilled bodies.
- Both `grid feed post --type question` and `grid job post --type question`
  return exit 1 for a reused gate id and append no record. MCP `feed_post`
  returns a tool error and appends no record through the same store check.
- An unchanged retry with the original record id retains existing idempotency.
  A new record claiming an existing gate id is refused even when its body is
  identical. Distinct gate ids, unnamed questions, and other tasks remain valid.
- Old Feeds resolve duplicates by kind: person takes precedence over timer,
  which takes precedence over other kinds. All questions tied at the strictest
  kind must open. Readiness uses their latest timestamp, making both eligibility
  and ready ordering independent of map iteration.
- The serialized orchestrator tick posts one warning per duplicate gate id,
  linked to `question:Q-N`. The counted task-lease warning in the Feed prevents
  repeats, including after local orchestrator metadata is deleted. `Ready`
  remains a pure predicate for CLI readers and worker spawn sizing.

## Regression evidence

The tests were first run against the unchanged starting implementation, then
all final regression test files were copied into a temporary archive of the
`main` revision above and rerun:

```sh
go test ./internal/feed ./internal/orchestrator ./internal/cli ./internal/mcp \
  -run 'TestGateReuse|TestGateConcurrentWriters|TestLegacyDuplicate' -count=1
```

All four packages failed on main as expected:

- Both CLI commands, running as an agent with an acknowledged Job lease,
  accepted a timer with a past deadline under an existing person gate id,
  returned exit 0, and appended a record. MCP accepted the same attack.
- The concurrent writer test admitted all 16 questions claiming one gate id.
- Legacy duplicate tests opened unanswered person gates, allowed weaker closed
  gates to block stricter open gates, and changed ready ordering with map order.

The lane tests also check same-kind content changes, original record-id retries,
same-writer and different-writer attempts, held and spilled questions, task
scoping, person/timer/CI ties, job gates, repeated ticks, warning persistence,
and readiness timestamps. Legacy fixtures change unique gate ids on disk to
simulate old Feeds without bypassing the new API in production.

## Validation

All passed:

```sh
make test
go test -race -count=1 ./internal/feed ./internal/orchestrator ./internal/cli ./internal/mcp
go test ./internal/orchestrator -run '^TestLegacyDuplicate' -count=30
make lint
GOOS=windows go build ./...
GOOS=darwin go build ./...
```

`make test` ran the uncached full suite and reported no new temporary-file
leaks. Each legacy readiness test repeats the predicate 100 times per case;
the repeated run passed all 30 executions. Cross-platform validation was build
validation, not execution of the tests on those operating systems.
