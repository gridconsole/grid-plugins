# L57: agent readiness checks

Implemented `agent.Check(ctx, Env)` and `grid agent check [--json]`. The current
`lane-L57B` branch includes the three commits from `origin/lane-L57` (`1a0b7d0`),
rebased onto `origin/main` (`92ad117`). The original brief was read from the
reference briefs directory because this checkout contained only the L57B brief.

The JSON answer follows the supplied `app/client.mjs:449` contract:

```text
{ agents: [{ agent: 'claude' | 'codex', found, path?, version?, min, signedIn?, fix? }] }
```

Reports are ordered Claude Code then Codex, even though the agents are probed
concurrently. `found`, `agent`, and `min` always appear; optional fields are
omitted when unknown. A known negative sign-in is `signedIn: false`, and an
unknown sign-in is absent. No `ready` field is added: an absent `fix` means ready.
Plain output contains one line per agent with the same facts. Unready agents
exit 0, invalid flags or operands exit 2, and output failures exit 1.

Only the agent command-table registration in `internal/cli/cli.go` changed.
The new dispatcher delegates existing `agent set` and `agent list` calls to the
existing settings handler; settings files, doctor, and contract files were not
changed. No credential file is read and no agent turn is started.

## Deliberate differences and boundaries

- Rust's final lookup step invokes a login shell with `command -v`
  (`host/spawn.rs:683-712`). The brief explicitly requires the supplied launch
  PATH and forbids shells. After the same standard install folders, this port
  searches that PATH in directory order using qualified `exec.LookPath` calls.
  It never changes the process PATH. Empty PATH disables only this fallback;
  standard install folders are still checked. Relative PATH matches are refused
  with `exec.ErrDot`. No shell configuration is evaluated.
- Windows executable extensions use the process PATHEXT as required by the
  brief; Rust's resolver tests exact names. The Unix system install folders
  are skipped when they are not absolute on Windows. Lookup may find `.cmd` or
  `.bat` launchers; `Check` explicitly refuses those extensions, ignoring case,
  before calling any runner. They remain found with no version or sign-in status
  and an install fix. Windows can otherwise run batch files through `cmd.exe`,
  so relying on direct process startup to reject them was incorrect. Windows
  runtime tests were not executed here; cross-build validation is recorded below.
- Rust serializes absent report options as null; the app contract permits
  optional fields, so Go omits them. Rust's update fix is just the update
  command; the required minimum is in `min` and the plain `min=` field rather
  than appended to the fix string. This preserves the Rust fix text.
- Sign-in parsing expects the agent's JSON object response. Go's JSON map
  decoder keeps the last duplicate `authMethod` key, whereas Rust's derived
  struct decoder rejects a duplicate known field; Go also rejects array-form
  status values. Normal object responses use the same case-sensitive key,
  string/null checks, and exact `none` comparison.
- The runner retains the groundwork's 100 ms `Cmd.WaitDelay` for an inherited
  stdout pipe held open after the direct child exits. Rust waits for the
  remaining deadline, with a 200 ms minimum (`setup/agents.rs:381-390`). Go
  closes its copy pipe and reports a failed probe on drain timeout; Rust
  returns a completed exit with empty output. Both bound waiting and reap the
  direct child; neither promises to terminate descendant process trees.
- The CLI cancels probes on interrupt or termination signals and waits for
  cleanup. Go enforces caller cancellation as well as WAIT, including ignoring a late
  successful fake-runner answer. A signal-terminated child counts as an
  unsuccessful exit; context cancellation still makes the probe unknown.
  Rust uses ten-millisecond polling and has no caller context. Go does not
  recover a panic in an injected Runner, unlike Rust's thread-join fallback.
- `Env.Home` supplies the child HOME (and USERPROFILE on Windows), rather than
  forwarding possibly inconsistent values from the base environment. If home
  is empty, home-local lookup is skipped and the child inherits the working
  directory; Rust onboarding instead requires a usable home. `Env.Base` and
  `Env.Lookup` allow isolated tests; production defaults to the process
  environment and standard resolver. Rust's test-only home-bin switch is not
  part of the plugin environment.
- This is a CLI query with no onboarding report cache, account selection, or
  desktop command registration. It retains the CLI's existing Grid-home format
  guard. The rebased main has no named success/usage/failure integer constants:
  `internal/cli/exitcode.go` contains the help constant and error classifier.
  The command reuses `parse`, `writeJSON`, and `exitCode` for their existing
  statuses, and returns the existing success value 0 for plain output.

## Validation

Fake-runner tests cover both found agents, missing agents without spawning,
minimum equality and old versions, malformed/prefixed/multiline versions,
successful and unsuccessful sign-in, unknown status, start failures, parent
cancellation, concurrent probes, and fresh five-second per-probe deadlines.
Resolver tests cover standard-directory/PATH precedence, empty PATH, executable
permissions, process-PATH isolation, and Windows PATHEXT. Cask symlink tests
exercise the update fix. CLI tests assert exact JSON, optional fields, plain
output, registration, help, bad flags/operands, and success for unready agents.

The real helper-process timeout test remains: it verifies startup, timeout,
non-success, and completed reaping, with a cleanup kill/wait fallback. Additional
real helper runs verify child working directory, environment, and bounded stdout
retention while draining a larger answer. Existing settings tests verify the
preserved agent settings commands.

All required checks passed on the final implementation:

```sh
make test
go test -race -count=1 ./internal/agent/... ./internal/cli/...
make lint
GOOS=windows go build ./...
GOOS=darwin go build ./...
```

`make test` used the default TMPDIR and reported no new matching temporary
entries. Race tests passed for both packages. Cross-builds validate compilation,
not native Windows or macOS execution. There is no root `DONE.md`.

## L57C: refuse batch launchers and verify null stdin

Reset `lane-L57C` to `origin/lane-L57B` and rebased onto `origin/main` without
conflicts. Changes are confined to `internal/agent/` and this report.

The pure `isBatchLauncher` predicate rejects `.cmd` and `.bat` extensions
case-insensitively on every OS. `Check` preserves the found path, leaves version
and sign-in unknown, and reports the existing platform-specific install fix
before either the version or status runner can be called. Native executables
and extensionless candidates retain the existing behavior.

`TestAgentCheckBatchLaunchers` supplies fake `claude.CMD` and `codex.bat`
candidates, plus lower-, upper-, and mixed-case variants, and asserts the report
and zero runner calls. In a temporary archive of `origin/lane-L57B` with the new
tests copied in, it failed with four runner calls per case; it passes here.
Pure predicate tests also cover native executables, an extensionless name, a
`.cmd.exe` suffix, and a directory whose name ends in `.cmd`.

`TestRunnerNullStdin` substitutes a nonempty file for the parent's `os.Stdin`
and runs a real helper process that copies its stdin to stdout. The unmodified
runner returns immediate EOF with no output. The test passes on L57B and here;
in the temporary L57B archive, injecting the M6 mutation `cmd.Stdin = os.Stdin`
makes it fail because the helper reads the parent's marker. No production stdin
change was needed.
