## Implemented groundwork

- `internal/agent.Env` supplies launch PATH, home, and an injectable Runner.
  Runner receives a context and argv and returns stdout and exit status.
- The default runner uses `exec.CommandContext` without a shell. Standard input
  and standard error use the null device; stdout uses a pipe, so no standard
  stream inherits a terminal. Launch environment variables are preserved except
  PATH, HOME, and USERPROFILE, which come from Env.
- A context deadline kills the direct child; `Run` waits and reaps it before
  returning. Pipe draining has a further 100 ms maximum if a descendant retains
  stdout. Tests use a two-second deadline; this is not a chosen production WAIT.
  The eventual Check implementation must supply the Rust WAIT for each probe.
- Resolution searches the supplied PATH in directory order using qualified
  candidates and `exec.LookPath`, without changing global PATH. Windows extension
  selection uses the process PATHEXT. Empty PATH searches nothing, and relative
  PATH matches are refused with `exec.ErrDot`. Other Rust candidate locations,
  if any, must be added after the source is available.
- The resolver can identify Windows `.cmd` launchers; execution uses the direct
  process API and never invokes a command shell. Whether launcher-specific
  handling is needed remains to be assessed against the missing Rust reference.

The real helper-process timeout test verifies startup, deadline expiry,
non-success status, and completed reaping, with a cleanup fallback that kills
and waits. Resolver tests cover precedence, isolation from process PATH, empty
PATH, executable permissions, and Windows PATHEXT behavior. Windows tests are
written but were not executed on Windows; cross-compilation passed.
