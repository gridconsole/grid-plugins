# Lane L20: task artifacts

Only the artifact half of the lane is merged. The usage half (`grid usage`, usage limit notices, `internal/usage`) is not merged: it waits for the Feed rework and a contract decision for a usage post type. The `usage` entry in `internal/cli/cli.go` stays a stub.

Built `internal/artifact` and its CLI adapter `internal/cli/artifact.go`, with table-driven tests on temporary homes and JSON golden files. The only edit to `internal/cli/cli.go` is the artifact table registration; `internal/where`, `internal/project`, `go.mod` and the Makefile are unchanged.

## Commands

```sh
grid artifact import report.pdf --title "Example report" --json
grid artifact link https://example.com/report --title "Published report"
grid artifact list --task T-01 --json
grid artifact publish <artifact-id>
```

Artifact commands resolve their task through `where`; inside a task folder, `--task` is optional. Outside it, pass a task path or an ID resolvable in the current project. Publish also accepts `--task` and `--json`; link also accepts `--json`. Flags may precede or follow operands. Use `--` before an operand that starts with a dash.

Imports copy regular-file bytes without changing the source. Each import creates `artifacts/A-<32 hex digits>-<basename>` plus `artifacts/A-<32 hex digits>.json`. Sidecars contain `id`, `title`, `source`, `kind`, `sha256`, `created`, `file` for imports, and `published`. Titles default to the original basename for imports and the URL for links. Link records have no payload file and an empty SHA-256 field; no URL is fetched. HTTPS URLs with credentials are refused. Publication is an idempotent local Boolean update, without uploading or changing task status. Lists include managed sidecars only, sorted by ID. Duplicate imports remain separate records. Symlink artifact directories and sidecars are refused.

## Import boundary (set when merged)

- The source is opened with `O_NONBLOCK|O_NOFOLLOW` (through `internal/fslock`) and checked with fstat on the opened handle, so a file swapped for a pipe or device cannot block, and a symlink source is refused. Other platforms open it plainly and still check the handle.
- An import above 200 MiB (`artifact.DefaultMaxImportBytes`) is refused with the limit in the error. The copy also runs through a bounded reader, so a file that grows during the copy stops at the limit and its partial copy is removed.
- A sidecar's `file` must be one plain name: no `/` or `\`, no NUL, not `.` or `..`, not absolute, no volume. `List` and `publish` refuse a sidecar that breaks this. An import whose base name would break it is refused.
- The sidecar's `source` never holds an absolute path. A file inside the project's folder (the `folder` from `grid where`) is recorded by its slash-separated path below it, for example `docs/report.txt`. Any other file is recorded as `<base name>#<16 hex>`, the first 8 bytes of the SHA-256 of its absolute path, so two files with one base name stay apart.

## Validation

```sh
make test
make lint
go test -race ./internal/artifact ./internal/cli
GOOS=windows go build ./...
```

Tests cover binary and empty imports, duplicate filenames, source preservation, hashing, repeated publication, HTTPS validation, path traversal and symlinks, missing tasks, pipe, device and symlink source refusal, the size limit, unsafe sidecar file names, and the recorded source inside and outside the project folder.
