# Lane L29: remaining session hooks

Runtime events compose handlers for activity, history, usage, brain pointers,
stop checks and permission forwarding. `hook.Handles` recognizes each runtime
subscription and each migration component. `cli.Implemented("hook")` gates the
corpus adapter. Component invocations isolate the old script's effects; runtime
invocations exercise the same functions alongside the existing guards.

## Storage and behavior

Heartbeat hooks call `lease.HookActivity` and `session.Touch` for an existing
supervised session. They never invent a pid, machine id, fence or Running state.
The existing supervisor API, `session.Reconcile`, writes `feed/.live` after a
successful pid/start-time check. Stop ends a turn, not a session. SessionEnd
ends a known process record and removes its live file. This follows the design
in feed-contract.md sections 7 and 8: hooks never renew; heartbeat is not a type.

Hook evidence lives in `sessions/.hooks/<session_id>.json` under its resolved
task, or the Grid home when no task is attached. The existing session lock and
atomic JSON writer serialize updates. No-op retries keep the old timestamp.
Usage is numeric tool observations keyed by tool-use id; retries replace rather
than add. `grid usage [--task T-NN] [--json]` folds those records. No prices are
guessed and no usage or heartbeat Feed post is emitted. This command reports
its selected scope, not an aggregate across all tasks or account-limit holds.

History uses `task.AppendHistory`, an exclusive fslock on the existing regular
history.md file, consecutive deduplication and cleaned fields. Task discovery
uses `gridhome.TasksDirs` through `task.FolderAt`, including Personal tasks.
Bash snapshots hash bounded file contents in the current task and are keyed by
session and tool-use id. Success and failure consume the same snapshot. The
scan excludes history, sessions, Feed files, hidden entries and symlinks; it is
limited to 2,000 files and 32 MiB. Background commands are not snapshotted.

Brain reads use `brain.Store.Show` to recognize accepted notes at the current
project or home level. Recall uses `brain.Store.Search`: at most five pointers
with their summary and a description explaining when to read them. Bodies are
never injected. Recall deduplicates by task, agent and plan content hash; any
plan edit can recall again. Planner dispatch remembers a validated task for
SubagentStart. Read deduplication is per task, session and note pointer.

Stop checks preserve legacy summary/next and completed-brief requirements;
reviewers need Verdict, other writers need Outcome, and scouts are exempt.
An unambiguous transcript identifies a legacy brief to mark done or blocked.
The task package owns the atomic transition under a stable status lock.
`stop_hook_active` allows the second stop; only a positive guard finding returns
2. Internal errors are logged on stderr and allow the turn with exit zero.
New tasks use title and intent rather than requiring legacy summary/next keys.

PermissionRequest evaluates local guards before forwarding unanswered requests
to an explicit GRID_URL at hooks/permission. HTTPS or loopback HTTP is required,
redirects are refused, responses are bounded to 64 KiB, and the timeout is at
most eight seconds (a smaller GRID_PERMISSION_TIMEOUT_MS is honored). The
server may allow or deny; changed tool input is checked again before allowing.
No answer, invalid data, timeout or transport failure falls back to the terminal.
The Personal task tree is now included in the existing only-writer guard.

## Intended differences in the corpus

D1. SessionStart records session evidence and injects the bounded brain index.
The old agent-routing/grid-env scripts did neither. Evidence uses mode 0600
and session locks; the existing context/export differences remain.

D2. Heartbeat emits no legacy Feed heartbeat. Missing explicit tasks now produce
a diagnostic while returning zero. Only supervision owns the live-file clock.

D3. History no longer writes plugin-data task/agent/brief pointer lists. File
history and duplicate suppression remain. Bash snapshots use content hashes in
session records instead of legacy size/mtime/ctime files and deletion markers.
Reading or writing history.md does not itself create attachment pointers.

D4. Untyped loose knowledge/demo.md files are not accepted brain notes and are
not logged as brain reads. Accepted notes use portable brain ids and session
markers instead of plugin-data .brain-read lists. The new note schema is owned
by internal/brain; hooks do not synthesize accepted metadata for old files.

D5. Recall has a shorter pointer-oriented message, a pointer-count history line
and locked JSON markers instead of .recalled/.planner text files. It hashes plan
content rather than reading only the numeric revision. JSON map keys are sorted.

D6. Stop guard messages use concise task-relative names and direct the caller
through grid. Status marking leaves a stable mode-0600 .status.lock and uses
the task atomic writer's mode-0600 replacement instead of a mode-0644 temp file.

D7. Usage records only numeric counters and transcript references in session
JSON; it omits old response-key lists, result text, model/status words and brief
metadata. SessionStart and SubagentStop observations replace .usage JSONL files.

D8. Worker exits act only for a Grid Worker session: GRID_FEED_TASK, GRID_JOB and
GRID_WORKER set, and no result or worker-exit for the Job's attempt in the Feed.
Evidence is durable and deduplicated per agent, Job, lease epoch and attempt.
Claude Code's own SessionEnd reasons (prompt_input_exit, other, any unlisted
reason) are a normal end (done, record Finished); clear and logout are cancelled
(StoppedByYou). Only an explicit Grid reason of crash or loop ends the record
Errored. usage_limit keeps its reason. Missing tasks log and allow.

D9. Pure helper semantics reuse taskfile, guard and task functions. Frontmatter
objects serialize in sorted Go map-key order rather than JavaScript insertion
order. All helper values, including string-valued scalars, retain parity.

D10. The 20 inherited guard differences remain those documented in L4: read-only
evaluators omit dispatch pointers, diagnostics name the Go commands, the
only-writer deny takes priority, home allows are counted, and script allowances
require the plugin root. L29 retains their existing explanations in the manifest.

## Limits and dependencies

Main now has a fenced Feed writer (feed.Store.Post). The worker-exit handler does
not use it yet: it records session evidence only and reads the Feed to see whether
the Job already has a result. Posting worker-exit, and a loop-detected post when
the verify cap lets a failing stop through, is left for a follow-up (it needs the
Worker's lease epoch and attempt environment). `grid usage post`, the usage log
and the threshold usage-notice are also left for a later lane; usage stays off the
Feed and lives in the session activity records. A session-end hook is not process
supervision and does not infer a missing result.

Automatic desktop bridge discovery is not carried over. Explicit GRID_URL works;
without it, the runtime's permission prompt remains the authority. Bridge tokens,
process probes and machine binding belong to setup/server integration.

Legacy cross-task shell inference, attachment pointer lists, overlapping Bash
snapshot settlement, dispatch-fallback brief inference, carry-on nudges and
silent-wait/reviewer-launch orchestration are not reproduced. Hooks use explicit
scope, cwd, typed file paths or an unambiguous transcript. New immutable rendered
Jobs are not marked by editing brief.md; their status belongs to the Feed fold.
Proposal batching and curator scheduling are also outside these event handlers.

The 19 remaining corpus skips are needs-you (3), session-attach (3), session-check
(3), session-record (4) and terminal-task (6). They have no component adapter in
this lane; existing runtime session activity is tested directly. No lib helper
or requested script remains skipped. The original recordings are unchanged.

## Validation

Run make test, make lint and make golden with the default TMPDIR. Also run
GOOS=windows go build ./... and GOOS=darwin go build ./... . The corpus target is
136 cases: 62 pass, 55 known differences, zero failures and 19 skips. The 35 new
known differences each cite D1 through D9 above; inherited entries cite D10 too.

Tests cover numeric usage retry folding and text exclusion, locked history
appends, successful pointer recall and per-note deduplication, changed-plan
recall, stop retry/marking, activity without lease renewal, session end cleanup,
Bash failure history, storage errors, Personal task guards, server decisions,
modified-input guard rechecks, timeout, invalid response and redirect fallback.
Cross-compilation does not claim native Windows or macOS test execution.

## Additional design behavior

D11. With GRID_JOB set, Stop reads the immutable saved jobs/<id>/job.yaml and
runs its verify command through the existing eval process runner. It requires
both exit zero and verify.min_tests observed passes. Supported counts are Go
JSON/verbose, TAP, pytest/Jest summaries and unittest summaries; unknown output
does not prove any tests ran. Output is bounded by the eval runner and the
reported excerpt is at most 2,000 characters. The command has 45 seconds.
Actual process-start/storage errors log and allow; a timeout is a failed check.
The hook blocks at most eight times per session/Job/attempt/command (two with
GRID_RUNTIME=codex), even with stop_hook_active. At the cap it retains failure
evidence in the session record and allows; publishing that failed result needs
the same missing fenced Feed writer as worker-exit. SubagentStop does not run a
parent session's GRID_JOB command against a nested agent's partial work.

D12. SessionStart now includes brain.Index's bounded topic table and still caps
its complete context below 10,000 characters. Planner and builder starts can
recall; emitted pointer lines stay within a 2,400-byte budget with an elision
notice. PreCompact prints the summary-retention reminder rather than injecting
new context. Current Job rendering and open Feed decisions on compact still
need the worker/Feed integration; the topic index is refreshed immediately.
