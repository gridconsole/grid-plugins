# Lane L9: grid migrate

L9 moves today's `~/.grid/<name>/` data into the single versioned Grid home
(migration.md section 10, go-architecture.md "migrate"). `grid migrate` previews
(the default, `--dry-run`) or applies (`--apply`) and takes `--from <old folder>`.
It runs offline: stop the old writers first.

## What it does

- Scan reads metadata only (lstat, no file is held in memory) and plans: copies,
  `identify` rewrites of project.md and task.md, a `machine` file, `VERSION` and
  `migration.log`. Conflicts and unmapped items block apply.
- project.md is written through `internal/project` (`folders`, `repos`, `keys`),
  so `grid where` works on the migrated home. Keys are `remote:` for each remote,
  `root:` only for a repo with no remote, and `common:` with the machine. The old
  body is kept byte for byte; `folder:`, `repo:` and `key:` lines are dropped.
  The machine id is read from `<home>/machine` (or the source); when there is none
  it is made once at apply and written into the `machine` file and every record.
  The plan shows a placeholder for it.
- Ids are deterministic ULIDs with a zero timestamp (`legacyID`), so repeated plans
  are identical and a dry run writes nothing.
- Symlinks are recorded and copied as links, never followed; absolute ones are
  counted in a note. Files are streamed through sha256 while they are copied.
- Session pointers are compared after resolving symlinks (macOS `/var`).

## Crash safety (recover.go)

Beside the home: `<home>.migrate-lock` (pid and start time; a dead or reused pid
is stale), `<home>.migrate-journal` (written before each phase), a staged copy,
`<home>.migrate-previous-ID` and `<home>-backup/DATE-ID` (verified by re-reading,
manifest written last, never removed). Publication is two renames with a journal
written before the first. A rerun reads the journal and the folders that exist and
discards, finishes, puts the old home back or cleans up; a state it cannot explain
is an error that changes nothing. A dry run reports an interrupted run and writes
nothing. Between the two renames there is no home path; the journal covers it.

## Tests

`make test`; `go test -race ./internal/migrate/...` (the crash tests re-run the test
binary and exit after each step: locked, journal-preparing, backed-up, staged,
journal-publishing, displaced, published, previous-removed, done, and inside
recovery). `internal/cli/migrate_test.go` migrates a fixture and then runs
`grid where` on it.

## Not done (should-fix from the review)

- Unknown entries in a real home (.DS_Store, config.json, bin/, ...) block apply.
- `machine` as a directory (old Rust app) is a conflict, not converted.
- Live git worktrees block instead of being moved with `git worktree move`.
- Knowledge from two named homes merges into one folder; differing files conflict.
- Session JSON is re-encoded (key order); CRLF in task.md becomes LF.
- Session pointers and usage under CLAUDE_PLUGIN_DATA are not migrated.
- `--rollback` and re-importing tasks exported after cutover.
- Windows: builds (`GOOS=windows go build ./...`), not run.
