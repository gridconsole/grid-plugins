# L131: stable CLI failure codes

Base: plugin main `cab22985261819efdcde153ac5ac1d806ac57115`.
Branch: `lane-L131`.

The command table's `Run` dispatcher previously printed most errors only to
stderr. `commandError` used its supplied command prefix; `failure` used `grid:`.
Signal act/dismiss/move already emitted flat error objects on stdout, and person
refusals emitted `error`, `reason`, and `hint` there. Those channels, prefixes,
messages, exit statuses, and existing fields are preserved.

Five documented constants now identify missing projects, tasks, and signal/notes,
person refusals, and invalid arguments. Existing JSON error objects gain `code`;
failures without JSON use a nested `error` object containing `code` and `message`.
Person refusals also gain the stderr message while retaining the current reason.
The public reference is [CLI JSON failures](../../contract/README.md#cli-json-failures).

Lookup errors carry typed identities through the current data sources. Signal
move no longer needs an English-text match to recognize an unregistered project.
Other signal state refusals retain their previous categories without being
classified as missing records. The dispatcher forwards stdout and stderr as they
are written and supplies a new envelope only when a classified failure has not
already produced stdout. Only the small person gate/probe objects are buffered
for their additive fields.

Scope beyond CLI code: minimal changes in `internal/where`, `internal/task`, and
`internal/signal` preserve error identity independently of human wording. Existing
tests that required empty stdout on JSON failures now check the new envelope and
retain their stderr, exit, access-control, and unchanged-storage assertions.
No data source, successful output field, or lookup policy was replaced. The L122
files named in the brief were not edited; a CLI adapter extends person output.
The module and Makefile are unchanged.

## Validation

The new real-command regression table was run on the base before implementation:
all 12 cases failed because their codes were missing. It was committed separately
as `32e9c6a`. Each case uses a temporary Grid home, compares JSON and plain stderr
byte-for-byte, and checks the original exit status. Additional tests cover changed
error wording, wrapped identities, and JSON flag values versus operands.

All required checks passed:

- `make test` (including the temporary-file leak check).
- `go test -race -count=1 ./internal/cli ./internal/signal ./internal/task ./internal/where`.
- `make lint`.
- `make generate`, with no generated-file changes.
- `GOOS=windows go build ./...`.
- `GOOS=darwin go build ./...`.

No golden or contract fixture needed regeneration: successful output is unchanged,
and existing failure expectations were inline tests. The generated command
inventory is unchanged. The final diff also leaves all four L122 exclusions
untouched and introduces no private paths or host identifiers.
