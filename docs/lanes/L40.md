# Lane L40: terminal task attach

Built the terminal resume meaning of `grid task attach T-NN`. File and note attachment are excluded by the lane's scope correction. The command uses the existing task resolver, session store, machine identity, process identity and task history writer.

## Commands

```sh
grid task attach T-01
grid task attach --session terminal-example T-01 --runtime claude
grid task attach T-01 --json
```

Flags may precede or follow the task ID; `--` protects subsequent operands. Exit status is 0 on success, 1 on refusal, and 2 on invalid usage. Unknown tasks name the supplied ID. Closed tasks name `grid task reopen T-NN`.

Successful attachment reports the task ID, title, state, current plan approval and open question count, then `Attached. T-NN <title>`. JSON carries those facts plus the session and machine IDs and a `holders` list (empty when nobody holds the task). Holder advice text goes to stderr with `--json`, keeping stdout valid JSON.

The session is recorded under `<task>/sessions/<machine>/<session>.json`, with `where: terminal`, Claude runtime, caller working directory and the parent process's PID and start identity. Resuming the same key preserves its original start time and transcript. Session state starts as `Liveness unknown`; only the existing supervision API can supply evidence of Running.

A different Running session with a Job lease, or one Running on another machine, produces holder advice naming `grid lease take-over`. A Job session whose liveness is unknown also produces conservative advice: unknown does not prove its tenure is free. Ended, sleeping and stale records do not produce advice. Attachment still succeeds. No lease is taken, released, renewed or broken, and existing heartbeats remain untouched. Reusing a Job session's key is refused with a request for a different `--session`, including when that Job has ended.

Every successful invocation appends one `attach` history receipt. The existing task lock serializes attachment with other task writes. Task and plan bytes remain untouched, including task.md's inode. The task journal now accepts history-only transactions. Session.Start also refuses converting a Job session to a non-Job session under its existing lock, so a concurrent Job start cannot cause attach to delete its heartbeat.

Agent callers identified by `GRID_AGENT`, `GRID_WORKER_ID`, `GRID_WORKER`, or a role other than owner/member/cli must target their `GRID_TASK` assignment, or the enclosing task when no assignment is supplied. This is the repository's cooperative environment boundary, not authentication. Existing guard rules are unchanged; tests explicitly cover direct writes to inputs and attachments.

## Defaults (owner may change)

- Closed tasks refuse attach and name `grid task reopen`.
- Session ID precedence is nonempty `--session`, `GRID_SESSION_ID`, `CLAUDE_SESSION_ID`, then a generated ULID using the existing Feed ID generator.
- Runtime defaults to `claude`; other runtimes are usage errors, matching the current session store's support.
- No file, note, filename or size defaults are selected: those operations are out of scope.

## Limits

File/note attachment and lease take-over were intentionally not built. The command records/resumes the terminal association; it does not launch Claude, send a resume prompt, or change session hooks. See `docs/old-plugin-map.md:61` for the old launcher responsibilities.

Session publication and task history use separate existing stores: a crash or storage failure after the session write but before the history journal commit can leave a session without that invocation's receipt. Once the history journal commits, existing recovery is idempotent. Successful concurrent invocations each have exactly one receipt.

The small `internal/migrate.ProcessStart` export reuses the existing platform-specific process identity implementation; there is no second process probe, locking or atomic-write implementation. The additional session change is the locked Job-key refusal described above, not a hook change. No dependencies were added.

## Review follow-ups

- Process identity still lives in `internal/migrate` and the CLI imports it. If more callers appear, move it to a neutral package such as `internal/proc`.
- The session record and the history receipt are not one atomic write (see Limits above); this is a known limit.

## Implementation notes and limits

[Lane documentation](docs/lanes/L40.md) explains the command, defaults and coverage. Supporting changes allow history-only journals, refuse Job-to-terminal conversion under the existing session lock, and expose the existing platform process identity helper through `internal/migrate.ProcessStart`. No new lock, atomic writer, machine ID helper, front-matter helper or dependency was introduced.

Session publication and history are separate existing-store writes. A crash or storage failure between session publication and history commit can leave a session without that invocation's receipt; committed history journals recover idempotently. No macOS/Windows runtime was available for execution. Everything in the corrected terminal-attach scope is implemented; file/note attachment and lease take-over are intentionally excluded.
