## Scope blockers

The user was asked whether to allow the minimal contract and workflow changes plus directly affected tests and goldens. No answer has been received at the time of this note.

- `contract/schemas/control.json` requires `lease: "task"` and a positive fence for every control. Owner and member are already admitted author roles, so changing the roles in `internal/contract` cannot enable leaseless publication. A narrow schema alternative for person withdrawal is required. Guest controls are also rejected by the schema before the question fold; testing a counted forged guest control requires accounting for that boundary.
- The final instruction requires reading `question_withdraw_roles` from the workflow, superseding the earlier instruction not to read a workflow file. However, `internal/workflow/parse.go` rejects unknown keys and has no field for this policy. That directory is explicitly excluded from edits. The existing `workflow.Read` API cannot return the requested policy without extending the parser. Workflow selection and inheritance must also be specified and tested when adding that support.

No schema, workflow, Feed fold, or help changes have been made. Successful leaseless publication, event ordering, workflow integration, and the remaining acceptance rows are not implemented. The lane is not ready to merge.

## Completed changes and decisions

- Regression coverage invokes the real CLI from outside any project with an absolute task folder inside Grid home. It checks owner/member success, custom/default reason, Feed envelope and needs-you state, and idempotent JSON output. Those success checks remain red until publication and folding are implemented.
- `question.Store.WithdrawAllowed func(role string) bool` and the command environment hook allow a host or workflow to replace the default. Nil allows only owner/member. An owner-only callback refuses member in a unit test; this is not yet a workflow-file integration test.
- Leaseless role checks precede agent-shell checks, giving guest a stable role-refusal diagnostic. The CLI reuses `agentShell` from task writing. A permissive callback cannot authorize an agent/CLI author. Existing task-lease withdrawal bypasses the person policy and retains its publication path.
- Malformed withdrawal IDs are usage errors. Existing answered/defaulted state refusals are classified as refusals; already-withdrawn questions retain the existing no-op path after caller checks.
- The existing command default reason remains `No longer needed`.
- No changes were made to the prohibited task, signal, lease, guard, where, workflow, intent, or exit-code files. No root `DONE.md` was created.
