## Policy and ordering choices

The final workflow instruction supersedes the original instruction not to read workflow files. A host can supply `question.Store.WithdrawAllowed func(role string) bool`; nil loads workflow policy, then defaults to owner/member. `feed.FoldReadAt` accepts the same optional callback. No global mutable policy or cache is used.

`question_withdraw_roles` is a comma-separated list of distinct person roles: owner, member, guest or lead. Empty lists, duplicate roles and unknown/non-person roles are parser errors. Missing keys/files use owner/member; guest and every other role are refused by default. The optional parsed JSON field is omitted when absent, preserving existing workflow goldens.

For standard Grid task folders, workspace `workflows.md` and the task project's `workflows.md` are read; Personal uses the workspace file. Task front matter's explicit workflow name wins. Otherwise the first matching template rule wins, falling back to the workspace default. Title rules use case-insensitive substring matching; goal/project rules use case-insensitive equality; labels use exact membership. Project sections replace same-named workspace sections case-insensitively; project copies inherit matching rules. Omission of the roles key in the selected section restores the standard default rather than inheriting a different role list. Standalone Store task folders without the Grid layout use the default. Malformed policy files and unknown explicit selections in loaded workflows return operational errors (1), not a silent permissive fallback.

Policy checks precede agent-shell checks, yielding a stable role-refusal message for default-refused roles. A permissive callback cannot authorize agent/CLI authors. Hosts can admit guest/lead person records; the CLI still uses the requested existing `agentShell` test, which classifies guest/lead environments as agent shells even when role policy permits them. All three shell markers (`GRID_AGENT`, `GRID_WORKER_ID`, `GRID_WORKER`) are tested. An authorized task lease bypasses the person role policy, as before.

Person events follow Feed order; task controls retain `(gen, fence, worker, seq)` tenure order. Explicit `after` dependencies are honored, preserving default audit history before a late answer even when display order ties. Cyclic pending events do not close gates. Existing distinct-answer conflict handling and explicit answer selection remain; an answer may still override a default. A person withdrawal after an applied answer/default is ignored, and an event at/after the deadline cannot bypass the default merely because no default audit control exists. A withdrawn gate stays closed to later answers. Contract verdicts are not rewritten by the person fold.

The default reason remains `No longer needed`; an explicit reason is stored verbatim. Already-withdrawn retries succeed and print the record without a Feed append after caller authorization. Invalid IDs are usage errors; unknown well-formed IDs remain operational failures. Tests resolve an absolute task folder inside Grid home while cwd is outside every project.
