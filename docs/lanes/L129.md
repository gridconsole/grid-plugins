# L129: invalid person policy cannot disable hook decisions

Base: plugin main `f68cf6e32690cf446563758abbedd1b7c042e876`.
Branch: `lane-L129`.

`gateCommand` now bypasses hook commands before resolving or reading task
policy, except commands in `persongate.Floor()`: currently `hook level`.
Neither invalid `person_verbs` nor a valid policy listing hook verbs can prevent
the event handler from returning its normal decision.

For other commands, `ErrPersonVerbs` emits exactly this warning and then uses
the existing error fallback (`policy = nil`), preserving the floor:

```text
grid: warning: invalid person_verbs; ignoring the key and keeping the person-only floor
```

The warning contains neither a path nor the invalid value. `task show T-01`
continues with exit 0. An agent's `approve T-01` still refuses with exit 3 and
`person_required` / `agent_env`, as do all other floor verbs. The invalid key
cannot change task or settings files through these refused commands.

The host guard's explicit file list now includes task `workflow.md`, covering
Write, Edit, MultiEdit and NotebookEdit, including Personal tasks, case variants
and resolved symlink aliases. Existing Bash protection remains active when the
plan guard is off; it covers redirection, append, tee and other literal writes.
Reads and unrelated file names remain allowed by this guard.

Base inspection clarified two assumptions in the brief. The composed hook's
only-writer guard and generated Claude deny rules already protect every file in
task folders; the missing explicit file entry was in the host guard. Also,
`workflow.PersonVerbs` reads only the task snapshot. Project `workflows.md` is
not a separate source of this key, so no data source was added or substituted.
The generated rules need no change. The protected-file documentation in
`contract/README.md` and runtime denial text now name the workflow snapshot.
The brief supplied no explicit touch list; the documentation update is the
small accompanying change needed to keep the documented rules accurate.

## Regression evidence

Added CLI regressions exercise `person_verbs: 5`, invalid boolean/list/map/role
values, command continuation, every floor verb, and unchanged files after
refusals. Hook comparisons check normal handler output for PreToolUse,
PermissionRequest, SessionStart, Stop, PostToolUse, unknown events and levels
with both invalid policy and valid policy explicitly listing hook verbs.

The probe supplies a Bash `grid approve T-01` payload to `grid hook PreToolUse`
in the affected task. It requires exit 0, a `hookSpecificOutput` object with
`hookEventName: PreToolUse` and `permissionDecision: deny`, and no gate
diagnostic. Write and Edit payloads targeting that task's `workflow.md` require
the same decision. Direct host-guard tests isolate its protection from the
composed only-writer guard, with reads and near misses as negative controls.
