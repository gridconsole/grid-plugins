## What changed

- `internal/eval/process_windows.go`, `internal/routine/process_windows.go` (new, `//go:build windows`): `configureProcess` adds `CREATE_NEW_PROCESS_GROUP` to the command's creation flags and sets `cmd.Cancel` to end the tree with `taskkill /T /F /PID` (OS binary by absolute path, 5 s timeout, `Process.Kill()` fallback, `os.ErrProcessDone` mapped as on Unix); `cleanupProcess` ends the tree of a command that is still running.
- `internal/eval/process_taskkill.go`, `internal/routine/process_taskkill.go` (new, no build tag): `windowsTaskkillPath` and `taskkillArgs`, so the path and arguments are tested on any host. Same function as `land/process.go:18`; land cannot share it without being changed.
- `internal/eval/process_other.go`, `internal/routine/process_other.go`: tag is `!linux && !darwin && !windows`.
- Tests: `process_taskkill_test.go` in both packages (run on Linux); `process_windows_test.go` in both (Windows only, compiled here).

## Open items

- A child that exits on its own while its background children keep running is not cleaned up on Windows. Unix kills the group after `Run`; taskkill /T cannot find descendants of a dead pid, and the pid may be reused, so `cleanupProcess` skips an exited child. Covering it needs a job object (`KILL_ON_JOB_CLOSE`) assigned right after `Start`, which needs a hook between `Start` and `Wait` in `eval/process.go` and `routine/execute.go`; that is a caller change on all systems and outside this brief. The timeout and stop paths the brief names are covered.
- `windowsTaskkillPath` and `taskkillArgs` now exist in land, eval and routine. A shared home would remove the copies; each package change here stays inside its own brief.
