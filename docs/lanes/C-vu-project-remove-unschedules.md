## What changed

- `internal/routine/schedule.go`: `Scheduler.UnscheduleProject(ctx, project) ([]string, error)` holds the loop of Unschedule's name-less branch, takes `.routine-timers.lock`, and returns the routine names it took down, sorted, as a non-nil empty list when none. `Unschedule(ctx, project, "")` calls it. The inner `remove` became `removeTimer`, which also says whether it found the timer's record (a manifest the scheduler cannot match is a no-op and is not counted as taken down); `remove` wraps it. New exported `TimerError{Name, Err}` carries the failing routine's name so the CLI can name it; its text is the cause's text, and `Unschedule` returns the cause, not the wrapper.
- `internal/cli/projects.go`: after `s.Remove` succeeds, `projectRemoved` builds the scheduler like `routine.go` does (native backend, `ExecOSRunner`, `env.executable()`), calls `UnscheduleProject` with the removed entry's name, and answers with the entry plus `"unscheduled": [...]` (JSON, `[]` when none) or one `unscheduled: <name>` line per timer. On failure it still writes that answer (naming what came down), then stderr `grid: project alpha is removed, but its timers on this machine are not all taken down: routine daily: <cause>` and exit 1; the project stays removed. On native Windows (`routine.NativePreviewOnly()`) nothing is called, because Grid only previews timers there and none exists to take down.
- `internal/cli/cli.go`: the unexported test seam `Env.timerOS func() (routine.Backend, routine.OSRunner)` and the `routine` import. The brief puts the seam "on Env", and `Env` is declared in cli.go, so this file is touched for that field only (like `afterApprove`).
- `contract/schemas/cmd-project-remove.json`: `unscheduled` (array of strings) added and required; description rewritten without the stale `projects.go:172` / `projects.go:398` line numbers.
- `contract/fixtures/cmd-project-remove/valid/basic.json`, `populated.json`: `"unscheduled": []` by hand. The invalid fixtures are unchanged and still invalid.
- `testdata/golden/project-remove-json.golden`: `,"unscheduled":[]` (the only golden touched).
- New tests: `internal/routine/vu_unschedule_project_test.go` (`vuUns...`, reuses `urBackend`, `urRunner` helpers `urExists`, `urWrite`, `urWantErr`, `urWantCalls`, `urWantSyntax`), `internal/cli/vu_project_remove_unschedules_test.go` (`vuRm...`, reuses `ynSpNew` for the isolated harness).
