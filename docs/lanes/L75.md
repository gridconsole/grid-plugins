# L75: withdrawal policy follow-ups

Based on L71R `7df36c48363235d65c855aa4870d3b53d8991a52`, rebased onto plugin main `1c70a9c4f57d21b7b129aa33246b10ba506a5f58`. Implementation: `cc60434`. Regression tests were committed first as `2ab20fb`.

## Behavior

Task `workflow.md` read errors now fail closed with exit 1 before withdrawal writes. The shared reader distinguishes filesystem errors from malformed policy and returns a typed operational error; MCP returns `isError: true` with numeric `code: 1` without terminating the server. The diagnostic is one line: `cannot read task withdrawal policy (workflow.md): <cause>`. It omits the task path and normalizes whitespace in the cause. Read errors never emit a fallback warning.

Missing files still use owner/member without warning. Malformed policy still uses owner/member. Question withdrawal resolves its role callback once per operation and reuses it for authorization and projections, so the fallback warning prints once, including on idempotent retries. Each new operation reads policy again; there is no global cache. Append preflight checks are silent because appending does not apply person role defaults; projection owns that warning.

Question, Feed, Job, MCP and direct host publication check unreadable policy before writing. Checks also cover task lease holders and precede agent-shell refusals at command boundaries. Feed repeats the check at the append boundary, and orchestrator writes check before creating their lock. Host role callbacks still control person authorization, but cannot bypass unreadable policy on withdrawal.

The contract now explicitly limits the no-task-lease posting refusal to agent shells and explains why `withdraw: [guest]` and `[lead]` only affect host-written person records. This is separate from the policy read error, which applies to every withdrawal path.

## Scope

The smallest necessary supporting changes are in CLI Feed/Job dispatch, the question command adapter and MCP dispatch to check policy before writer/session setup; Feed append and orchestrator Write to protect direct callers; and Feed State/orchestrator Load to propagate the shared reader's new error result before reading caches. The existing Feed unreadable-policy test now expects an error instead of fallback. These changes preserve consistent publication, projection and readiness behavior. No explicit file touch list was supplied beyond the requested contract and lane documentation.

The existing module and Makefile were retained. No root DONE file, private paths, host names or attribution lines were added. Existing untracked briefing and execution log files were left out of commits.

Coverage includes chmod 000 and directory-read errors across person question withdrawal, leased question withdrawal, Feed, Job, MCP and direct host Feed publication.
