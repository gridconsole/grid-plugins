## Policy and behavior

The routine entry is the brain workflow policy source. Explicit front matter
values win; omitted keys use the single default table in
`internal/routine/limits.go`.

| Key | Policy | Range |
| --- | --- | --- |
| `routine_timeout` | `10m` default, owner may change | Go duration, 1m through 2h |
| `routine_max_turns` | `10` default, owner may change | Integer, 1 through 100 |
| `routine_budget` | `1` default, owner may change | Decimal number, greater than 0 through 50 USD |

YAML nodes retain scalar types and distinguish omission from explicit null.
Quoted numbers, nulls, booleans, collections, unknown duration units and values
outside the range are refused. Decimal cap validation also checks the exact
value, so floating-point rounding cannot admit a value just above 50.
Only supplied overrides are persisted; defaults do not become fixed settings.
The existing strict front matter parser remains in use.

`routine add` accepts `--routine-timeout`, `--routine-max-turns`, and
`--routine-budget`. These set the corresponding front matter keys. Invalid
values return exit 2 with `grid: invalid <key>` and do not write a routine.
At run time, validation happens under the existing entry lock before execution,
interval skipping or updating `last_run`. Invalid policy returns exit 2 without
executing a command, changing the stored file or recording a failure signal.
Refusal messages contain the key, never the supplied value or a file path.

`ProcessExecutor` has timeout, turn and budget fields; zero fields resolve from
the entry's validated policy. Skill argv uses the resolved turn and budget
values. Grid argv uses only the timeout and receives no agent flags. Existing
process-group cleanup, environment filtering, interval guard, schedule
fingerprint, owner check and failure reporting remain intact.

`list --json`, `run --json` (including skipped and failed runs), and `add --json`
retain the existing entry fields and add this effective default object:

```json
{"limits":{"routine_timeout":"10m","routine_max_turns":10,"routine_budget":1}}
```

The command inventory was regenerated with `make generate`; the parser inventory
already discovers the new literal flag registrations, so its source needed no
change. The README had no routine section, so a short section was added. New
limit tests live beside the existing routine and CLI tests. These are the
smallest supporting additions to the named implementation files. Existing data
sources, endpoint fields, the module definition and unrelated command behavior
are preserved.
