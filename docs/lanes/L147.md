## Scout answer: how the hook names a task

All line numbers are on `03a9e574`.

`taskDir(o, in)` (`internal/hook/events.go:146`) reads, in this order:

1. `o.Resolver.GridHome`. Empty means no Grid home: it returns `""` and no error.
2. The environment, through `o.Getenv`: `GRID_TASK`, else `GRID_FEED_TASK`. When one is
   set it calls `Resolver.Resolve(where.Query{Cwd: in.Cwd, Task: <value>})`
   (`internal/where/where.go:83`, `explicitTask` `:205`) and then `task.FolderAt` on the
   resolved task path.
   - A value with a path separator (or starting with `.`) must be inside the Grid home and
     names the task folder wherever the session's cwd is.
   - A bare id or folder name (`T-01`, `T-01-demo`) is looked up in the project the cwd
     resolves to (`where.go:234-246`): a cwd in a project folder with a record, or inside a
     task folder. A cwd in no project with a record returns an error (not `""`):
     "task ... needs --project".
   - A stale value (task not found) is also an error.
3. The cwd. With neither variable set, `task.FolderAt(o.Resolver, in.Cwd)`
   (`internal/task/history.go:20`) returns the task folder only when the cwd is
   `<tasks dir>/T-N[-slug]` or inside it, and that folder has a regular `task.md`.
   Otherwise `""`.

It does not read the brief. `activityStore` (`events.go:163-171`) falls back to the Grid
home when `taskDir` returns `""`; the hold does nothing in that case instead.

`taskDir` returns `""` for: no Grid home; a plain session whose cwd is not in a task folder
and with neither variable set; and an agent working on a task from a code worktree when the
hook's environment carries no `GRID_TASK` / `GRID_FEED_TASK`.

The CLI builds `usage.Store{TaskPath: res.TaskPath, GridHome: env.GridHome, ...}`
(`internal/cli/usage.go:122-126` for post/show, `:242` for threshold and budget), with
`res` from `taskFor` (`internal/cli/artifact.go:48`). The hook builds the same two fields
from `taskDir`'s folder and `o.Resolver.GridHome`; `Writer` and `WorkflowWarning` are not
needed to read.

Main limit of this lane: an agent working on a task from a code worktree is held only when
its hook environment names the task (`GRID_TASK` or `GRID_FEED_TASK`, which a worker sets).
A session in a code worktree with neither variable is not held. `taskDir` is not widened.
Pinned by `TestHoldDoesNotReachACodeFolderWithoutATaskInTheEnvironment`.

## What changed

- `internal/usage/hold.go` (new): `Store.Hold() (HoldDecision, error)`. It reads the
  effective configuration (`Config`, including the workspace `tokens_per_task` default) and
  the same fold as `grid usage show`. A task with no budget returns before the log is read.
  Dollars and minutes compare in whole micro-units, tokens as integers, so a decimal amount
  that equals the limit holds. Spent counts the whole task total (not since the budget was
  set, unlike notices): a budget set below the current spend holds at once, and
  `grid usage budget set` or `clear` lifts it.
- `internal/usage/usage.go`: one field on `Store`, `HoldPolicy HoldPolicy` (nil = default).
- `internal/hook/hook.go`: `usageHold`, called once in `toolUse` after `evaluateGuards`
  when the event is PreToolUse and the decision is not deny, before `history` and `recall`
  (a refused agent start leaves neither record). A guard deny is never reached by the hold.
  Errors from `taskDir` or `Hold` are logged as `grid hook: usage hold: ...` and allow.
- Tests: `internal/usage/hold_test.go`, `internal/hook/hold_hook_test.go`.

Named keys (in `hold.go`, behind `HoldSettings` and `DefaultHoldSettings`):
`usage_hold_at_percent` = 100, `usage_hold_tools` = `["Agent", "Task"]`. They are code
defaults; no workflow file sets them yet.

### Where the brief and the code disagreed (resolved as follows)

- `usage.Summary` has no budget, so `HoldPolicy func(Summary)` could not judge a budget.
  The seam is `type HoldPolicy func(HoldSummary) (hold bool, reason string)`, where
  `HoldSummary` embeds `Summary` (spent) and adds `Budget` per unit.
- The brief names both `DefaultHoldPolicy = HoldPolicy{AtPercent, Tools}` and a func type
  `HoldPolicy`. The keys are `HoldSettings` / `DefaultHoldSettings`; `DefaultHoldPolicy` is
  the func built from them.
- Tools are checked in the hook through `usage.HoldsTool(tool)` over `DefaultHoldSettings`.
  A replaced `HoldPolicy` does not change the tool list.
