# L92R: Require explicit job command member context on main

Base plugin main: `e10b749f7baa5425df7ffa026b463b0908e23ad5`.
Branch: `lane-L92R`, rebased from `origin/lane-L92` onto that base.
Implementation: `56ea1d552dfcddf810f1ae82efdb3cc6499e1553`.

Main already has `Env.Resolver where.Resolver` and
`Trace(resolver where.Resolver, ...)`. Both remain value-based. The shared
`memberContext` check rejects `strings.TrimSpace(resolver.Caller.Role) == ""`
in `Run` before dispatch and in `Trace` before enumeration. Commands return
exit 2 with `missing member context`; direct `Trace` callers receive an error
and empty rows. Plain and JSON errors retain their existing formats, including
trace's problems array. Refused commands cannot render bundles or launch
verification.

The same implementation commit carries `internal/cli/job.go` role stamping
and passes the resulting resolver value to jobcmd and task resolution. A local
session with neither role nor member becomes `owner`; a member without a role
becomes `member`; explicit roles are preserved. `TestJobOwnerContext` covers
both unset and explicit owner roles. Fixtures and direct Trace tests use value
resolvers, including zero, path-only, whitespace-role, and member-without-role
contexts. Existing caller policy and saved-bundle behavior are preserved.

## Rebase resolution and scope

Kept main's complete `internal/where/choke_test.go` unchanged. At the recorded
base, its allowlist already excludes `internal/workflow/files.go`,
`internal/workflow/write.go`, and `internal/job/jobcmd/trace.go`; none is
reintroduced. The lane's broader resolver-prefix and write exceptions were
discarded, avoiding duplicate keys and stale needles. Main's caller-aware Trace
and workflow data sources remain intact.

The necessary adjacent fixture changes are in
`internal/job/jobcmd/command_test.go`, which supplies explicit owner values,
and `internal/cli/job_test.go`, which protects owner access with GRID_ROLE
unset. No workflow production changes or additional exceptions are needed.
