# L92: Require explicit job command member context

Base plugin main: `aeb572c59170c4b5095880879bcc0f308d932522`.
Branch: `lane-L92`.
Implementation: `f7dc971197ee1812830834050d8ab3486a15ca10`.

On this base, the package is `internal/job/jobcmd`, and `Env` has no
`Resolver` field. The fix therefore adds `Resolver *where.Resolver` and
requires a nonblank `Caller.Role` before any command dispatch. Nil, empty,
path-only, whitespace-role, and member-without-role contexts return exit 2
with `missing member context` and instructions to supply an explicit owner
role when appropriate. Plain and JSON errors preserve their command output
formats, including trace's problems array. Refused commands cannot read job
files, render bundles, or launch verification.

The audit of `Env{`, `Resolver`, and `jobcmd.Run` across `cmd/` and
`internal/` found one production adapter: `internal/cli/job.go`. It passes
the shared resolver explicitly, mapping a local session with neither role
nor member to `owner`, and a member without a host role to `member`.
Existing host roles are preserved. All direct jobcmd test fixtures now
supply explicit owner context; CLI tests cover both local and explicit
owner rendering.

## Regression evidence

Commit `1e051ce4f8be0c302bb561c8cdb116bcfcd3dbc8` adds only the regression
test to the base. Running
`go test -count=1 ./internal/job/jobcmd -run '^TestMissingMemberContext$'`
against that production code failed: the context-free render returned 0
instead of 2 and published a job bundle. The lane refuses it before any
artifacts are created. Additional tests cover all five commands in plain
and JSON modes, explicit owner success, and caller-aware trace enumeration.

## Choke point and adjacent changes

`internal/workflow/files.go` no longer constructs a resolver, so its stale
allowlist entry is removed. The base choke-point test also failed on two
other call sites; these needed small adjacent changes to meet the passing
test requirement:

- Trace used `gridhome.TasksDirs` directly. `Trace` now accepts explicit
  resolver context and calls `Resolver.TasksDirs`; its three direct test
  callers were updated. Tests verify that owners retain Personal results
  and named members and guests see only the non-Personal project results.
- `internal/workflow/write.go` still constructs a resolver for registered
  project lookup after its CLI adapter checks `WriteDefaultAllowed`.
  The exception now names that actual file and explains the existing
  boundary. No workflow production code or write policy was changed.
