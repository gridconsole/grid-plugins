## What changed

- `internal/workflow/tasksteps.go`: `TaskWorkflow` returns the template a task's
  steps come from (nil for an inline list) with the steps; the template comes back
  even when the steps do not resolve for the task's size. `TaskSteps` keeps its
  signature and wraps it.
- `internal/task/hold.go`: `DefinitionDigest` is the sha256 over the template's
  full step list (per step: lowercase name, kind, plan gate of the full list,
  sizes), in order, whatever the task's size. `StepsFor` compares it as soon as
  the template is found, before the steps resolve, whenever `workflow_digest` is
  present. An inline list is not compared (decision (b), below).
  One form only (plain hex, no `v2:`): nothing with the L155T form shipped, and a
  value of the old form now reads as a change, which holds.
- `internal/task/create.go`: `grid task new` stamps the definition digest for
  every size, `auto` included, whenever a template is found. An inline list, or
  no template to find at creation (a name no `workflows.md` holds, an unreadable
  `workflows.md`, an empty `workflow` when the rules need a choice or there is no
  default), leaves the field out: those tasks keep the folder-name check, as today.
- `internal/cli/deliver.go`: a refused `grid deliver` records its error, so
  `--json` prints `{"error":{"code":"workflow_changed","message":"Deliver blocked: ..."}}`
  on stdout; stderr and exit 1 are unchanged. No `plan_not_approved` code exists
  in the contract or `error_codes.go`, so none was added; a plain plan refusal
  keeps no envelope.
- `contract/README.md` (code row, digest paragraph, the inline and person-edit
  lines) and `docs/delivery.md` name `grid deliver` and describe the definition
  digest.
- `internal/cli/deliver_workflow_changed_test.go` (new): the review's size-auto
  S1/S2 through the CLI root (`grid task new`, `grid hook pretooluse`,
  `grid deliver --json`), size large S1/S2, renamed back and rebuilt identical,
  a size-auto task sized later by a person, and the inline rewrite row below.

## Decision (b): an inline list is not compared

When `task.md`'s `workflow:` is an inline list, `StepsFor` skips the digest
compare: the steps live in `task.md`, which agents cannot write, so nothing
outside the task can drift. Named and default templates keep the compare.
`TestNamedWorkflowMatchesInline` (internal/guard/plan_stage_steps_test.go) is
unchanged and passes. `contract/README.md` says a person who rewrites the
`workflow:` line as an inline list acts outside the digest.

New row `TestInlineRewriteOfStampedTaskNotHeld`: a size-large task stamped from
Large, at build, whose `workflow: Large` line a person rewrote as the same steps
inline, is not held (the hook allows the write, `grid deliver --json` exits 0).
It documents behaviour base shares, so it is not a fails-on-base row.
