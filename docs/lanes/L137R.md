# L137R: the brain audit log past 1 MiB

Base: `lane-L137` (`fa6f93e1`) rebased on plugin main `caab16bd`.
Branch: `lane-L137R`. Only `internal/brain` changed.

## Why

`logAudit` and `Changes` read `knowledge/log.md` whole with `safefile.Read`, which
refuses files over 1 MiB. Routine runs save their config twice per run, so the log
reaches that size in days; after that `EditConfig`, `Accept` and `Changes` fail,
the first two after they have already published.

## What changed

- `changes.go`, `logAudit` (under the level lock): `NoSymlinks` and an `Lstat`
  regular-file check as before, then `OpenFile` with `O_RDWR|O_APPEND|O_CREATE`
  through the level's `os.Root`, and a second regular-file check on the open file.
  It reads only the last `logTail` (64 KiB) bytes to find an identical retry line,
  then appends the line in one write and fsyncs. A new or empty log gets the
  `# Brain log` header first and its directory is synced. A last line without
  its newline (an interrupted append) is ended before the new line. The file is
  no longer replaced through a temp file.
- `changes.go`, `Changes`: `openLog` (same checks as `safefile.Read`, no size cap)
  and a `bufio.Scanner` with a 1 MiB line limit (`maxLogLine`). A line over that
  limit makes `Changes` return an error; no valid audit line is near it.
- `logappend_test.go` (new; no existing test edited):
  - `TestLargeLogStillTakesConfigEditsAndAccepts`: a log of just over 1 MiB, then
    `EditConfig` and `Accept` succeed, each new line is present exactly once, the old
    bytes are untouched, a repeated `Accept` and an unchanged `EditConfig` add nothing,
    `Changes` returns every line newest first, and `limit` works.
  - `TestLogAuditRetryOnlyLooksAtTheTail`: three identical `logAudit` calls give one
    line; a line buried deeper than 64 KiB is appended again (the bound is real).
  - `TestLogAuditEndsAnInterruptedLine`: a truncated last line does not swallow the
    next one.
  - `TestLogRefusesSymlinksAndNonRegularFiles`: a symlinked or directory `log.md` is
    refused by `logAudit` and `Changes`, and the symlink target is not created.

## Fails on base

addition was a scratch file defining `logTail`, so the test compiles:

## Known limits and NOT VERIFIED

- A retry is recognised only if its line is within the last 64 KiB (about 500
  lines). A retry after more writes than that appends a second identical line.
- `TestConcurrentWritersKeepVersionsGapFree` fails often on macOS (about 18 of 30 runs
  at `-count=30`) with `openat .brain.lock: no such file or directory`. It does so on
  `lane-L137` unchanged, in the lock open, before any log code; it passes on Linux at
  `-race -count=20`. Not touched here.
- Nothing ran on Windows or macOS beyond the cross-builds; `os.Root` maps `O_APPEND`
  to `FILE_APPEND_DATA` on Windows (read in the Go source), not exercised.

## Follow-ups (not built here)
