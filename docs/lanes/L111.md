## Implementation and replaceable defaults

`signal.Apply` validates input, checks caller policy, and holds `.signals.lock`
across reading the current note, checking its state, creating a task when
needed, and atomically publishing the updated note. The nested task allocation
lock is acquired by the existing `task.Store.New` path. The default `Act` wrapper
now keeps the note; the dismiss alias shares the same state machine.

Each applied action rewrites updated and clears until, except snooze which
replaces until with a local minute. Wake preserves became; reopen clears it.
Note on kept and dismiss on dismissed return unchanged without rewriting the
note. Legacy acted is read as done, including deduplication reads, without
silently migrating the file. Optional fields do not change old encoding when
absent. Typed errors feed a mapper local to the signal CLI: bad input is 2,
refused is 3, and ordinary failures remain 1.

Turn uses exactly the note title, a blank line, and
`Signal: projects/<p>/notes/<id>.md` as task words. The body stays external data
in the note. Task creation uses the resolved note project and the same caller
identity precedence as task new, including GRID_ACTOR fallback. The note is
written only after New succeeds. Encoding is preflighted with room for any
allocatable task id, so oversized output is rejected before task creation.
There is no transaction spanning the task and note files: a crash or note-write
I/O error after task publication can leave an unlinked task. New failure leaves
the original note byte-identical.

These defaults remain replaceable policy seams; this lane reads no workflow
file for them:

| Workflow key | Default |
| --- | --- |
| `inbox_act_roles` | Existing owner, member, local and agent roles; guest/external/unknown callers refused through Caller.IsGuest |
| `inbox_acts` | turn, add, note, snooze, dismiss, wake, reopen |
| `inbox_turn_body` | link; copy is a future alternative, not implemented here |

`signal act` is not in the person-gate floor because its default roles (brief
Goal 8) admit agent and local roles, like `task new`; a task's workflow can add it
through `person_verbs` once L105 lands, which gates only calls that resolve to
that task.

## A68 argv and exits

A68 invokes the following argument arrays, in this order, with no shell:

```text
["signal", "act", "<id>", "--project", "<p>", "--act", "turn", "--json"]
["signal", "act", "<id>", "--project", "<p>", "--act", "add", "--task", "T-<n>", "--json"]
["signal", "act", "<id>", "--project", "<p>", "--act", "note", "--json"]
["signal", "act", "<id>", "--project", "<p>", "--act", "snooze", "--until", "<time>", "--json"]
["signal", "act", "<id>", "--project", "<p>", "--act", "dismiss", "--json"]
["signal", "act", "<id>", "--project", "<p>", "--act", "wake", "--json"]
["signal", "act", "<id>", "--project", "<p>", "--act", "reopen", "--json"]
```

The executable is grid. A68 does not send --later. The CLI rejects every
--later occurrence, including --later=false. Without --act the CLI uses note.

| CLI exit | CLI result | A68 handling after invocation |
| --- | --- | --- |
| 0 | updated or unchanged; Result JSON with optional became/until | Reread the scoped row, HTTP 200 with state applied |
| 1 | I/O, lock, task creation, unregistered project | HTTP 502, read_or_plugin_failed |
| 2 | Unknown/empty act, invalid id, missing/invalid task or until, misplaced options, later | HTTP 400, invalid_arguments |
| 3 | Note state refusal or guest caller | HTTP 409, refused, first stderr line as message |

A68 has its own access and input checks before invoking grid. Plugin refusal
lines are exactly:

```text
grid: no such note
grid: this note is not snoozed
grid: this note is not decided
grid: this note is already decided (<status>)
grid: guests cannot act on signals
```

The status in the fourth line is normalized, so legacy acted reports done.
All four state messages and exact exits are covered by the CLI matrix or
missing-note case. Guests are refused before project/note reading, including
when the note path is unreadable as a file.

## L111R — JSON refusal reasons

The preceding validation describes the original L111 implementation. This
rework starts from reviewed L111 `a43f62f35ed87093779fa068f90d17b8edcd77ee`,
rebased onto plugin main `0ebca7c36c2932a61ca41fd3aed6eff58646d5af` on
`lane-L111R`. `make generate` after the rebase produced no diff.

With `--json`, input errors (exit 2) now write exactly one stdout object line
with `error: invalid`, and refusals (exit 3) use `error: refused`; both carry
`message`. They never use `person_required`. Stderr diagnostics and exit codes
are preserved. Unknown act values containing path separators are omitted from
the JSON message so caller-supplied absolute paths cannot leak into it. Flag
parsing errors use `invalid signal arguments`, including when parsing stops
before `--json`; wrong argument counts use `wrong number of arguments`.
Without JSON, stdout stays empty on errors. Successful result fields and
signal behavior are unchanged.

Only `internal/cli/signal.go`, `internal/cli/signal_act_test.go`, the Signal
acts section of `contract/README.md`, and this lane note change in L111R.
There are no new touch-list exceptions.
