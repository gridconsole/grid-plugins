# L97R: pin stop grace on Up health timeout

Base: plugin main `b739de0141c7e880b960283b60732e0c8924f2a8`.

This lane covers dev-process stop grace, not lease grace. `Manager.grace()`
uses a positive `Grace` unchanged; zero or negative becomes 2s. The stop ladder
applies that grace after SIGINT and again after SIGTERM before escalating to
SIGKILL. Up's health-timeout path must pass `m.grace()` to `ports.StopRecord`
at `internal/env/env.go:81`.

`TestUpHealthTimeoutHonorsStopGrace` starts a helper that ignores SIGINT and
SIGTERM and never listens on the health URL. It waits for the helper's readiness
marker before calling Up on the existing reservation, keeping process startup
out of the timed interval. Timeout and Grace are each 100ms. The test requires
`context.DeadlineExceeded`, subtracts the health timeout from the elapsed Up
call, asserts a lower bound of `2*Grace` for shutdown, and uses `assertEmpty` to
verify reservation removal. There is no upper timing bound.

The helper-signal test is excluded on Windows by the existing
`//go:build linux || darwin` constraint on `internal/env/env_test.go`; the Unix
signal behavior does not apply there.
