## Behavior and compatibility

- `grid usage post --tokens N` records a non-negative integer delta, independently
  of dollars/minutes, and `usage show` includes tokens per Job and for the task.
  Jobs, sessions and agents contribute to the same task total. `Input.Tokens` and
  the optional record field distinguish omission from explicit zero. Record
  version stays **1**; old records without tokens contribute zero. Explicit null,
  negative, fractional, string-valued and out-of-range record tokens fail closed.
- Counts, budgets and baselines cover the full unsigned 64-bit range. CLI token
  amounts accept ASCII digits only, including leading zeros; negative, fractional,
  exponent, signed, nonnumeric and overflowing arguments exit **2** before any
  writes. Zero usage is valid; zero budget is a semantic error (exit **1**, no
  writes), matching existing positive-budget behavior. Sum overflow fails before
  appending. Token crossing arithmetic uses exact decimal percentage ratios,
  rather than converting counts to floating point.
- `budget set --tokens N`, `budget clear --tokens`, and token threshold set/clear
  use the existing task configuration and lock. Percentages remain finite numbers
  in [0,100], at most eight distinct values, defaulting to **50, 80, 100**.
  Fractional percentages are valid. A non-integral token crossing waits for the
  next whole token; zero-percent thresholds do not fire, matching existing units.
  Notices fire at equality, once per unit/percentage for the task's lifetime,
  including crash recovery. Task configuration changes snapshot the current
  usage baseline and do not retroactively fire or re-arm notices.
- A missing task token budget inherits the replaceable **`tokens_per_task`**
  default from `<GRID_HOME>/workspace.md`. The existing
  `taskfile.ParseFrontmatter` reader supplies string scalars; no YAML helper was
  added. Digits must represent an integer from 1 through 18446744073709551615.
  Quoted digits, leading zeros and trailing comments follow that reader's existing
  scalar rules. Missing keys/files, symlinks, non-regular/unreadable files,
  invalid UTF-8, invalid values and files larger than **64 KiB** give no default.
  Opening refuses symlinks, checks file identity, and bounds the read itself.
- `budget show`, set and clear return effective settings, including
  `token_budget_source: "task" | "workspace" | "none"`; text prints that source.
  `budget.tokens` is absent for none. Threshold output uses the same configuration
  shape. Old version-1 settings acquire default token percentages and a zero
  token baseline on read. Budget/baseline JSON values remain numbers, preserving
  exact integer text; quoted numbers and null are rejected. Inherited budgets and
  derived sources are never saved into task settings.
- Clearing the task token budget restores the workspace default; it is **not** a
  way to disable an inherited limit. Clear without selectors clears all three
  units. Explicit false selectors fail without writes. Each post/budget show reads the
  current workspace default. An external default change does not rewrite the
  task baseline; an unfired crossing can therefore be noticed on the next post.
  Read-only commands neither write nor emit notices.
- `internal/usage/fold.go` reads only explicit delta records, not observed session
  totals. The separate flags-only `grid usage --json` path already folds session
  hook token observations via `session.FoldUsage`; it stays separate to avoid
  double counting. Workers/hooks must post their task deltas to this ledger in
  the follow-up. No transcript inference or workspace writer was added.
- The 100% notice is informational here: posting continues beyond the limit.
  Holding/refusing/stopping sessions is **not enforced yet** and belongs to the
  worker/session-hook follow-up. No workflow file is read; the default key and
  existing threshold settings remain replaceable.

## Scope exceptions

The brief authorized the smallest necessary exceptions without asking:

1. `contract/schemas/usage-notice.json`: admit the integer `tokens` unit and require
   exactly one of dollars/minutes/tokens. Without this change every token notice
   is rejected by Feed admission. Tests check negative/fractional tokens and
   mixed-unit rejection.
2. `internal/feed/record.go`, `read.go`, `store.go`: preserve token notice numbers
   through normalization, stored-body reads and cached/cold reads. A boundary
   regression proved the existing float conversion changed
   `18446744073709551615` into `18446744073709552000`. The decoder preserves only
   the token notice's token number; other fields retain their representation.
   The embedded Entry decoder preserves cache/admission metadata as well.
3. Ten existing `testdata/golden/usage-*.golden` JSON expectations needed additive
   token totals/thresholds/baselines/source fields. No existing help golden changed;
   the usage help is covered directly, including the workspace key and missing
   hold enforcement. No unrelated golden was regenerated.
4. `testdata/golden/mcp-session.golden`: the full suite found that the advertised
   Feed type inventory embeds the usage-notice schema. Only that schema payload
   was updated to include tokens; the MCP implementation was not changed.

`go.mod`, the Makefile, and `contract/commands.json` were not edited. The inventory
file does not exist at the fetched base, and no current test requires it. No
root `DONE.md` was added. Pre-existing untracked runner files were left alone.

## L47R command inventory additions

Add the following flag forms to the existing commands (all also accept `--task`
and `--json`); set/show/clear JSON is the effective Configuration described above:

```text
grid usage post --job J-N|lead --tokens N [--session ID] [--model NAME]
grid usage threshold set --tokens PERCENT [--tokens PERCENT ...]
grid usage threshold clear --tokens
grid usage budget set --tokens N
grid usage budget clear --tokens
grid usage show --json                 # jobs[].tokens and totals.tokens: uint64
grid usage budget show --json          # budget.tokens?: uint64; token_budget_source
grid usage threshold show --json       # tokens: percentage[]; same budget/source
```

`post` JSON adds tokens to jobs/totals and keeps notices/warnings arrays. Budget
set requires a positive integer; post permits zero. Threshold percentages are
numbers, not token counts. All summaries include tokens even when the total is
zero. Source is always one of task/workspace/none in effective settings.

## App runner argv

The later app lane should use explicit task scope and consume numeric JSON:

```json
["usage","budget","show","--task","T-NN","--json"]
["usage","budget","set","--tokens","N","--task","T-NN","--json"]
["usage","budget","clear","--tokens","--task","T-NN","--json"]
```

These are argv after the `grid` executable. `token_limit` maps `budget.tokens`
(or absence) to `{tokensPerTask: N}` (or null), retaining source information when
useful. `save_token_limit` uses set for positive N and clear for null, then reads
that command's effective result. Clear can return an inherited non-null limit;
it removes a task override, not the workspace setting. These ops now require a
resolved task; workspace-wide saving/clearing is not implemented by this lane.
