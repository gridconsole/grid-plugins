## Audit

The eight original exceptions are now four exact-file exceptions. Each remaining
entry has a one-line explanation beside it. Directory-prefix matching is gone;
the audit also rejects unused exceptions and empty reasons.

| Original rule | Original exception | Decision and reason |
| --- | --- | --- |
| `gridhome.TasksDirs(` | `internal/gridhome/` | Remove: the primitive defines `TasksDirs` but never calls this qualified expression. |
| `gridhome.TasksDirs(` | `internal/where/` | Narrow to `internal/where/personal.go`, which applies caller policy to primitive task roots. |
| `gridhome.TasksDirs(` | `internal/task/create.go` | Keep: global ID allocation must include Personal IDs; allocation-lock staging cleanup must visit every root. Filtering these scans could reuse IDs or abandon stale staging folders. |
| `gridhome.TasksDirs(` | `internal/task/history.go` | Remove: its single enumeration now uses the supplied resolver, including caller identity and policy overrides. |
| `where.Resolver{` | `internal/where/` | Remove: the implementation does not use this qualified literal. |
| `where.Resolver{` | `internal/cli/cli.go` | Keep: the shared CLI boundary constructs the resolver and stamps `CallerFrom(env.getenv)`. |
| `where.Resolver{` | `internal/guard/settings.go` | Keep: direct guard adapters are a separate environment boundary and stamp their own caller before resolving settings. |
| `where.Resolver{` | `internal/workflow/files.go` | Remove: workflow file discovery no longer constructs a resolver. |

`FolderAt` now accepts a resolver instead of just the Grid home. All five hook
call sites pass their existing resolver, preserving caller policy during history,
current-task, named-task, and saved planner-task lookups. Canonicalization stays
inside the lookup; the existing metadata and symlink checks remain in place.

## Necessary adjacent changes

The baseline choke-point test already failed on two unallowlisted uses:
`internal/job/jobcmd/trace.go` called `gridhome.TasksDirs`, and
`internal/workflow/write.go` constructed a resolver without caller identity.
These were fixed instead of adding exceptions:

- Trace takes a resolver and enumerates its visible task roots. The CLI passes
  its existing resolver through `jobcmd.Env`; direct trace tests pass fixtures.
- Workflow writes take the CLI's resolver for project selection instead of
  constructing a new one. Existing strict project-registry and safe-write
  validation is preserved; write tests use resolver fixtures.
- The hook callers and focused tests changed only as needed for propagation and
  regression coverage. No changes to the module, build rules, or primitive
  task-creation scans were needed.

New regressions cover owner, guest, identified member, and policy-override task
lookups; owner versus guest trace visibility through the CLI; and workflow writes
respecting an explicit Personal-policy override. Existing package tests cover
legacy hook metadata, unsafe trace paths, and workflow write validation.
