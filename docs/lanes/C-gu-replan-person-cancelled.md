# C-gu-replan-person-cancelled

Base: lane-C-gu-replan-job-dead-asks-owner (stacked, merged into this branch at 9b92c31b; it is itself on lane-C-gu-replan-after-reject). Base check: on base, `gkReplan` (internal/orchestrator/replan.go:30) skips every Job without ExitReason "cancelled", and a person Job is never assigned to a worker (person.go:146-152), so it has no worker-exit. A person Job withdrawn by a control (status cancelled, `grid job cancel`) while Jobs wait on it through a done edge gets nothing: they wait for ever ("waiting for J-1, which was cancelled").

A person Job (role Person) that is Cancelled while Posted or Ready Jobs still hold a done edge to it gets one re-plan Job (role orchestrator, `discovered_from` the person Job), the same Job `gkReplan` posts, with no cause. The pass posts a Job and nothing more. It adds no guard, gate, cap or limit on agents, cancels nothing and counts nothing; replan.go is not edited.

## What changed

- internal/orchestrator/replan_person.go (new): `Store.guReplanPersonCancelled`. It walks `snap.Items`; for an item with `IsPerson()` whose folded status is Cancelled, with `gkWaiting(snap, id)` not empty and `gkReplanned(snap, id)` false, it posts `ReplanJobBody(gkNextJobID(snap), id, "", waiting)` and reloads the snapshot (as replan.go:41-45 does), so the next withdrawn Job counts this one when it picks its id.
- internal/orchestrator/tick.go: after `guReplanAskOwner`, `snap, e = Load(s.Feed)` then `s.guReplanPersonCancelled(snap)` (R3 shows the reload is needed).
- internal/orchestrator/gu_replan_person_test.go (new): rows 1 to 4, plus `TestGuPcNoWaiter`, `TestGuPcSameTickAsOwnerJob` and `TestGuPcChainEndsAtOwner`.

Once-only comes from the re-plan Job on the Feed (`gkReplanned`, read from `snap.Items`); no memory field, file or counter was added. If that re-plan Job later ends Cancelled or Rejected with the Jobs still waiting, the base lane's `guReplanAskOwner` posts one person Job for the owner (`TestGuPcChainEndsAtOwner`), so the chain still ends at a person.

## Notes for the reviewer

- Only status Cancelled is acted on, as the brief says. A person Job closed Rejected by a control gets nothing from this pass, and needs nothing: `guReplanRejected` (replan_reject.go:21-23) takes every Job with status Rejected and has no person filter, so it covers a rejected person Job. I did not add a test for that case.
- `proposals(snap)` in tick.go still gets the snapshot taken before this pass posts, as it did for the base lane's pass; it was already not the latest after `guReplanAskOwner`. `Ready` is computed on a fresh `Load` after it (tick.go:109).
- The re-plan Job body is `ReplanJobBody` unchanged: its A1 text says "No Job waits on J-1 any more ... the work of J-1 is posted again as a new Job", which reads fine for a person Job; the title and A1 say "was cancelled".
