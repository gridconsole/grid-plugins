# L141: brain lock create no longer races through os.Root on macOS

Branch: `lane-L141`, from plugin main `35ba5de7bafc72e6135bd24645b3bc8154b0b681`.

## Changes

`locked()` in `internal/brain/store.go` opened the lock with
`root.OpenFile(lockName, O_RDWR|O_CREATE)`. On macOS, several writers creating
the missing lock at once through `os.Root` could get
`openat .brain.lock: no such file or directory`.

`locked()` now calls a new `openLock(root)`: it creates the file with
`O_RDWR|O_CREATE|O_EXCL` (ignoring `ErrExist`, and `ErrNotExist` from the
create itself), then opens it with `O_RDWR` and no create, retrying up to 20
times on `ErrNotExist`. The same pattern already exists in
`internal/workflow/write.go` `openLock`.

The refusal of an unsafe lock stays inside `os.Root`: `safefile.NoSymlinks`
runs first as before, and after the open `checkLock` compares the opened file
with `root.Lstat(lockName)` (must be regular, `os.SameFile`), so a symlink or
non-regular file swapped in is refused.

New test `TestLockCreateRaceNeverFails` (`internal/brain/lock_create_test.go`):
64 goroutines, each with its own `os.Root`, released together, take the lock on
a fresh folder with no lock file, 4 rounds per run. No call may error and no two
may hold the lock at once.
