## Workspace inbox policy

`workflow.InboxWorkspace` is in a new `internal/workflow/inbox_workspace.go`.
It reuses `parseFrontmatter` without modifying the helper and reads only workspace
`workflows.md` through the existing capped, symlink-refusing reader. Missing
files, legacy prose, and unset keys default to Personal. Only the string
`personal` is accepted; malformed front matter and unsafe reads fail closed.
The shared parser rejects an empty YAML document, which remains a parse failure.
Project-local inbox keys cannot override the workspace. Named destinations skip
the inbox policy read, including a destination explicitly named `personal`.

The CLI returns exit 1 with exactly this value-free, path-free stderr line:

```text
grid signal move: invalid inbox_workspace in workspace workflow (only personal is supported)
```

With `--json`, stdout contains exactly one object:

```json
{"error":"invalid_policy","key":"inbox_workspace"}
```
