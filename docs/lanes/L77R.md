## Home policy

Owner and known worker roles retain their existing home behavior. Members and
leads, with or without identity, can access other projects, knowledge and home
settings, but cannot access Personal. Their permission approvals apply only to
the current request and never add a directory permission. Their own-script
shortcut remains available; explicit Personal path arguments are refused.
Implicit legacy-script behavior is retained for members, as requested; this
permission guard is not a shell sandbox.

Guests and external callers get only the active registered project, because no
membership ACL exists. Unknown roles get no home or own-script approval,
including inside the active project. Personal and scope denials remain hard
denials when home-allow is off or warn. Lexical and resolved Personal paths,
symlinks and broad ancestor directory requests remain guarded.

The role table covers owner, member without identity, member with identity,
lead with and without identity, worker, guest and unknown. Each covers another
project, knowledge, settings.json, Personal and an own-script Bash call, plus
the active project and script arguments, both role spellings and both events.
The real CLI entry regression covers PreToolUse, PermissionRequest and
permission-forward and no longer expects members to be confined as guests.
