## Home policy

Owner and known worker roles retain their existing home behavior. Members and
leads, with or without identity, can access other projects, knowledge and home
settings, but cannot access Personal. Their permission approvals apply only to
the current request and never add a directory permission. Their own-script
shortcut remains available; explicit Personal path arguments are refused.
Implicit legacy-script behavior is retained for members, as requested; this
permission guard is not a shell sandbox.

Guests and external callers get only the active registered project, because no
membership ACL exists. Unknown roles get no home or own-script approval,
including inside the active project. Personal and scope denials remain hard
denials when home-allow is off or warn. Lexical and resolved Personal paths,
symlinks and broad ancestor directory requests remain guarded.

The role table covers owner, member without identity, member with identity,
lead with and without identity, worker, guest and unknown. Each covers another
project, knowledge, settings.json, Personal and an own-script Bash call, plus
the active project and script arguments, both role spellings and both events.
The real CLI entry regression covers PreToolUse, PermissionRequest and
permission-forward and no longer expects members to be confined as guests.

## Security follow-ups

Brain writes recognize only grid:grid-curator, grid-curator,
grid:grid-planner and grid-planner. Bare curator/planner, foreign namespaces,
short namespace aliases and repeated prefixes are refused. Tests cover both
home and project knowledge folders.

Glob validation expands nested braces with bounded work, checks path elements
before normalization, and refuses every `..` element, including `{..,x}`,
`{.,x}.`, and combinations spanning adjacent braces. Absolute patterns require
a literal prefix inside the permitted root both lexically and after symlink
resolution. Malformed or excessive brace expansion fails closed. The existing
owner glob regression now expects a hard denial for an escaping pattern; valid
relative and in-scope absolute patterns still pass.

Job trace now receives the CLI's existing caller-aware resolver and enumerates
only its visible task roots. Workflow writes receive that same resolver for
project selection instead of constructing an anonymous owner resolver. Their
package tests check that member identity cannot expose Personal trace rows or
write a Personal workflow. No choke-test exception was added. The workflow
write role gate also uses the shared role normalizer, preserving L77's alias
rule for this newer main entry point.

Two existing CLI fixtures needed alignment: the feed-types byte baseline now
includes main's guest control role, and the fresh-home task-lease test uses an
owner to create its Personal task. These changes retain the production
withdrawal and Personal policies instead of weakening them for fixtures.

case from no automatic answer to a hard denial. A single known-difference
entry cites this note; recorded golden outputs are untouched. The corpus
citation parser now accepts an optional R suffix for rework lane notes.
