# L100 — Remaining task folder operands

Base: plugin main `978c88d116c0cc981e5d8ad1122503edd804ca12`.
Branch: `lane-L100`.

## Changes

All nine task-naming command paths now use L85's existing
`internal/cli/task_operand.go:resolveTaskOperand` and `taskOperandError`:

- `deliver --task`
- `proof add --task` and `proof index --task`
- `history add --task`
- `land <task>`
- `brain show --task`, `brain search --task`, `brain keep --task`, and
  `brain decide <task>`

The resolver returns the validated task record; ID-based stores receive its ID,
and proof and brain use its resolved path. Existing delivery gates, proof checks,
land approval checks, brain decisions and task writer locks remain in their
stores. Brain's independent command package accepts resolver and error callbacks
from the CLI, so no second folder resolver was introduced. Its standalone
ID-based default remains available to package callers.

Task resolution failures now use the shared L85 diagnostic and exit mapping,
including plain stderr for brain task resolution with `--json`. Other store
errors keep their existing command handling. Outside folders still exit 2.
The shared helper now returns `task not found` with exit 1 for a direct Personal
task path hidden from the caller, matching hidden and unknown IDs. This also
applies to L85's existing verbs and avoids inspecting the hidden task itself.

Help for all nine command paths and the three relevant group help screens has
new goldens. Usage uses `<task>` and preserves the exact existing L85 wording:

```text
<task> is an id, exact folder name, or folder path inside a project tasks directory.
```

The task operand contract and delivery documentation describe the extended
coverage. There was no explicit file touch list in the brief. The supporting
changes outside the named CLI command files are the two brain command adapter
files, the six-line shared-helper privacy fix, the regression matrix, help
goldens and these contract/documentation updates. The shared-helper fix was
necessary because L85 previously returned exit 2 for hidden Personal paths,
which differed from the requested unknown-ID refusal. No command inventory
change was needed: command names, flags and positional annotations are unchanged.
Neither `go.mod` nor the Makefile was changed. No Rust reference was needed.

## Validation

`TestRemainingTaskOperands` supplies a per-command table of nine forms: bare ID,
absolute folder, exact folder name, relative folder, outside folder, unknown ID,
hidden ID, hidden absolute folder and hidden folder name. Hidden cases use a guest
caller and a real Personal task. Refusal rows compare their expected message and
exit code with L85 `task show`, require empty stdout, and compare the complete
Grid home file contents before and after to detect writes. Successful commands
must return valid JSON without stderr. Existing package tests also cover omitted
current-task selection and command-specific state and approval rules.

Validation results:

- `make test`: passed, including all packages and no new matching temp entries.
- `go test -race -count=1 -p 2 ./internal/cli/... ./internal/task/... ./internal/where/...`:
  passed (CLI 34.963s, task 7.461s, where 2.467s).
- `make lint`: passed (`go vet ./...` and formatting check).
- `GOOS=windows go build ./...`: passed.
- `GOOS=darwin go build ./...`: passed.
