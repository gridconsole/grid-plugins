## Policy audit and changes

Only `List` opts into the question Store's deny-all read fallback. The shared
projection policy reader is strict by default. Every operation that persists
question projections resolves the actual workflow policy before creating the
question directory, opening its lock, repairing projections, or appending Feed
records. The CLI also checks before writer identity setup can create machine
state. Unreadable policy returns exit 1, empty stdout, and one path-free policy
diagnostic without a fallback warning.

The complete question Store write audit is:

| Operation | Policy-dependent writes and protection |
| --- | --- |
| `Answer` / `grid answer` | Calls `change()`, which checks strictly before both projections and the answer append; covers open and withdrawn questions. |
| `Withdraw` / `question withdraw` | Checks before authorization, then calls the strictly checked `change()`; person and leased paths remain closed on read errors. |
| `Add` / `question add` | Checks before directory/lock creation, projection repair, ID allocation, and question publication. |
| `Tick` / `question tick` | Checks before projection repair or durable default/aging events. |
| `Sync` / `question sync` | Checks before writing repaired projection files. |

`Answer` and `Withdraw` are the only callers of `change()`. `ReserveGate` was
also inspected: it allocates an ID marker from filenames and invokes a publisher;
it neither reads withdrawal policy nor folds question state, so it is unchanged.
Host `WithdrawAllowed` overrides cannot bypass an unreadable workflow file.
Resolved callbacks stay on operation-local Store copies, so later calls read
policy again. A repeated check uses a silent warning sink when the operation
already has a callback, preserving one malformed-policy warning for withdrawal.
Missing and malformed policy behavior otherwise remains unchanged.

This rework supersedes L81's fallback for `question tick` and `question sync`:
both persist policy-dependent state. Their rows move out of the successful-read
table. `question list` still succeeds with one deny-all warning; the existing
Feed/orchestrator projection fallback and non-withdrawal Job posting behavior
remain covered. Feed, Job, MCP, host, person, and leased withdrawal refusal tests
continue to pass. Orchestrator tick remains the original brief's explicit
continuation case, distinct from the question Store's durable tick.

`question add` did write before its failure on L81. On an empty task it created
question directory/lock entries; with a withdrawn question it rewrote that
projection using the deny-all fallback before the gate-role read failed. Both
cases now fail before those changes and produce the same path-free diagnostic
as answer.

No explicit touch list was supplied. The smallest supporting changes outside
`question.go` are the command preflight, `Sync` preflight in `feed.go`, regression
tables, and contract text documenting the corrected split. The existing module,
Makefile, and inherited unrelated L81 changes were retained. No root DONE file
was created; the pre-existing untracked briefing and execution log are excluded
from commits.
