# L58: trace filed Job inputs

Base: `bea29f9`, after `60ce72d`, on `lane-L58`. Added the read-only
`grid job trace` command. No root DONE.md, contract edits, Feed writes,
brain changes, or changes to existing Job verbs. Package-level names were
checked against local main and this checkout before implementation.

## Command and API

```sh
grid job trace brain:project/x
grid job trace brain:home/x --sha256 aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa --project alpha --json
grid job trace 'repo:docs/example.md#overview'
```

`jobcmd.Trace(home, pointer, digest, project)` returns `(TraceResult, error)`.
The JSON result has exactly two keys, always arrays:

```json
{
  "rows": [
    {
      "project": "alpha",
      "task": "T-01",
      "job": "J-1",
      "pointer": "brain:project/x#overview",
      "sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
      "updated": "2026-01-01",
      "tier": "person-team",
      "filed": "2026-01-02T03:04:05.000Z"
    }
  ],
  "problems": []
}
```

Rows are sorted lexically by project, task ID, then Job folder ID. Each matching
saved source yields a row; several anchors from one Job can therefore yield
several rows. Equal-key rows retain their saved source order. The source pointer,
digest, updated value and tier are copied from the saved evidence. `filed` is
the **bundle directory modification time**, formatted with `contract.FormatTime`.
The current saved Job shape has no filed timestamp. Copying or touching a bundle
can change this time; it is not the time the Job ran. Trace does not read job.yaml.

Plain output prints one row per line in the same field order, with labeled
sha256, updated, tier and filed fields. Values are quoted so embedded newlines
cannot manufacture extra rows. Problem lines follow the rows. A problem has
exactly `{task, job, text}` and reports no home path or raw filesystem error.
Task or Job may be empty when a problem concerns a parent folder. JSON errors
also use the two-key shape, with empty rows and a problem whose task and job are
empty; plain command errors go to stderr.

The added dispatch case runs before the existing shared flag parser, letting
trace own `--sha256` and `--project` without changing how existing verbs parse
flags. Flags may occur before or after the pointer, following `trace`.
No pointer, extra positionals, malformed brain IDs, invalid SHA-256 digests,
missing flag values, or unknown flags return usage status 2. An unknown project
returns status 1. Successful scans return 0, including no matches and scans with
problems. Output failures return 1. There are no shared named usage or not-found
constants on this base or local main: L51's actual convention is 0/1/2/3/4
(`internal/cli/exitcode.go`, `docs/lanes/L51.md`). Trace uses local named constants
for 0, 1 and 2; not found uses the existing general failure status 1.

## Matching and reading

- Remove `#anchor` and the resolver's trailing `:start-end` line range from
  query and saved pointer before matching.
- For brain pointers, call `job.ParseBrain` and match both level and name.
  `brain:home/x` and `brain:project/x` are distinct. Project-level identities
  match in every project by default; `--project` narrows their scope.
- For other pointers, compare the path parts exactly. There is no basename,
  prefix, case folding, path cleaning, or scheme removal.
- A supplied digest must be 64 hexadecimal characters and match the saved
  digest exactly, including case. Omission matches every saved version.
- `gridhome.TasksDirs` enumerates Personal and all project task roots;
  `task.Read` owns task.md and intent.md reading. Project selection accepts
  an exact folder name, `personal`, or an ID resolved through `project.Load`.
  Named legacy project folders do not require project.md.
- Only filed `jobs/*/inputs.json` evidence is scanned. Temporary `.render-*`
  directories are ignored. Every input read passes through `job.Within`, plus
  a check refusing symlink components even when they point inside the task.
  Nonregular input files are refused. A symlink used for the home itself is
  accepted, including platform aliases above the home.
- Broken, missing, null or malformed inputs, unsafe paths, and invalid task
  metadata produce problems without aborting the other bundles or tasks.
  A missing jobs directory is normal. Failure to enumerate the home or resolve
  an explicit project is a command error.
- `job.Inputs` remains the reader, including older files without `brain_tokens`,
  `not_rendered`, or the later shell-execution field. The committed legacy
  fixture exercises that format; tests also use older task front matter.
  All saved sources count, including budget-omitted and pointer-only sources.
  Trace does not consult live brain contents or infer execution from a render.

## Differences and the later keeper step

This adds a read-only query over the Go renderer's saved evidence, not a new
legacy-reader format. Reference `docs/job-contract.md:80` defines deterministic
renders saved with inputs.json. Reference `docs/brain-feed.md:18` and
`docs/plugin-design.md:22` describe `grid brain uses <id>@<version>` and a revert
posting re-checks. This lane intentionally exposes that lookup as
`grid job trace <pointer> --sha256 <digest>`, also supporting non-brain paths,
project filtering, structured problems and partial results. These are the
intended command/output differences; existing render, lint, show and verify
behavior stays unchanged.

The tk-trace reopen step remains out of scope. After the keeper's revert exists,
it can use these saved source matches to identify affected Jobs, decide which
require review, and post the appropriate re-check/reopen records. Trace neither
reverts entries nor reopens Jobs, edits saved bundles, posts Feed records, or
claims a filed render was executed. No other requested implementation is left
unfinished.

## Contract README block to paste later

```markdown
### Trace filed Job inputs

`grid job trace <pointer> [--sha256 <digest>] [--project <name-or-id>] [--json]`
reads saved `jobs/*/inputs.json` across Personal and every project. Brain IDs
match by level and name, ignoring anchors; other pointers match their exact
path part. Line ranges are ignored. `--sha256` selects an exact saved digest.
`--project` selects a project name, stable ID, or `personal`.

JSON is `{rows, problems}`. Each row contains `project`, `task`, `job`,
`pointer`, `sha256`, `updated`, `tier`, and `filed`, sorted by project, task,
and Job. Each matching saved source is a row. `filed` is the bundle directory
modification time, not an execution timestamp. Problems contain `task`, `job`,
and `text`, without home paths. Plain output lists rows followed by problems.
Malformed and symlinked bundles are reported without discarding other matches.
Old inputs without brain_tokens or not_rendered remain readable.

Exit 0 includes no matches and partial results with problems; usage is 2 and
an unknown project or command-level read/output failure is 1. This command is
read-only: it does not revert brain entries, post Feed records, or reopen Jobs.
```
