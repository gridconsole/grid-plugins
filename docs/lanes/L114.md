## Problem and policy

Task workflows could not supply usage notice thresholds. The new
`workflow.UsageNoticeThresholds(taskDir)` reads the top-level
`usage_notice_thresholds` key in task `workflow.md` front matter using the same
delimiter rules and `yaml.Load` as `GatePostRoles`. Missing files or keys return
a nil map. Nested or body keys do not apply. Supplied units must be `tokens`,
`dollars`, or `minutes`, with nonempty lists of positive finite numbers, strictly
increasing and ending at 100. Omitted units remain omitted for the configuration
source to resolve. Invalid units are omitted while valid units survive; errors
name the policy and unit, are joined in sorted unit order, and filesystem read
errors omit the task path.

Steps 1 and 2 left integration pending landed L113; step 3 below completes it
using the existing seam. Precedence per unit is task `thresholds.json`, then
`usage_notice_thresholds`, then the default.

## Step 3: wire the workflow policy (L114B)

Branch: `lane-L114B`. Fetched origin, reset this branch to `origin/lane-L114`,
and rebased onto plugin main `49ca9088d61d8c033c9fcd136aa7decc669b4900`.
L113's landed `docs/lanes/L113.md` and implementation commit `1b197ab`
confirmed the dependency and seam, without relying on ancestry alone.
Validated implementation head: `c4ee0d238b7c8290e6ed93418597b1b423fd23f7`.
This lane-note commit is a documentation-only follow-up to that head.

The missing behavior was applying the already implemented workflow reader to
usage configuration. `Store.readConfig` now calls
`workflow.UsageNoticeThresholds(s.TaskPath)` at `internal/usage/notice.go:220`
and fills L113's existing `Store.UsageNoticeThresholds *NoticeThresholds` seam
on the local Store copy. The field remains nil by default; an explicitly
injected seam still replaces workflow reading and keeps its existing error
signature. Config, Configure and posting all use this single read site.
No shared Store mutation or new lock is introduced.

Per unit, task `thresholds.json` wins, then `usage_notice_thresholds`, then
built-in defaults (tokens 80/100, dollars and minutes 50/80/100). Explicit
empty task lists remain authoritative. Invalid workflow units retain defaults
while valid units survive. `Store.WorkflowWarning` receives joined errors once
per configuration read; both task CLI Store constructors install the same
stderr reporter, yielding one warning per command. Posting still records usage
and emits notices. The seam's existing eight-threshold limit is retained;
workflow lists exceeding it also fall back and warn instead of stopping notices.
Existing configuration saves still persist all effective lists, which then have
task precedence on subsequent reads. Fired entries and notice persistence are
unchanged, including recovery when a notice exists but its fired state was not
saved.
