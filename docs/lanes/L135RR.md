# L135RR — a case pattern's ) must not close a $( ) group

## Base

`lane-L135R` (1527a307) rebased onto plugin main `35ba5de7`. Clean rebase; the
three lane files are the only ones touched.

## What changed

Only `internal/guard/host_targets.go` and a new test file,
`internal/guard/host_write_targets_case_test.go`. No existing test is edited
(`host_write_targets_test.go` and `host_write_targets_rework_test.go` are
byte-identical to 1527a307).

1. Case groups (must-fix 1). `hostShellGroup` ends a `$(..)`, `<(..)`, `>(..)` or
   nested `(..)` group at the first unmatched `)`. It now also counts the words
   `case` and `esac` inside a `(`-closed group; while a `case` is open, a `)` is
   a pattern terminator and does not close the group. The whole `case .. esac`
   stays the body, so `hostSegments` on the body sees `tee alias` as a command of
   its own, and `writesProjectWorkflow` (host.go) and `protectedWriteReason`
   already refuse it. Backtick and `${..}` groups already ended correctly and are
   untouched.
   - Every whole word `case` counts, in command position or not (`echo $(echo case
     x)`). A miscount can only keep a group open until the end of the text. An
     unfinished group consumes the rest of the text, and that text is scanned as a
     command, so a command is never allowed because it fails to parse
     (`echo $(case x in x) tee alias </dev/null;;)` and the same without the
     closing `)` are refused).
   - A stray word `case` followed by a blank inside `$( )` keeps the group open
     to the end of the text. The rest is then scanned inside that body instead of
     as outer segments; it is still scanned as commands, so it is refused or
     allowed by the same checks (`echo $(echo case x) > notes.md` runs).
2. Clobber forms (must-fix 2). `>!`, `>>!`, `&>!`, `&>>!`, `>|`, `>>|`, `&>|`,
   `>&|`, `>&!` and the zsh `>>&` are read as one write operator each (the
   operand is a target). `>&` followed by an fd or `-` stays an fd duplication.
