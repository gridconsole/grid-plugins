## What changed

- `versions.go`: `Version{N, Hash, Path}`, `Store.Versions(level, topic, name)`
  (oldest first; a missing folder is an empty list) and `recordVersion`.
  Versions live at `knowledge/versions/<topic>/<name>/<n>.md`, written with
  `atomicWrite` through the level's `os.Root`; `NoSymlinks` runs on the folder
  before it is listed and on every write, so a symlinked `versions` folder is
  refused. `<n>` is one higher than the highest present. When the highest
  already holds exactly the bytes about to be published, its number is reused
  and nothing is written: that is what makes a retry add nothing.
- `changes.go`: `Change`, `Store.Changes(level, since, limit)` and the log line.
- The version is written before the entry is published, under the existing level
  lock, at all three sites: `Store.decide` (Accept), `DecideTask` (accept and
  merge-into) and `EditConfig`. The audit line follows the publication.
- Signatures of `EditConfig`, `Accept`, `Reject` and `DecideTask` are unchanged.

### Log line

The five original fields keep their positions; topic, version and hash are
appended:

```text
- <at> | <status> | <name> | <kind>:<id> | <reason> | <topic> | v<n> | sha256:<16 hex>
```

The hash is the first 16 hex digits of the SHA-256 of the bytes written to the
published file, which are also the bytes of version `n`. A rejection publishes
nothing and logs `v0` and an empty hash. The retry rule is the old one: a line
already present is not appended again.

`Store.Changes` reads both formats. A line of five fields is an old line: topic
empty, version 0, hash empty. Lines that are not `- ` lines, have an unreadable
stamp, or have a malformed version or hash field are skipped, so a hand edit
never breaks a read. `at` is a string in `contract.TimeLayout`, like
`Note.Updated`. Newest first; stamps that tie are ordered by position in the
log, later lines first. `since` keeps lines stamped at or after it (the zero time
keeps all). `limit` of zero or less means no cap.

## Decisions the brief left open

- `merge-into` and `accept` through `DecideTask`: the line names the entry that
  was published (its topic and name), not the proposal, because that is what has
  versions. For `Accept` they are the same. The reason still reads
  `merge-into brain:<level>/<name>`. `reject` keeps the proposal's name.
- Config edit line: status `accepted`, origin `config:<session id>` from
  `SessionOrigin`, empty reason, topic and name of the entry.
- A config edit that returns the bytes already in the file adds no version and
  no line. Removing a config entry (nil from the callback) adds neither and
  leaves its history in place.
- A retry of an accept finds the published note already there, and records a
  version for it only when the newest stored one differs (an entry published
  before this change gets version 1 then).
- An entry published before this change is not snapshotted when it is first
  changed: its first stored version is the new bytes. Nothing in the brief asks
  for the old bytes, so there is no way back to them.

## Tests

- `TestAcceptKeepsVersionAndAuditHash`: accept makes version 1 and a line with
  its hash; a repeated accept adds neither; a rejection logs `v0`.
- `TestMergeIntoKeepsNextVersion`: merge-into makes versions 2 and 3 with
  matching hashes; an interrupted decision finished by a retry adds nothing.
- `TestDecideTaskAcceptNamesThePublishedEntry`.
- `TestConfigEditKeepsVersionAndAuditHash`: edits make versions 1 and 2 with

## NOT VERIFIED

- Windows and macOS were built, not run.
- `knowledge/log.md` is read whole by `safefile.Read`, which refuses files over
  1 MiB. Config edits now add a line each (routine state saves included), so a
  busy home reaches that limit after a few thousand edits and every brain write
  would then fail. The brief names no rotation; this needs a decision.
- The desktop app's brain reader lists any `.md` below `knowledge/` to depth 4
  except `index.md`, `log.md` and `TOPIC.md`, and only hides configured topic
  names, so by reading its code it would surface `versions/<topic>/<name>/<n>.md`
  as entries. Not checked against a running app, and outside this repo.
- A crash between publishing and the log write loses the audit line: a retry
  finds identical bytes and, for a config edit, treats it as no change.
