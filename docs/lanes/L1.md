# Lane L1: Feed and Job contract

L1 built 26 JSON Schema 2020-12 documents (all 19 Feed post types, the envelope,
the Job record, leases, the heartbeat file, the takeover entry and the trust tier)
with valid and invalid fixtures for each, named after the rule they test. The
standard-library-only `internal/contract` package embeds the schemas, validates
them with a small fail-closed subset validator, and folds one task's posts into
Job state with `Fold(posts)`. `contract/README.md` holds the type, schema and
source table, the spec disagreements and the chosen defaults.

Check it with `make test` and `make lint` from the repository root.

## Not covered here

- The lane implements record contracts and an in-memory fold, not a Feed file
  writer, reader or worker supervisor. The filesystem, concurrency and macOS
  durability spikes were not run.
- The caller verifies writer filenames, admission and takeover offsets, resolves
  body references and supplies authorized tenures.
- Liveness polling, sleep and wake detection, ready scheduling, gate timers, CI
  and crash-loop scheduling need those outside components. The fold never infers
  stale from a clock, and a schema cannot authenticate a stamped role.

## Left as they are after review

- Every schema `$id` uses the placeholder host `https://example.com/grid/contract/`.
  A stable id under the module comes with the published contract.
- When two fence-0 writers post the same `job` id, the fold's sort tie-break on
  `worker` decides which one wins, although feed-contract.md:174 orders nothing
  across files. Refusing a `job` post outside a task-lease tenure, or ignoring
  both duplicates, is left to the spec owner.
