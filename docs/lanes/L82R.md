# L82R: environment lifecycle review fixes

Rebased `lane-L82R` from the L82 branch onto plugin main `6dff18acff33cd1a1122bbebefc2149c68d6ddee`; no conflicts. Fix commit: `730a4f0`.

## Changes and scope

- Replace the lifetime FIFO with a loopback TCP listener and one connection per helper process. Each process writes its startup witness and holds the connection until exit; the tree case requires both witnesses and EOF on both connections. Accepts and reads share the existing three-second shutdown bound. No sleeps, retries, or increased timeouts were added.
- Restore `TestDevServerLifecycle/stubborn`'s lower bound around `Manager.Down`: stopping must take at least `2*m.Grace` (200 ms). Scheduler delays can only increase this elapsed time. This checks env's grace argument plumbing in addition to ports' isolated signal-ladder tests.
- Name `TestStopSignalLadder` and `TestStopRechecksIdentityBeforeEscalation` in `internal/ports/process_unix_test.go` as the coverage for the removed signal-log assertion, both in the lifecycle test comment and in `L82.md`.

The necessary companion change outside the explicitly named test/doc files is `internal/env/testdata/server/main.go`: read the lifetime address and dial TCP instead of opening the FIFO. The witness remains optional for CLI callers. Production env, migrate, and ports code, the module, and the Makefile are unchanged.

## Portability

Validation runs on Linux amd64 with Go 1.27.3. No Darwin runtime is available in this environment, so native execution of the seven lifecycle subtests and the GC test on Darwin is not claimed.

The replacement uses Go's portable `net.ListenTCP`, `TCPListener.AcceptTCP`, `TCPListener.SetDeadline`, and `net.Conn.SetReadDeadline` APIs instead of file deadlines. `ListenTCP` with port zero requests an automatically selected port; `TCPListener.SetDeadline` bounds accepts; `SetReadDeadline` bounds pending and future reads. `io.ReadAll` succeeds only after EOF, preserving the shutdown witness rather than relying on PID disappearance. These network APIs support both Linux and Darwin and do not depend on Darwin FIFO polling support. Listener cleanup and deferred connection closes release all test-owned sockets.
