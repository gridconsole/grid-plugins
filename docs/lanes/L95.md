# L95: blocked-publication notice once per blocked state

Base: plugin main `aeb572c59170c4b5095880879bcc0f308d932522`.
Branch: `lane-L95`.

The orchestrator now writes publication notices through its injected
`Store.Diagnostics` writer. The CLI supplies `env.Stderr`; a nil writer
discards diagnostics. No orchestrator code or diagnostic test uses the global
logger. The original text is retained with an actionable approval command:

```text
plan publication skipped: workflow requires approval of the current plan; run grid approve before Jobs can post
```

The existing per-task orchestrator memory records whether publication is
blocked. The pass lock serializes both state transitions and notices, and
the state survives fresh Store instances and separate CLI invocations.
Older memory files default to unblocked, so their first blocked tick emits
the notice. The transition is saved before continuing the pass, so failures
later in the tick do not cause repeated notices.

Three blocked ticks emit one line. Editing a still-unapproved plan does not
emit another line. A tick that observes valid approval, a workflow waiver,
or no plan clears the blocked state; a subsequent blocked tick emits a new
line. Changes that occur entirely between ticks are not observed. Approval
checks and their task/plan locking remain intact. Migrated history alone
still cannot authorize new Jobs; the notice directs the person to
`grid approve`.

Implementation commit `beb35df` makes that test pass. The CLI test also checks
that JSON stdout remains valid and migrated approval history cannot publish
the new planned Job. Each tick constructs a fresh Store.

`TestPlanPublicationNoticeRepeatsOnlyAfterUnblocked` runs parallel subtests
for approval, workflow waiver, and plan removal. Each checks three blocked
ticks, an edit while still blocked, an unblocked tick, and three blocked
ticks again, with exactly one then two notices. Blocked ticks add no Feed
records or assignments, and approval/waiver allows publication. The existing
approval diagnostics test and its subtests now run with `t.Parallel()` using
private buffers, with no global logger changes. Independent fixtures also
exercise task-local suppression.
