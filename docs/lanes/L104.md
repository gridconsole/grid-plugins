## Behavior and tests

- Task `plan.md` anchors validate the exact text read using
  `task.ApprovedDigest`, `plan.Hash`, and `plan.Digest` before selecting text.
  This covers `step-N`, `verify`, other anchors, line ranges, and `task:` forms.
  No new digest implementation or second plan read is introduced.
- Plan anchors bypass the resolver's source cache, so a resolver reused between
  lint and render cannot reuse stale approval or hide a newly approved edit.
  Failure returns a clear `plan needs approval` error with no source text.
- Render's lint pass retains a distinct `job.plan-approval` finding. Both that
  finding and direct render approval errors produce exit 2 before bundle saving.
  Tests cover plain and JSON output and verify that no Job directory, brief,
  or input snapshot is created on refusal.
- Regression tests cover approved resolution, changed step prose after approval,
  refusal by fresh and reused resolvers, explicit reapproval, missing receipts,
  no partial rendered brief, and unaffected intent/repo/prototype anchors.
  Reapproval uses the real task approval writer with the current plan hash.
- This uses the existing approval compatibility policy: full-digest receipts
  bind canonical plan content; legacy receipts without a digest retain the
  shared helper's short-hash fallback. Checkbox and formatting canonicalization
  are unchanged. Previously saved briefs and replay snapshots remain snapshots.
