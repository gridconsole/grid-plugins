## Corrections

- `task.ApprovedDigest` shares receipt, task-state, identity, and gate validation
  with `Approved` through `checkApproval`, without reading `plan.md`.
  Publication computes the hash and digest from the exact text read inside
  `WithHash`, validates that snapshot, and publishes that same text. Locks
  serialize cooperative writers but do not supply the snapshot guarantee.
- A local reader seam replaces the plan immediately after the publication
  read. The changed-snapshot case restores the approved file before checking
  the receipt and must publish no Jobs. The reverse case replaces the file
  with changed content and confirms only the approved snapshot's writer Job
  is published. No sleeps, goroutine races, or process-global hooks are used.
- Full digests include step `evidence:` and `needs:` lines, including steps in
  `Where it stands`. Regression tests verify those lines reach worker anchors,
  change the digest while retaining the legacy short hash, block publication,
  and permit publication after reapproval. Task tests cover receipt creation,
  locked and lock-free reads, and refusal of implicit reapproval.
- The before-run condition uses a helper whose removal from the predicate
  leaves valid Go. Behavioral cases include approval before both `run` and
  `work`, and preserve delivery approval after either kind.

Implementation commits: `65775f5` (snapshot check), `a588b24` (step metadata),
and `92ff951` (mutation-testable before-run rule).

## Compatibility and limits

The six-digit hash remains byte-compatible with existing hash fixtures. The
64-digit digest is no longer necessarily prefixed by that hash because it also
covers step metadata. Existing full-digest receipts over plans containing
previously excluded metadata fail closed and require explicit reapproval.
Legacy receipts without a digest retain their weaker short-hash behavior.
Heading, checkbox state, status prose, line endings, and trailing whitespace
retain the established canonicalization. This change checks publication's
snapshot; it does not freeze mutable plan anchors for subsequent worker reads.
