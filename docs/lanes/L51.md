## Built

`feed.ErrInvalidRecord` and `feed.InvalidRecordError` classify rejected content
without changing its diagnostic. The wrapper retains the original error for
`errors.Is` and `errors.As`. Feed, Handover, MCP, Orchestrator, and internal API
callers share the same validation points. `exitCode` maps stale leases and
invalid records to 3, disk full to 4, and other failures to 1. Flag parsing
still returns 2, and successful writes still return 0.

`grid feed post|handover` and `grid job post|ack|result|cancel` use the shared
mapping. Identical worker-exit retries keep returning 0. Duplicate Job wakes
keep printing the first record ID and returning 1. MCP still returns an
`isError: true` tool result with the same error text.

The Run comment, top-level help, Feed help, Job help, `docs/feed-mcp.md:72`,
and the exit-code sentence beside the intent documentation in
`contract/README.md` describe the codes. Job help is owned by
`internal/job/jobcmd/command.go:54`; its usage string received only the requested
exit-status footer. This is the one additional implementation file needed for
the explicitly requested Job help update. In `internal/cli/orchestrator.go`,
only the `fail` closure changed: it classifies the existing exact non-object
body diagnostic before using `exitCode`, keeping the closure-only lane boundary.

## Intended differences and limits

The old shell front end exits 1 for malformed JSON and failed tool calls
(`old-plugin/bin/grid-feed:41`, `:53` in the reference tree). This lane makes
invalid record writes final at status 3 while retaining today's Go CLI
messages. It supersedes only the validation portion of the old implementation
wording in `docs/lanes/L5.md:34`; stale tenure remains 3 and disk full remains
4. Job writes now honor the same final-rejection and disk-full mapping as Feed,
consistent with refusal of late Job results in `docs/feed-contract.md:198`.
The help footer and documented invalid-body classification are new. No record
shape, wire encoding, retry identity, schema, reader verdict, or MCP protocol
behavior was intentionally changed. Disk-full CLI integration is limited to
the shared mapping plus the existing Feed write seam as described above.
