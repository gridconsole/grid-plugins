## What changed

- `internal/project/project.go`: new `KeepOtherKeys(canonical, old)`. `Format` is untouched, so a file with no other key is written exactly as before. With other keys, it loads the old front matter as a YAML node tree, keeps every key Record does not model with its value (comments on those keys too), in the order the old file had them, and puts the keys of Record, as `Format` wrote them, in their place: a key of Record that was in the file keeps its place; one that was not goes after the nearest key of Record before it in `id folders repos keys` order, or before the first one after it, or first when the file has none; one that is now empty is dropped, as `omitempty` does today. The list of owned keys is read from the yaml tags of `Record`, so a new field of Record is owned without a second list.
- `internal/projects/projects.go`: `Store.write` calls `project.KeepOtherKeys(data, old)` before it appends the old body (that loop is unchanged: it takes everything after the first closing `---` line, so a `---` line in the body is kept). If the old front matter is not valid YAML, `write` returns an error and does not overwrite the file.
- `internal/projectmd/projectmd.go:80`: the comment now says what holds: the lock orders this edit and a relink, and a relink keeps every key it does not own.
- Tests: `internal/projects/gk_keys_survive_test.go` (new) and `TestGgSetBesideRelink` with `ggRunChildrenDuring` in `internal/projectmd/gg_set_concurrent_test.go`.
- No change to the file format: the output has the same keys, the same layout (`Format`'s) and the same body; `project.Parse` of it, and so the binary of main, reads the fields it knows the same.

Side effects, same as `projectmd.Key` already has: a list in another key is written in the layout of the writers (`- a` at the start of the line), not as the person indented it; a comment on a key of Record is dropped as before.
