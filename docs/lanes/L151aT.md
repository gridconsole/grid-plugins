# L151aT: a task.md write may not change any header value it did not set

Base: lane-L151aS 3c114f19 (on ref/main af68c214). Branch lane-L151aT. Code head 2dd1d2bb; the final head differs from it by this report only.

## Why
L151aS compared the reader's `workflow` and `Odd` before and after `rewriteTask`. The review (L151aS, note 1) found the same hole through `step`: a held inline-list task with `step: plan` and an indented `  build` line reads as step "plan" (the reader takes a value from its key's own line), the YAML dump joins it into `step: plan build`, and `grid task status <id> running` (Change) released the plan hold: planStage went from "gate" to "past". `step:` with the value on the next line did the same for a task held as "unreadable", and `size:` with the value on the next line read "" before and "large" after.

## Changed
- internal/task/write.go `rewriteTask`: the keys whose value node the edit replaced or added are the keys it set. After the dump the output is parsed again and the reader's value of every other key (present in one header only, or another value or type) must be the same; the first difference, in name order, refuses the write and writes nothing. The error names the key and the fix: `task.md key "step" would read differently after this write; put its whole value on the key's own line (no indented continuation lines) or remove the key, then retry; nothing was written`.
- `workflow` and `Odd` keep their L151aS checks, first and with their texts: `workflow` is compared even where the edit sets it, so no existing refusal is loosened. The new compare comes between them.
- Rows, new files only, no existing test line edited: internal/task/write_header_test.go and internal/guard/write_hold_test.go.

## Open
- A task whose header has a value the reader cannot see in full can no longer be closed (Change) or delivered (Deliver) until it is fixed by hand; the error names the key and the fix. Probed forms: a list at column 0 under any key, and a wrapped plain value (`title: a`, then an indented `b`). Quoted, escaped, folded, block, commented, aliased and tagged values are not refused.
- Not changed: Rename (patchTaskFields, which rewrites only the key it sets) and the guard. An agent Edit that adds the hidden continuation line is still allowed by `leavesPlan` (the reader's step does not change); it is the writers that now refuse to act on it.
