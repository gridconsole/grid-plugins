# L43: task lease commands

The existing `grid lease` command now accepts `task` for take, release and status. Merge lease behavior is unchanged. Task commands use the existing Feed resolver and writer identity, so the task must already have a stable ULID in `task.md` (`id` or `ulid`).

```text
grid lease take task --task T-07 --project example --pid <pid> --pid-start <RFC3339>
grid lease take task --task T-07 --project example --session <session-id>
grid lease status task --task T-07 --project example --json
grid lease release task --task T-07 --project example --epoch 0.1
```

Task and project flags are optional when the current task resolves. Take requires an explicit process identity or a registered local session. It never defaults to the parent shell's pid, and it refuses an identity that `session.ProbeLocal` does not report alive on this host: `task lease take refused: pid <pid> started <start> is not a live process on this host (dead|unknown)`, exit 1, nothing written. Handwritten start times must be RFC3339; storage uses UTC, milliseconds and `Z`. Legacy session process tokens are converted only after proving that the recorded process identity is still alive. `session.ProcessStart` runs `ps` with `LC_ALL=C` and `TZ=UTC`; its timestamp round-trips through `ProbeLocal` at second precision.

Successful take prints:

```text
task lease taken, fence 1
epoch 0.1
```

The epoch is passed to subsequent Feed and Orchestrator commands as `--lease-epoch`. Take JSON contains `lease`, `holder`, `gen`, `fence`, `since` and `adopted` (null or `session-gone`). Release requires the exact holder, generation and fence. Releasing a free task lease, never taken or already released, prints `no task lease is held`, exits 1 like a merge release that does not hold the lease, and creates no lease file. Status includes holder, generation, fence, since, pid and process state: `alive`, `dead`, `unknown`, or `remote`. A free lease prints `task lease free`.

## Grant, adoption and recovery

`TaskStore.AdoptTask` checks the old holder's machine and probes its pid/start pair while holding the task lease's exclusive lock. Only `Dead` permits adoption. Live, unknown and remote holders remain held. The existing tenure-end log and shared fence counter are reused, and the current generation is preserved by the CLI.

A new task holder posts `handover` as its first Feed record. Adoption includes `adopted: session-gone` and `from`. `old_fence` is omitted because `contract/schemas/handover.json:30-63` does not allow it. The old fence remains in the takeover log.

`feed/lease/task-take.lock`, opened and locked through `internal/fslock`, serializes CLI takes through their handover posts. This prevents a concurrent taker from mistaking an in-progress grant for a failed handover. Its contents retain the granted fence and handover body as retry metadata, written through `TaskStore.BeforeTaskGrant` under the lease lock after the fence is chosen and before the tenure is written; this file grants no authority. The lease owner still validates and probes under the lease file's own exclusive lock. Neither lock file is replaced or removed.

If handover fails after a grant, take prints the grant and error, exits 1, and retains the lease. A retry by the same member with the same pid and start consults the Feed: if that tenure has no counted handover, it posts the missing record without advancing the fence. Another process of the same member is a new taker: it is refused while the holder lives and adopts it once it is dead. Completed handovers cause subsequent live-holder takes to be refused. Only a lease held error from take leads to adoption; any other take error is reported as it is.

Tests cover contract validation, a live real process, a reaped child's identity, remote and unknown refusals, takeover snapshots, exact-epoch release, local/remote status, session resolution, handover failure and retry, and concurrent takers in two goroutines and two re-executed test processes. A store test verifies that release cannot pass the adoption probe while it holds the lease lock. Linux and macOS run the tests; Windows is cross-built only.

The reachability test creates a task and writes a checklist plan with one Job. It explicitly supplies a stable ULID fixture, takes the task lease through the CLI, checks that `job next` passes its lease check, publishes the Job through `grid feed post`, then observes the assigned J-1 row using the printed epoch. This is not the exact four-command acceptance sequence; see the prerequisites below.

## Remaining integration prerequisites

- `task new` currently writes only the display ID (`internal/task/create.go:76-110`). The shared Feed resolver requires a stable ULID (`internal/cli/feed.go:190`, `internal/feed/identity.go:54`). Fresh tasks therefore cannot take a task lease without that metadata. Task creation is outside this lane's listed files; no second task metadata writer was added.
- `plan write` stores the plan without publishing Feed Jobs (`internal/cli/plan.go:100-118`). The Orchestrator loads Jobs exclusively from Feed (`internal/orchestrator/ready.go:29-58`). Returning a ready Job from the exact requested sequence still needs that integration. Orchestrator and Job code were left unchanged.
- Windows cross-compiles and take refuses with `task lease needs a Unix host for process identity`. However, runtime status of an existing lease and release remain blocked by the existing Windows `fslock` stubs (`internal/fslock/fslock_windows.go:7-12`). Those return `ErrUnsupported`; the protected package was not changed and no alternate lock implementation was introduced.

## Spec decisions

1. No default pid. Take requires `--pid` plus `--pid-start`, or `--session`, and the identity must probe alive. A short-lived parent shell is not implicitly made holder. This follows the lane default and the process-identity requirement in reference `docs/feed-contract.md:100,212`.
2. No local forced takeover of a live holder. Live, unknown and remote holders are refused. A person's 15-minute takeover requires server-observed offline time and remains outside this CLI (`docs/feed-contract.md:116,214,218`).
3. Both lease reading paths remain: `lease.ReadJob` and `TaskStore.Read`. Unifying them is L34 review should-fix 6 and was explicitly excluded from this lane (`internal/lease/job.go:28-32`, `internal/lease/task.go:83`).
4. Remote status prints `remote`; remote holders are never probed or adopted. This retains the boundary requested for L34 review should-fix 5 (`docs/feed-contract.md:116,214`).
5. Handwritten start times are RFC3339 and stored with `contract.FormatTime`. `proc:` and raw `lstart` strings are never persisted in a task lease (`contract/schemas/lease.json:94-98`). Registered legacy sessions are converted only after verifying their process identity.
6. Adoption omits `old_fence`: the unchanged handover schema permits `from` and `adopted` but forbids additional body fields (`contract/schemas/handover.json:30-63`). The old tenure fence is recorded in `lease/takeovers.jsonl`.
7. Take refuses unsupported process-identity hosts. Windows runtime release/status support requires the existing lock package to support Windows; cross-compilation alone does not provide that support.

## Intended differences from the old plugin

The document references below name the read-only reference specifications; they are not new local copies.

| Difference | Old behavior and governing reference |
| --- | --- |
| A locked lease file grants authority and a monotonic fence; handover announces the grant. | Old `feed/lib.mjs:238-285,335,447-451` derives authority and epoch from ordered handovers. Reference `docs/feed-contract.md:94-124` requires lease-file authority, a fence counter and tenure-end snapshots. |
| Task ownership names an explicit long-lived process or registered session, with pid and actual process start time. | Old `feed/lock.mjs:24-38,49` uses process liveness, host and freshness of the loop lock. Reference `docs/feed-contract.md:100,202-218` requires pid/start identity and treats failed checks as unknown. |
| Only proven same-host death permits automatic adoption, and its first post says `adopted: session-gone`. | Old `feed/lock.mjs:43-66` reclaims locks deemed stale. Reference `docs/feed-contract.md:116-124,214,218` reserves remote/live takeover for server authority and forbids using age alone. |
| Release checks holder, generation and fence and records the tenure's end before clearing the holder. | Old `feed/lock.mjs:72-73` removes the loop lock when its pid and started stamp match. Reference `docs/feed-contract.md:100-110,118-124` requires a released null holder and a takeover-log snapshot. |
| Shell users receive a granted fence and reusable `gen.fence` epoch; held takes exit 1 and identify holder/since. | Reference `docs/feed-contract.md:305-310` establishes lease output wording. This lane applies it to task scope and adds the explicit epoch needed by the existing Orchestrator CLI. |

## Rework

The review rejected the first landing: `make test` failed on a timing bug in a lane test, and it listed six should-fixes. Rebased onto main b008485, which includes 2f70ab2 (non-blocking exclusive lock in `fslock`); every L43 lock call still uses the blocking `LockExclusive` and `LockShared`. The conflicts were the `job` and `lease` help lines in `internal/cli/cli.go` and main's merge lease holder checks in `internal/cli/liveness.go` and `liveness_test.go`; both sides are kept. The `--holder` check applies to merge leases only, because `lease ... task` is dispatched before it.

1. Flaky `TestTaskAdoptionAndRelease/dead_local`. It passed `time.Now()` as the holder's process start and then compared the probe input to `Since`, a second `time.Now()` inside the store. The test now pins the store clock through `TaskStore.Now` and captures the start once, an hour before that clock, and compares the probe input to it.
2. Take refuses a pid and start that `session.ProbeLocal` does not report alive, for `--pid`/`--pid-start` and for a registered session alike, with the error above. Before, a wrong pair was stored as given and a second taker on the host could adopt the live holder. Test: `TestTaskLeaseTakeRefusesIdentityNotAlive` (wrong start, reaped child, session with a wrong start).
3. Handover recovery after a failed post matches the member, the pid and the start of the tenure, not the member alone. Test: `TestTaskLeaseRecoveryNeedsTheGrantedProcess`.
4. The adoption retry details (`adopted: session-gone`, `from`) are saved in `task-take.lock` by `TaskStore.BeforeTaskGrant`, after the fence is chosen and before the tenure is written, so a crash after the grant leaves them for the retry. Tests: `TestTaskLeaseAdoptionSurvivesACrashBeforeItsHandover` (a re-executed take exits through the `afterTaskGrant` test hook right after the grant; the retry posts session-gone from the old holder) and `TestTaskGrantPreparesBeforeTheTenure` (the hook runs before the tenure is written, and its error grants nothing).
5. Releasing a free task lease returns `lease.ErrTaskFree` (`no task lease is held`), exits 1 and creates nothing; before, it created an empty `lease/task.json` and printed `held by nobody since  (epoch 0.0)`. Tests: `TestTaskLeaseReleaseFree`, `TestReleaseFreeTask`.
6. Take falls through to adoption only when `TakeTask` wraps `lease.ErrTaskHeld`; any other error is printed as it is. Test: `TestTaskLeaseTakeReportsGrantErrors` (a fence counter that cannot be opened).
7. The completion report that sat in a root `DONE.md` is folded into this file.

Each new CLI test was run once against the L43 head before the rework, 385e7fa on main 793152b, in a detached worktree (its task lease code is unchanged by the rebases; that head is now 7816250 on b008485), with only the new test file copied in plus the one-line `afterTaskGrant` hook placed at the old crash point, after `AdoptTask` and before the retry metadata write. All five failed: the other process recovered the grant (`other process: 0 task lease taken, fence 1`); the retry posted an empty body (`retry lost the adoption: ... Body:map[]`); the three wrong identities were taken (`take: 0 task lease taken, fence 1`); the free release printed `held by nobody since  (epoch 0.0)`; the counter error was reported as `task lease held by nobody`. The two store tests use the new `BeforeTaskGrant` and `ErrTaskFree` and do not compile on the old code; the CLI tests above cover the same behaviour.
