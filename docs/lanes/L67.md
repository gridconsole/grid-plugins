# L67: Personal access for host callers

Base: `f39661a`, branch: `lane-L67`.

`where.Resolver` now carries `Role` and an optional `PersonalAllowed` predicate.
Successful explicit and implicit resolutions meet at one final check. A denied
Personal result returns an empty result and the exported, `errors.Is`-compatible
`ErrPersonalRefused`: `this caller cannot use the Personal project`. The refusal
contains no path. Task paths, task IDs resolved within Personal, and implicit
Personal fallbacks all pass through this check.

The nil predicate uses `DefaultPersonalAllowed`: only the empty local CLI role
and exact `owner` are allowed. Members, guests, and unknown roles are refused.
This is an overridable default: a host or workflow can supply its own predicate,
including one that allows members or refuses owners. Future workflow wiring
should use `personal_roles`, following L60's `gate_post_roles` override pattern
in `internal/workflow/gates.go` (inspected in the L60R checkout). This lane reads
no workflow file.

The shared CLI resolver receives `strings.TrimSpace(env.getenv("GRID_ROLE"))`.
The only CLI production edits are this field and the required `strings` import;
command registrations and exit-code handling are unchanged. `grid where`
refusals exit 1, emit the message to stderr, and leave stdout empty.

Project lookup still accepts only an exact record name or ID, including for
nonempty roles. Unregistered names and case variants of registered names fail;
the existing case-insensitive Personal selector remains subject to the guard.

## Rework

L67R supersedes the role-only policy and the failing-suite status above. Started
with the requested reset to `origin/lane-L67` (`1d27177`), then rebased onto the
supplied `origin/main` (`a47b063`), producing base `58f5549`. The referenced
`decisions/personal-access.md` is absent from this checkout; this rework follows
the caller decision stated in the brief. No workflow file is read by the policy.

`where.Caller{Role, Member}` replaces `Resolver.Role`; `CallerFrom` trims both
host environment values. The default lowercases the role and uses
`contract.TierFor`: guests and external callers are refused; owners are allowed;
member/lead callers are refused only with a nonempty member identity; every
agent-tier role, including empty, cli, worker, builder and unknown, is allowed.
`PersonalAllowed func(Caller) bool` remains replaceable. The future workflow key
is `personal roles:`, to be wired after L60R and L68, not the earlier
`personal_roles` spelling in the historical report.

`PersonalOK` and `TasksDirs` centralize the policy. Task resolution no longer has
a Personal shortcut. Task ID lookup, environment Job lookup and hook brain
lookup use the filtered roots. CLI brain and signal stores receive the shared
resolver; guard settings stamp both caller fields. Project listing filters
Personal, including a stored Personal record. Explicit Personal record IDs are
also refused before looking up a task.

Explicit Personal names, regardless of case, fail before project lookup. Where
uses `project %q is not registered` for unavailable projects, without a data
path. Task commands map that error to `project is not registered`, making
`task list --project personal` and `--project nosuch` byte-identical. Refused
callers get `task not found` for missing task IDs, including IDs held only in
Personal. Explicit Personal task paths are refused before filesystem lookup;
implicit Grid-home and Personal-task cwd still return `ErrPersonalRefused`.
The bare task-ID lookup never falls back to reading Personal for those callers.
An ID shared by alpha and Personal resolves to alpha.

Two small implementation details are needed by the requested surfaces:
`brain show` and `brain search` now accept `--task` (previously only `keep` did),
and brain's existing fact-only package callers retain their environment defaults
without replacing a supplied caller policy. The only touch-list exception is
removing the unused `strings` import from `internal/cli/cli.go`, outside its
resolver function, after moving trimming into `CallerFrom`. No module file,
workflow implementation, exit-code helper, intent code, feed code or root
DONE file was changed.

No L64 lane/ref or named landing was identifiable in the supplied main history.
For the lander coordinating L64, preserve the two integration lines:
`internal/guard/settings.go:34` stamps `CallerFrom` from the guard environment;
`internal/hook/brain.go:85` calls `o.Resolver.TasksDirs()`. Only that one hook line
changed. The project-to-Personal task symlink note and workflow policy loading
remain out of scope.
