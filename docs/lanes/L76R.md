## Deterministic concurrency regression

Implementation commit: `3eba781`.
`TestConcurrentFirstWritesKeepOneTaskULID` now lives in
`internal/feed/identity_concurrent_test.go` in package `feed_test`. It still
runs `question.Store.Add` against a direct `feed.Store.Post`, both starting with
legacy metadata. Moving it permits a test-only export bridge in
`internal/feed/export_test.go`; no production API exposes the hooks.

`beforeTaskIDLock` is unexported and nil in production, immediately before
`.task.lock` acquisition. The test installs a two-party barrier there, so both
writers meet before either acquires the lock. A pre-lock barrier alone cannot
force overlapping reads after lock removal. Therefore a second unexported,
nil-by-default hook, `afterTaskIDRead`, probes the lock with a separate file
descriptor after reading the metadata and requires `fslock.ErrLocked`. This
checks that the metadata read is protected independently of scheduling. The
barrier's timeout only diagnoses a missing participant; no sleep determines
whether contention succeeded. Hooks are restored after both writers finish.

The test also verifies one persisted ULID, unchanged other metadata and file
permissions, a stable identity on the next write, and three admitted Feed
records carrying that same identity.

Command for both variants:

```sh
go test -json -race -count=30 -run '^TestConcurrentFirstWritesKeepOneTaskULID$' ./internal/feed
```

Counts from test-level JSON pass/fail events:

| Variant | Passed | Failed | Command exit |
| --- | ---: | ---: | ---: |
| Lock present | 30/30 | 0/30 | 0 |
| M1: remove only EnsureTaskID's LockExclusive block and deferred Unlock | 0/30 | 30/30 | 1 |

M1 reports `task metadata read without the task lock: probe = <nil>`.
The lock was restored byte-for-byte before the package suites and builds.
