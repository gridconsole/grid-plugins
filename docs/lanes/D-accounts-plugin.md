# D-accounts-plugin: `grid account` in the plugin

Base: plugin main f9602370. The decision is D-accounts-decide item 5 and 6, read from the app bundle's ref copy (the bundle needs app base d327090, so it was read with `git show` from the app reference repo).

## What changed

- New `internal/account/`: `Scan`, `MakeFolder`, `SignIn`, `Note`, `Windows`, `Status` and a small registry. No guard, gate, cap or limit anywhere; nothing removed.
- New `internal/cli/account.go`, and the `account` line of `internal/cli/cli.go` now has a handler. `contract/commands.json` was regenerated by `make generate` (the repo's target; it runs the env-prefixed test itself, no env-prefixed command was typed). It lists `account` as built with 7 subcommands.
- `internal/cli/contract_inventory_test.go`: seven lines added to the route annotation table (`account list|status|scan|folder|windows|note|sign-in`). The inventory test fails without them. No existing test line was changed or removed. This file is outside the brief's owned list; it cannot be avoided.

Commands (all take `--json`):

| command | answer |
|---|---|
| `scan` | `{folders:[{kind, dir, home, signedIn, email, plan}]}`. Folders: `~/.claude`, `~/.claude-*`, `~/.codex`, `~/.codex-*`, and `$CLAUDE_CONFIG_DIR` / `$CODEX_HOME` when outside that list. Email: `claude auth status` (env set through `exec.Cmd`, unset for the home folder), then `.claude.json` `oauthAccount.emailAddress` (`~/.claude.json` for the home folder). A signed-out folder has no email. Codex: the `email` claim of `tokens.id_token` in `auth.json`; only the email and plan are kept. `.credentials.json` is never opened. |
| `folder --kind K --id ID` | `{dir, created}`. Makes `~/.<id>` (0700) and, off Windows, symlinks `settings.json CLAUDE.md agents commands skills` (Codex: `config.toml AGENTS.md`) from `~/.<kind>`. Idempotent. The id must be `<kind>-<name>`, so it cannot make `~/.ssh`. |
| `status` | The brief's registration. Scans, registers each login email not seen before (once, lower-cased match, under a file lock), makes its folder when it was seen on `~/.claude` or `~/.codex`, and answers `{accounts:[{id, kind, name, email, dir, default, signedIn, checked, plan, added}]}`. `default` is derived on every call from the email on the home folder and is never stored. |
| `list` | The same answer from the registry, writing nothing. |
| `note [--dir D]` | Reads status line JSON on stdin and keeps only `rate_limits` in `<grid home>/accounts/windows/<sha8 of dir>.json`. A payload with no window writes nothing. |
| `windows [--id ID]` | `{accounts:[{id, kind, windows:[{label:"5h"\|"7d", used, resetsAt}], asOf?, source, note?}]}`. No snapshot: `source:"none"`, `windows:[]`, a `note`, and no `used`. A passed `resetsAt` gives `used:0`. |
| `sign-in (--id ID \| --dir D --kind K)` | Runs `claude auth login` or `codex login` with that folder's variable (unset for the home folder), streaming its output. Errors carry `bad_folder` and `no_agent`. A non-zero provider exit gives exit 1. |

Registry: `<grid home>/accounts/registry.json`, records `{id, kind, name, email, dir (as ~/...), added}`. Id is `kind-slug(local part)`, with `-2`, `-3` for another email of the same local part. Name is the email, or the local part over 40 characters.

Credentials (row 3): the code never reads `.credentials.json` and never touches the Keychain. Grid files hold emails, folder names and use numbers only. Same code on macOS and Linux: the provider writes its own credential when the person signs in on the new folder (Keychain entry keyed to the folder on macOS, `.credentials.json` in it on Linux). Tests `TestNoSecretReachesAGridFileOrTheNewFolder` and `TestAccountWritesNoSecretToTheGridHome` plant secrets in `.credentials.json`, `.claude.json` and `auth.json`, run status, folder, note and windows, and search the Grid home and the new folders.
