## Changes and retained behavior

Delete now enumerates through `s.Resolver.TasksDirs()`, matching other task
writes and honoring the caller-policy choke point. Explicit project selection
already delegates through `s.resolve`, including restore, and remains unchanged.
The trash fixture and its two replacement-task creations now provide `Cwd`, as
main's resolver requires; production resolution is not relaxed. The added test
denies an otherwise allowed owner through the resolver's replaceable Personal
policy and checks that home-wide delete, explicit delete, and restore leave the
task in place.

All accepted L80 tests remain. Allocation/task/lease lock ordering, owner and
person guards, project-name/id selection, symlink refusals, timestamp ordering,
same-minute and occupied-id refusals, and history-after-rename semantics are
unchanged. The existing task lock and lease coordination code is untouched.

The inventory records each command's required task operand, JSON support, and
project flag, required only for restore. As with rename/decline, the output
schema annotation is empty because no dedicated command schema exists; the
existing CLI tests retain coverage of the `{project,id,folder}` JSON result and
plain folder output.

The host guard change is exactly the plain alternation addition
`|delete|restore|rename|decline` after `stop`. Existing host-gate test cases now
exercise those four verbs through the shared shell-command matrix.
