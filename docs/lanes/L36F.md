## Changes

- A scheduled `run --due` whose definition no longer matches its approval now calls the existing failure signal. Its Personal note includes the refusal and `grid routine schedule` approval instruction. The entry's `last_run` and outcome stay unchanged, so repeated timer wakes reuse the existing SourceID and produce one note. Signal write errors are returned alongside the refusal. Manual runs keep their existing behavior.
- Launchd now uses `StartInterval` with an integer value of 60. Its plist includes `StandardOutPath` and `StandardErrorPath` under `<GridHome>/logs/routines/<timer-label>/`, using `stdout.log` and `stderr.log`. Scheduling creates the folder with mode 0700 before registration. Re-run `grid routine schedule` in each installed scope to refresh existing plists. Unscheduling retains logs.
- Task Scheduler XML is written as UTF-16LE with a BOM and a matching XML declaration. Ownership checks and unchanged-file comparisons understand the encoding, and ownership checks still accept the earlier UTF-8 files. Human and JSON previews retain readable text and identify the required encoding.
- `grid routine --help` and subcommand help explain that execution holds the entry lock and another run, schedule or removal of that entry waits.
- Scheduling and Windows previews reject Grid home paths with leading or trailing whitespace before acquiring locks, writing files or invoking an OS command. The diagnostic names Grid home and the whitespace restriction. Spaces inside a path remain supported.

## Intended differences from the old plugin

References below are to the read-only reference tree. L36's inherited differences and deferred integrations remain documented in `docs/lanes/L36.md`.

- Changed-definition refusals now use the Go Personal/Home signal writer as execution failures already do, including its existing deduplication identity; the old plugin used the signals skill and Node writer (`old-plugin-map.md:63,115`; `docs/plugin-design.md:460-462`). Keeping the old `last_run` is deliberate: a refused timer did not execute a run.
- The minute launchd trigger, retained local stdout/stderr, and UTF-16 Task Scheduler output implement the optional local OS schedule rather than restoring the old application scheduler (`docs/plugin-design.md:455,460`; `docs/go-architecture.md:33`). The per-routine log layout is an implementation choice; the architecture specifies separate binary logs but does not prescribe routine filenames (`docs/go-architecture.md:386`).
- Entry-lock help describes the existing serialization required for routine runs; it introduces no alternate lock (`docs/plugin-design.md:460`).
- Grid home edge whitespace is intentionally refused for scheduling on every backend, including previews, to keep a shared path contract when systemd strips surrounding whitespace from `WorkingDirectory` (`docs/plugin-design.md:455,460`). Interior spaces and non-ASCII paths remain supported.
