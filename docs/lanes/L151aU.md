# L151aU: keep untouched header bytes, and hold Deliver on an unapproved plan

Base: lane-L151aT 29297521 (on main af68c214). Branch lane-L151aU. Code head c40e14ed; the final head differs from it by this report only.

## Why
L151aT review, must-fix 1: `grid task new` with an emoji title, then `grid task rename`, then Deliver or close was refused (`task.md key "title" would read differently`). Rename writes the title with its literal characters; the whole-header dump in `rewriteTask` spelled a non-BMP character as `\UXXXXXXXX`, which the plugin reader does not decode, so the compare saw a changed key. Must-fix 2: `Deliver` set `step: ship` without asking whether the plan was approved, so on a held task in queued, running, stuck or reworking it moved the stage past the plan gate.

## Changed
- internal/task/write.go `rewriteTask`: the edit still runs on the YAML nodes, but the output is built from the original lines. A key the edit set keeps its place and is rewritten as its own entry (dumped alone, same options, so `state: running` looks as before and a same-line comment stays); a key the edit added goes after the header; a key the edit removed loses its lines; every other header line keeps its bytes, comments and line endings included. A value changed in place is refused (it would be lost with its lines kept). Block mappings only, as Rename already requires.
- The L151aT compare is kept and still runs on the output (`sameWorkflow`, `changedKey`, Odd). It also still runs on a whole-header dump for the keys that are wrapped over several lines (a list at column 0, a continuation line, a flow list on the next line): the reader reads those differently from YAML, so the write stays refused until a person fixes the header, with the same texts. A key of one line is not judged by how the dump would spell it, because its line is kept byte for byte and the reader sees what it saw.
- internal/task/hold.go (new): `PlanStage`, `HeldStage` and `PlanHeld`, moved from the guard. internal/guard/context.go `planStage`, `heldStage` and `held` now call them, so the guard and Deliver share one function.
- internal/task/deliver.go: `check` ends by asking `PlanHeld`; a held plan is refused with `ErrPlanNotApproved` (`plan not approved: T-NN waits for a person to approve its plan, and delivery would move it past that gate`). It is asked last, so the faults the agent can mend itself (proof, brain proposals, files) are named first, as before. It serves the dry run and the re-check under the locks.
