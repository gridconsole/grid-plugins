# L43F: task lease follow-ups

Completed on `lane-L43F`. The exact fresh-home command sequence now assigns a planned Job, invalid task writers exit 2 before lease storage is created, and CLI release serializes with take through `task-take.lock`.

## Base and integration

`main` was `f39661a`. It contained an older task acquisition command, but not L43's automatic adoption, release, process identity checks, or take lock. Applied the requested fallback: reset to `origin/rework-L43` (`2f012d8`) and rebase onto `origin/main`.

Resolved conflicts in the lease store, its tests, and the command table. Kept main's Job ID and lease identity validation alongside L43's adoption/release implementation. Removed the superseded `task_lease.go` wrapper and its tests for the old explicit `--adopt`/`--takeover` interface; the L43 liveness tests exercise the replacement interface, process checks, adoption refusals, concurrent takes, and recovery. Updated the failed-grant test to expect main's rejection of an empty lease file. The existing module, Makefile, and unrelated untracked workspace files were preserved.

## Changes

- `task new` writes a random stable ULID in `task.md` in the same staged write as the display ID. Existing display IDs and CLI output stay compatible. Task creation's golden test validates and normalizes the new ID. The hook result fixture now uses the generated task identity instead of replacing its display ID.
- A leased scheduler pass publishes missing planned Jobs before computing assignments. It uses the existing plan decoder, Job record projection, contract validator, review floor, and dependency graph. The task lease and orchestrator lock serialize publication and assignment. All new Jobs and the combined graph are validated before any publication. Repeated or interrupted passes publish only missing IDs; already published Jobs retain their Feed definition and lifecycle when the plan changes.
- `runTaskLease` checks `contract.ValidWorker(writer.Worker)` immediately after resolving the writer. A slash or whitespace in the member name returns usage exit 2, leaving `feed/lease` absent, including its lock file.
- Release takes the same exclusive `task-take.lock` used by take, before changing `task.json`. The lock remains held across take's held check, adoption, and first handover post. A preliminary read preserves free-release behavior without creating storage; the store still rechecks the exact holder and epoch under its own lock.

Plan publication deliberately happens at `job next`/`feed tick`, after the task lease and handover exist. `plan write` still saves the plan without manufacturing authority. A malformed new Job prevents a scheduler pass until corrected. Edits to published Job IDs do not replace their existing Feed records.

## Regression evidence

`TestTaskLeaseFreshHomeSequence` starts with an empty temporary GRID_HOME and invokes the real `Run` command table exactly four times:

1. `grid task new ... --json`
2. `grid plan write <draft>`
3. `grid lease take task --pid <live pid> --pid-start <actual start> --json`
4. `grid job next --lease-epoch <returned epoch> --json`

It requires J-1 to be assigned and the first Feed record to be the handover. There is no injected task ID, store grant, or extra Feed publication command. This replaces L43's fixture-assisted reachability test.

`TestTaskLeaseInvalidMemberCreatesNoLeaseDirectory` checks slash, space, and tab member names. Each failed take must return 2 and leave the entire lease directory absent.

`TestTaskLeaseReleaseBetweenHeldCheckAndAdoption` pauses take after `ErrTaskHeld`, then starts release. A barrier at release's lock acquisition uses `TryLockExclusive` to prove contention on the held take lock before adoption resumes. There are no sleeps establishing the order; five-second timeouts are deadlock guards. Adoption succeeds, the old release is refused, and the new process/fence remains held.
