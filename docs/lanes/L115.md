## Problem and result

L109 classified every workspace budget write failure as caller input (exit 2,
the app's 400 path). `SetWorkspaceTokens` now wraps exported
`ErrWorkspaceTokensInput` only for a zero token budget. `runWorkspaceBudget`
uses `errors.Is` to keep that case at exit 2 and returns exit 1 for every other
store error (the app's 502 path). All diagnostic text remains unchanged.
Authorization still runs before workspace access, flag validation still runs
before authorization, and show still reports no default for a bad file.

The contract now documents invalid flags and amounts as exit 2, refused roles
as exit 3, and unsafe files, size/encoding/front-matter failures, lock failures
and write failures as exit 1 with the workspace unchanged.

## Scope and policies

Only the six permitted files changed. The necessary standard-library `errors`
import is the only edit outside `runWorkspaceBudget` in the CLI production
file. No data source, response fields, locking, storage or authorization
behavior changed. No changes to notice.go, task_write.go, persongate, workflow,
task.go, go.mod, or generated files; no root DONE.md.

The existing replaceable defaults remain:

| Policy | Workflow key | Default allowed roles |
| --- | --- | --- |
| `WorkspaceBudgetReadAllowed` | `token_limit_read_roles` | empty local role, owner, member |
| `WorkspaceBudgetWriteAllowed` | `token_limit_write_roles` | empty local role, owner |

Guest and unknown roles fail closed before workspace access. No owner prompt
or workflow-loader change was introduced.

## Tests and changed assertions

Two new top-level tests, with six subcases:
`TestWorkspaceBudgetInputError` verifies the wrapped sentinel, unchanged text,
and non-input classification of missing-home set/clear failures;
`TestWorkspaceBudgetStoreErrorsCLI` directly exercises the helper's zero input,
missing-home failure and guest refusal. Calling the helper directly is necessary
because flag validation rejects zero before the store is called.

`TestWorkspaceBudgetRefusalsCLI` now has 16 subcases: set and clear for linked,
directory, invalid-utf8, unparsable, oversized, lock-directory, read-only-home,
and read-only-home-no-lock. The latter three are six added subcases. The
read-only cases cover both saving with an existing writable lock and failing
to create a missing lock. They ran under unprivileged Unix permissions; they
skip on Windows or root where those permissions cannot establish the failure.
Every refusal checks exact single-line, path-free stderr, empty stdout, unchanged
workspace identity/mtime, and unchanged bytes for file inputs (including the
symlink target). The directory stays the same directory.

Every changed pre-existing exit assertion is named here:

- `TestWorkspaceBudgetRefusalsCLI/linked/set` and `/linked/clear`: 2 to 1.
- `TestWorkspaceBudgetRefusalsCLI/directory/set` and `/directory/clear`: 2 to 1.
- `TestWorkspaceBudgetRefusalsCLI/invalid-utf8/set` and `/invalid-utf8/clear`: 2 to 1.
- `TestWorkspaceBudgetRefusalsCLI/unparsable/set` and `/unparsable/clear`: 2 to 1.
- `TestWorkspaceBudgetRefusalsCLI/oversized/set` and `/oversized/clear`: 2 to 1.

The shared exit assertion now uses `Errorf` instead of `Fatalf` so byte and
metadata checks still run after an incorrect exit. No assertion was deleted;
stdout, identity, mtime and bytes checks remain. `TestWorkspaceBudgetFlagsCLI`
is unchanged and keeps exit 2 for zero tokens, workspace/task combinations,
missing set tokens and all other invalid combinations. The unchanged role
table keeps guest set at exit 3 before access.
