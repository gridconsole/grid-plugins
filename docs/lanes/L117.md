## Problem and result

Approval had isolated verb coverage but no app-shaped round trip through the
approval readers. The new portable home and transcript exercise 17 commands in
three fresh scenarios: digest approval followed by a stale edit, legacy receipt
replacement, and short-token compatibility. The CLI replay uses `newHarness`
and `h.run`; it checks exact exit codes, sorted top-level JSON/receipt keys,
6/64-character lowercase hexadecimal tokens, receipt values, note propagation,
and the plain attach/job responses. Reads and rejected approvals must preserve
the receipt bytes. Legacy approvals match the short hash but lack a digest.

No production changes or workflow keys were needed. The replaceable token policy
is `plan_hash_token`, default `any`; workflow wiring belongs to L118. Both token
lengths remain accepted under that default. Access checks and data sources are
unchanged.

## App argv and compatibility

Quoted from app `3140480adf476f1d30a055da902f2589fb02249c`,
`internal/slices/gates/args.go`:

```go
"hash":    {"plan", "hash", "--task", "$folder", "--json"},
"approve": {"approve", "$task", "--plan-hash", "$hash", "$note", "--json"},
```

The same file expands the optional note as:

```go
if token == "$note" {
    if note := values[token]; note != "" {
        out = append(out, "--note", note)
    }
}
```

Thus the nonempty-note replay is
`approve $task --plan-hash $digest --note Reviewed --json`; without a note it is
`approve $task --plan-hash $hash --json`. In that app revision,
`internal/slices/gates/http.go` selects the submitted digest as the token when
present, otherwise the submitted short hash. The legacy-replacement scenario
also exercises approval without `--json`.

The brief calls the plan-hash response fields `plan_hash` and `plan_digest`.
Plugin main actually returns `hash` and `digest`; receipt fields are
`plan_hash` and `plan_digest`. The fixture preserves these existing contracts.
Likewise, attach lives in `internal/cli/task.go`, and the actual job command
package is `internal/job/jobcmd`, not `internal/jobcmd`. The race command below
uses the existing package. No out-of-touch-list implementation was necessary.

## Fixture replay protocol

`testdata/contract/plan-digest/home` is a minimal user home with one Grid project,
one waiting task, a renderable checklist plan, intent, and a legacy receipt.
The plan follows `testdata/job/task`'s established checklist format; its explicit
empty context lists avoid needing an unrelated brain fixture. There are no
recorded machine folders or machine identifiers.

Copy `home` into a fresh temporary directory for each scenario. Set `$home` to
that directory, `$folder` to its native-path join with the transcript's relative
`folder`, and `$task` to the transcript's task ID. Set the plugin home to the
copied home's `.grid` directory. Run each command from the transcript's `cwd`
(`$folder` supplies project context for the task-ID job command), with an isolated
CLI environment. Substitute whole argv tokens, never shell strings. Capture
`$hash` and `$digest` from the first command's JSON. Use native path joins, including
on Windows; no slash-containing path is built into argv.

Before a scenario with `remove_receipt: true`, remove its copied `approval.json`.
Before a step with `append_plan`, append that text to its copied `plan.md`, keeping
the previously captured tokens. Other scenarios retain the fixture's legacy
receipt. Each step records `{argv, exit, stdout_keys, receipt_keys}`; optional
`stdout_contains` and `stderr_contains` pin plain responses and refusal messages.
Key arrays are sorted and exact. Plain or failed commands have empty stdout-key
arrays; missing receipts have empty receipt-key arrays. Receipt keys are read
from the copied task's `approval.json` after every step.

As with `internal/golden`'s isolated replay and opt-in updates, a normal run never
writes the source fixture. This test reuses the existing contract JSON writer:

```sh
UPDATE_PLAN_DIGEST_FIXTURE=1 go test ./internal/cli -run '^TestPlanDigestRoundTrip$' -count=1
```

The updater captures exits and keys from live runs and refuses to write if a
semantic assertion failed. A second update was byte-identical. The portability
test scans the transcript and every home file for private-path/email/URL-host
patterns and drive-letter paths, and rejects nonregular fixture files.
