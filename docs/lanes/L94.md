# L94: embedded Feed records and forward-compatible thresholds

Base: plugin main `aeb572c59170c4b5095880879bcc0f308d932522`.
Branch: `lane-L94`. Regression commit: `185a095`. Implementation commit:
`462a80f`. The subsequent lane-note commit changes no tested code.

## Changes

`Record` and `Entry` now use ordinary struct JSON decoding. The custom decoder
lives on the named `Record.Body` field, so embedding either envelope no longer
promotes a decoder that consumes the outer object. Embedding a nil `*Record`
also lets the JSON decoder allocate it normally instead of panicking.

`Body` remains a string-keyed map. Its JSON decoder preserves `tokens` as
`json.Number`, including the full uint64 range; other numeric body fields keep
their float64 representation. The same helper handles post normalization and
spilled bodies, keeping cold reads, cache reads, and retries consistent. Number
preservation now follows the `tokens` field rather than the envelope type;
`usage-notice` is currently the only registered schema with that body field.
No envelope fields, JSON tags, schemas, or existing fixtures changed.

The thresholds reader ignores unknown top-level fields in version-1 settings.
Known field type checks, version checks, percentage ordering/ranges, budget and
baseline validation, fired-entry validation, and the single-object requirement
remain in place. Unknown options are ignored, not retained for later writes.

## Embedding audit and coverage

Repository-wide searches for `feed.Record` and anonymous `Record` fields found
one production embedding of the Feed type: `feed.Entry` in
`internal/feed/read.go`. Its previous decoder workaround was also removed,
because callers embedding `Entry` inherited the same field-swallowing behavior.
Other anonymous Records belong to separate types: `intent.View`, `lease.Status`,
`lease.JobStatus`, `task.Task`, the task-creation front matter, and
`cli.sessionView`. None embeds `feed.Record`.

The regression suite checks all fields of `Entry` and test extensions embedding
`Record` by value, `*Record`, and `Entry`, using JSON and YAML round trips. It
also checks invalid outer fields, malformed envelope/body values, and exact
token counts at zero, 2^53+1, and uint64 maximum. Existing usage tests cover
maximum token notices across posting, cold reads, and cached reads.

`TestRecordFixtureGolden` reads all 42 existing valid fixtures for the 19 registered
Feed post types. It compares decoded envelopes and body values with the independent
contract representation, then compares re-encoded JSON values with the original
fixture, preserving explicit nulls and empty arrays. Existing fixtures serve as
the goldens; none was regenerated.

Threshold regressions add an unknown object-valued option and verify unchanged
known settings. Table cases keep that option present while checking invalid
versions, types, percentages, order, duplicates, null required values, token
budgets, baselines, and fired entries.

## Regression evidence

The tests were added and run before implementation, with production code still
identical to the base SHA. The baseline runs failed both changed packages:

- JSON extensions of `Record` lost `Label` and `Count`.
- A nil embedded `*Record` panicked inside `Record.UnmarshalJSON`.
- JSON extensions of `Entry` lost `Label`.
- All three token-count extension cases lost outer fields.
- An invalid outer `count` was silently accepted.
- Reading the future threshold option failed with `unknown field "future_option"`.

The pointer panic initially stopped the Feed test process. A second run selected
the other extension, validation, threshold, and fixture tests to expose the
remaining failures and confirm the fixture goldens passed on the base. Both
complete packages pass with the implementation.

## Scope

The brief supplied no explicit touch list. Besides the decoder and thresholds
reader, `internal/feed/read.go` removes the Entry workaround and updates spilled
body decoding; `internal/feed/store.go` updates the two matching helper calls.
These are the smallest accompanying production changes needed to use the same
body decoder everywhere. Two existing CLI round-trip tests convert the named
`Body` map to `map[string]any` for comparison with their independently decoded
expected maps; their field/value assertions are unchanged. The first full-suite
run exposed that Go type-identity mismatch. The new tests and this lane note are
the remaining additions.

The existing module, Makefile, fixtures, and unrelated runner files were left
unchanged; no root `DONE.md` was created.
